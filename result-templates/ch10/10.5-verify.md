# 10.5 EKS에 Worklog + Argo CD 배포 — 예상 결과

## 상태 확인

### AWS Load Balancer Controller (ALB Ingress용)

```
$ kubectl get deploy -n kube-system aws-load-balancer-controller
NAME                           READY   UP-TO-DATE   AVAILABLE   AGE
aws-load-balancer-controller   2/2     2            2           2m
```

### Worklog 배포 (노출은 ALB Ingress)

```
$ kubectl get pods
NAME                               READY   STATUS    RESTARTS   AGE
worklog-mongodb-xxxx               1/1     Running   0          3m
worklog-backend-xxxx               1/1     Running   0          2m
worklog-frontend-xxxx              1/1     Running   0          2m

$ kubectl get ingress worklog
NAME      CLASS   HOSTS   ADDRESS                                        PORTS   AGE
worklog   alb     *       k8s-...-xxxx.ap-northeast-2.elb.amazonaws.com   80      2m
```

### ALB 접근

```
$ curl -sI http://<ALB주소>/          # 프론트 → 200
HTTP/1.1 200 OK
$ curl -s  http://<ALB주소>/health    # 백엔드 → 200
{"health":"OK"}
```

### Argo CD (LoadBalancer 노출)

```
$ kubectl get svc argocd-server -n argocd
NAME            TYPE           EXTERNAL-IP                                    PORT(S)
argocd-server   LoadBalancer   a...-....ap-northeast-2.elb.amazonaws.com      80:xxxxx/TCP,443:xxxxx/TCP

$ kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d
<16자 초기 비밀번호>
```

## 체크리스트

- [ ] AWS Load Balancer Controller 설치됨 (IAM 정책 + IRSA(OIDC) + Helm)
- [ ] mongodb → backend → frontend 순서로 배포, 모두 `Running`
- [ ] ⛔ **HTTPRoute 제거 → ALB Ingress(`ingressClassName: alb`)로 교체** (EKS엔 NGF 없음)
- [ ] `kubectl get ingress`에 ALB 주소 발급됨
- [ ] ALB `/` → 200(프론트), `/health` → 200(백엔드, mongodb 연결 포함)
- [ ] Argo CD 설치 + `argocd-server`를 `LoadBalancer`로 노출, 초기 admin 비번 확보
- [ ] Argo CD Application(worklog repo `deploy_manifest` → in-cluster) Synced/Healthy

## 검증 메모 & 주의 (실배포)

- 공개 이미지 사용 가능(빌드 불필요): `sysnet4admin/worklog-backend:<tag>`, `sysnet4admin/worklog-frontend-mock:<tag>` (Docker Hub 공개, 멀티아키).
- ⛔ **teardown 순서**: LoadBalancer Service·Ingress를 `kubectl delete`로 먼저 지워 컨트롤러/CCM이 ELB/ALB와 보안그룹을 회수하게 한다. CLI로 LB만 직접 지우면 `k8s-elb-*` 보안그룹이 orphan으로 남아 `terraform destroy`가 VPC를 DependencyViolation으로 막는다.
