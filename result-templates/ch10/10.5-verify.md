# 10.5 EKS에 Worklog + Argo CD 배포 — 예상 결과

## 상태 확인

### AWS Load Balancer Controller (ALB Ingress용)

```
$ kubectl get deploy -n kube-system aws-load-balancer-controller
NAME                           READY   UP-TO-DATE   AVAILABLE   AGE
aws-load-balancer-controller   2/2     2            2           2m
```

### Worklog 배포 (노출은 ALB Ingress)

```
$ kubectl get pods
NAME                               READY   STATUS    RESTARTS   AGE
worklog-mongodb-xxxx               1/1     Running   0          3m
worklog-backend-xxxx               1/1     Running   0          2m
worklog-frontend-xxxx              1/1     Running   0          2m

$ kubectl get ingress worklog
NAME      CLASS   HOSTS   ADDRESS                                        PORTS   AGE
worklog   alb     *       k8s-...-xxxx.<aws_region>.elb.amazonaws.com   80      2m
```

### ALB 접근

```
$ curl -s -o /dev/null -w "%{http_code}\n" http://<ALB주소>/     # frontend
200
$ curl -s http://<ALB주소>/api/v1/todos                         # frontend의 프록시를 거쳐 backend와 MongoDB까지
[]
$ curl -s http://<ALB주소>/health                               # 단계 10 뒤. deploy_manifest의 Ingress가 같은 ALB에 붙는다
{"health":"OK","imageTag":"<backend_tag>"}
```

```

$ kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d
<16자 초기 비밀번호>
```

## 체크리스트

- [ ] AWS Load Balancer Controller 설치됨 (IAM 정책 + Pod Identity + Helm)
- [ ] mongodb → backend → frontend 순서로 배포, 모두 `Running`
- [ ] ⛔ **HTTPRoute 제거 → ALB Ingress(`ingressClassName: alb`)로 교체** (EKS엔 NGF 없음)
- [ ] `kubectl get ingress`에 ALB 주소 발급됨
- [ ] ALB `/` → 200, `/api/v1/todos` → `[]`(frontend → backend → MongoDB). 여러 번 불러도 매번 응답한다(절반이 멈추면 10.4의 노드 간 보안 그룹 규칙을 본다)
- [ ] `worklog` Ingress의 `group.order`가 10, `worklog-backend`가 1이다
- [ ] 단계 10 뒤 `kubectl get ingress`의 `worklog`와 `worklog-backend`가 같은 ADDRESS(ALB 하나)이고 `/health`가 HTML이 아니라 `{"health":"OK",...}`를 돌려준다
- [ ] 로컬 클러스터의 `worklog-backend` Application은 자동 sync가 꺼져 있다(단계 0)
- [ ] argocd CLI가 EKS의 Argo CD에 로그인돼 있다(`argocd context`)
- [ ] Argo CD 설치 + `argocd-server`를 `LoadBalancer`로 노출, 초기 admin 비번 확보. UI는 `http://`로 연다
- [ ] Argo CD Application(worklog repo `deploy_manifest` → in-cluster) Synced/Healthy

## 검증 메모 & 주의 (실배포)

- EKS 노드는 amd64다. 이미지 태그는 `docker buildx imagetools inspect`로 `linux/amd64`가 있는 것을 고른다(10.5 단계 2).
- ⛔ **teardown 순서**: LoadBalancer Service·Ingress를 `kubectl delete`로 먼저 지워 컨트롤러/CCM이 ELB/ALB와 보안그룹을 회수하게 한다. CLI로 LB만 직접 지우면 `k8s-elb-*` 보안그룹이 orphan으로 남아 `terraform destroy`가 VPC를 DependencyViolation으로 막는다.
