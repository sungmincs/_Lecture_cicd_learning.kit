# 10.6 GitHub Actions → EKS — 예상 결과

## 상태 확인

### 파이프라인 성공 (Part A 직접 배포)

```
$ gh run list -R <github_username>/worklog-backend --limit 1
STATUS  TITLE                       WORKFLOW      BRANCH  ...
completed success  cicd: deploy to EKS ...   eks-deploy   main
```

deploy job 로그:
```
Run aws eks update-kubeconfig --region <aws_region> --name <cluster>
Added new context arn:aws:eks:... 
+ kubectl apply -f deploy_manifest/worklog-backend.yaml
deployment.apps/worklog-backend configured
+ kubectl rollout status deployment/worklog-backend
deployment "worklog-backend" successfully rolled out
```

### Part A 뒤: 클러스터와 Git이 어긋난다

```
$ kubectl get deploy worklog-backend -o jsonpath='{.spec.template.spec.containers[0].image}'
<dockerhub_username>/worklog-backend:<방금 커밋의 8자>
$ argocd app get worklog-backend --refresh | grep "Sync Status"
Sync Status:        OutOfSync from main (...)
```

자동 sync를 다시 켜면(단계 5) 이미지가 Git에 적힌 이전 태그로 돌아간다.

### EKS에서 배포 확인

```
$ kubectl get pods
NAME                               READY   STATUS    RESTARTS   AGE
worklog-backend-xxxx               1/1     Running   0          1m
```

### Part B (Argo CD 연동)

```
$ argocd app get worklog-backend
Sync Status:    Synced to main (<sha>)
Health Status:  Healthy
```

## 체크리스트

- [ ] GitHub Secrets: `DOCKERHUB_TOKEN`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `EKS_CLUSTER_NAME`(실제 이름과 일치), (Part B) `ARGOCD_ADMIN_PASSWORD`
- [ ] Secrets의 AWS 키가 10.4에서 클러스터를 만든 IAM 사용자의 것이다(CI 전용 사용자를 따로 만들었다면 `eks:DescribeCluster` 정책과 EKS access entry가 둘 다 필요하다)
- [ ] Part A 전에 Argo CD 자동 sync를 껐고(단계 2), Part A 뒤에 다시 켰다(단계 5)
- [ ] `eks-deploy.yaml`은 꺼져 있고 `eks-argocd.yaml`만 켜져 있다
- [ ] ⛔ **deploy_manifest의 HTTPRoute → ALB Ingress 교체** (EKS서 HTTPRoute apply 실패)
- [ ] Part A: `configure-aws-credentials` → `update-kubeconfig` → `kubectl apply` → rollout 성공
- [ ] Part B: 이미지태그 갱신 push → `argocd app sync` → Synced/Healthy
- [ ] `kubectl get pods`에 worklog-backend `Running`
