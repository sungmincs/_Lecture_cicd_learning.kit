## 상태 확인

### 파이프라인 성공 (Part A 직접 배포)

```
$ gh run list --limit 1
STATUS  TITLE                       WORKFLOW      BRANCH  ...
completed success  cicd: deploy to EKS ...   eks-deploy   main
```

deploy job 로그:
```
Run aws eks update-kubeconfig --region ap-northeast-2 --name <cluster>

+ kubectl apply -f deploy_manifest/worklog-backend.yaml
deployment.apps/worklog-backend configured
+ kubectl rollout status deployment/worklog-backend

```

```
$ argocd app get worklog-backend

```

## 체크리스트

- [ ] GitHub Secrets: `DOCKERHUB_TOKEN`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `EKS_CLUSTER_NAME`(실제 이름과 일치), (Part B) `ARGOCD_ADMIN_PASSWORD`
- [ ] ⛔ **CI IAM 유저에 `eks:DescribeCluster` IAM 정책** (`update-kubeconfig`가 호출)
- [ ] ⛔ **CI IAM 유저에 EKS access entry** (`create-access-entry` + `AmazonEKSClusterAdminPolicy`). 없으면 kubectl 401
- [ ] ⛔ **deploy_manifest의 HTTPRoute → ALB Ingress 교체** (EKS서 HTTPRoute apply 실패)
- [ ] Part A: `configure-aws-credentials` → `update-kubeconfig` → `kubectl apply` → rollout 성공
- [ ] Part B: 이미지태그 갱신 push → `argocd app sync` → Synced/Healthy
- [ ] `kubectl get pods`에 worklog-backend `Running`
