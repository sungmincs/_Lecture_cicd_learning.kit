# 10.4 Terraform으로 EKS 배포 — 예상 결과

## 상태 확인

모든 명령은 컨트롤 플레인 노드의 `/root/ch10/terraform-eks`에서 친다.

### Terraform 버전

```
$ terraform version
Terraform v1.15.7
on linux_<amd64|arm64>
```

### terraform apply 완료

```
$ terraform apply -auto-approve
...
Apply complete! Resources: 60 added, 0 changed, 0 destroyed.

Outputs:
cluster_endpoint = "https://XXXX.gr7.<aws_region>.eks.amazonaws.com"
cluster_name = "cicd-learning-eks"
region = "<aws_region>"
```

### kubectl context 둘과 노드 확인

```
$ kubectl config rename-context kubernetes-admin@kubernetes local
$ aws eks update-kubeconfig --name cicd-learning-eks --alias eks
Added new context eks to /root/.kube/config

$ kubectl config get-contexts
CURRENT   NAME    CLUSTER ...
*         eks     arn:aws:eks:...
          local   kubernetes

$ kubectl get nodes
NAME                                            STATUS   ROLES    AGE   VERSION
ip-10-0-1-xx.<aws_region>.compute.internal    Ready    <none>   50s   v1.36.x-eks-...
ip-10-0-2-xx.<aws_region>.compute.internal    Ready    <none>   50s   v1.36.x-eks-...
ip-10-0-3-xx.<aws_region>.compute.internal    Ready    <none>   52s   v1.36.x-eks-...
```

### 10장을 중간에 멈출 때만 여기서 destroy (평소에는 10.10에서 정리)

```
$ terraform destroy -auto-approve
...
Destroy complete! Resources: 60 destroyed.
```

## 체크리스트

- [ ] `main.tf`에 `cluster_version = "1.36"` (1.29는 EKS 생성 불가)
- [ ] `main.tf`에 `enable_cluster_creator_admin_permissions = true` (없으면 생성자도 kubectl 401 `You must be logged in to the server`)
- [ ] `main.tf`에 `node_security_group_additional_rules`의 `ingress_self_all`이 있다 (없으면 10.5에서 `/api` 요청이 노드가 다를 때 504)
- [ ] `terraform plan | grep "Plan:"`이 `60 to add` 안팎이고 change와 destroy가 0
- [ ] 모듈 버전 `terraform-aws-modules/eks ~> 20.0` (v21은 provider6 연쇄·count 버그로 회피)
- [ ] `terraform apply` 성공 (약 61 리소스, 11~15분: VPC→KMS→컨트롤플레인→노드그룹)
- [ ] kubectl context가 `eks`와 `local` 둘이고 현재는 `eks`
- [ ] `kubectl get nodes`에 EKS 노드 3대 `Ready`(v1.36), `kubectl --context local get nodes`에 로컬 노드 4대
- [ ] `/root/ch10/terraform-eks/terraform.tfstate`가 있다
- [ ] EKS를 지우지 않고 10.5로 넘어갔다 (정리는 10.10. 중단할 때만 여기서 `terraform destroy`)
- [ ] destroy 후 잔여 0 확인 (EKS·VPC·NAT·EIP·EC2). KMS 키는 `PendingDeletion`(과금 없음, 자동삭제)

## 검증 메모 (실배포)

- 2026-10-10 run-40: apply 11분, 노드 `v1.36.4-eks`. 노드 간 보안 그룹 규칙을 더해 리소스가 61개가 됐다.
- 2026-07-03 실배포로 확인. 노드 `v1.36.2-eks`, apply/destroy 각 60 리소스.
- KMS 키는 `terraform destroy` 후에도 최소 7일 삭제창으로 `PendingDeletion`에 남는다(정상, 과금 없음).
