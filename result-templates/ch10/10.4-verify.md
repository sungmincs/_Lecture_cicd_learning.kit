# 10.4 Terraform으로 EKS 배포 — 예상 결과

## 상태 확인

### terraform apply 완료

```
$ terraform apply -auto-approve
...
Apply complete! Resources: 60 added, 0 changed, 0 destroyed.

Outputs:
cluster_endpoint = "https://XXXX.gr7.ap-northeast-2.eks.amazonaws.com"
cluster_name = "cicd-learning-eks"
region = "ap-northeast-2"
```

### kubectl로 노드 확인 (creator-admin 필수)

```
$ aws eks update-kubeconfig --region ap-northeast-2 --name cicd-learning-eks
Added new context arn:aws:eks:... to ...

$ kubectl get nodes
NAME                                            STATUS   ROLES    AGE   VERSION
ip-10-0-1-xx.ap-northeast-2.compute.internal    Ready    <none>   50s   v1.36.x-eks-...
ip-10-0-2-xx.ap-northeast-2.compute.internal    Ready    <none>   50s   v1.36.x-eks-...
ip-10-0-3-xx.ap-northeast-2.compute.internal    Ready    <none>   52s   v1.36.x-eks-...
```

### 실습 종료 후 destroy

```
$ terraform destroy -auto-approve
...
Destroy complete! Resources: 60 destroyed.
```

## 체크리스트

- [ ] `main.tf`에 `cluster_version = "1.36"` (1.29는 EKS 생성 불가)
- [ ] `main.tf`에 `enable_cluster_creator_admin_permissions = true` (없으면 생성자도 kubectl 401 `You must be logged in to the server`)
- [ ] 모듈 버전 `terraform-aws-modules/eks ~> 20.0` (v21은 provider6 연쇄·count 버그로 회피)
- [ ] `terraform apply` 성공 (약 60 리소스, ~15분: VPC→KMS→컨트롤플레인→노드그룹)
- [ ] `aws eks update-kubeconfig` 후 `kubectl get nodes`에 노드 3대 `Ready`(v1.36)
- [ ] 실습 종료 후 `terraform destroy`로 전량 삭제
- [ ] destroy 후 잔여 0 확인 (EKS·VPC·NAT·EIP·EC2). KMS 키는 `PendingDeletion`(과금 없음, 자동삭제)

## 검증 메모 (실배포)

- 2026-07-03 실배포로 확인. 노드 `v1.36.2-eks`, apply/destroy 각 60 리소스.
- KMS 키는 `terraform destroy` 후에도 최소 7일 삭제창으로 `PendingDeletion`에 남는다(정상, 과금 없음).
