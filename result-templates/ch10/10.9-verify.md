# 10.9 검증: GitLab CI로 빌드하고 Argo CD로 EKS에 배포

## 확인 항목

- [ ] GitLab 프로젝트 `worklog-backend`가 학습자의 GitHub fork에서 가져와졌고 `deploy_manifest/`가 있다
- [ ] CI/CD Variables 3개(DOCKERHUB_USERNAME, DOCKERHUB_TOKEN, GITLAB_TOKEN)가 등록돼 있다. 토큰 둘은 masked
- [ ] 노드의 `/root/workspace/worklog-backend-gitlab`에 clone했고 push가 됐다(사용자 이름과 토큰 입력)
- [ ] 파이프라인 test → build → deploy가 모두 통과했다
- [ ] deploy가 만든 `[skip ci]` 커밋의 파이프라인이 `skipped`이고 job이 돌지 않았다
- [ ] Argo CD Application의 저장소가 gitlab.com이고 Synced, Healthy다
- [ ] EKS의 worklog-backend 이미지 태그가 방금 파이프라인의 SHA 8자리다

## 확인 명령

```bash
argocd app get worklog-backend | grep -E "Repo:|Sync Status|Health Status"
kubectl get deploy worklog-backend -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
```

## 참고

- 이 파이프라인에는 AWS 자격 증명이 없다. EKS에 반영한 것은 Argo CD다.
