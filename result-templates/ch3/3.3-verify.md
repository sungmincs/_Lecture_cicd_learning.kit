```
  Version:          29.x.x

[root@cp-k8s ~]# docker ps

(권한 오류 없이 빈 목록 또는 실행 중인 컨테이너 표시)
```

### 빌드 결과 확인

```
[root@cp-k8s ~]# docker images | grep worklog
<dockerhub_username>/worklog-frontend-mock   buildtest1   ...   ~XXX MB
```

> 💡 mock 이미지(Node.js + dev deps)는 backend(slim Python)보다 크기가 보통 큼.

### Push 실패 (단계 5) 확인

Docker 버전에 따라 다음 중 하나:

```
[root@cp-k8s ~]# docker push <dockerhub_username>/worklog-frontend-mock:buildtest1
The push refers to repository [docker.io/<dockerhub_username>/worklog-frontend-mock]
...
denied: requested access to the resource is denied
```

또는:

```
... push access denied, repository does not exist or may require authorization:
server message: insufficient_scope: authorization failed
```

## 이 단계 이후 아키텍처

```
[학습자 GitHub]
  ├── worklog-frontend-mock      (fork from sungmincs)
  └── worklog-backend            (fork from sungmincs)

[control plane: cp-k8s (192.168.1.10), root 사용자]
  └── Docker engine
       ├── 이미지: <user>/worklog-frontend-mock:buildtest1
       └── 이미지: <user>/worklog-backend:buildtest1
       (build 산출물; ch3.4에서 K8s가 Docker Hub에서 pull하므로
        cp의 local 이미지는 사용되지 않음)

[Docker Hub]
  ├── <user>/worklog-frontend-mock:buildtest1   (public)
  └── <user>/worklog-backend:buildtest1         (public)
```

ch3.4에서 K8s가 Docker Hub로부터 이 이미지들을 pull하여 Pod로 배포한다. cp에 빌드한 local 이미지는 사용되지 않음 — Docker Hub에 push되어야만 K8s가 사용 가능.
