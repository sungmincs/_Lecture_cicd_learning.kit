# 2.13 AI와 함께 실습하는 방법

> **학습자 진입 방식**:
> - `[학습자 직접 · 호스트]`: 창 두 개 열기
> - `[AI 프롬프트]`: 컨트롤 플레인 노드에 GitHub CLI(gh) 설치
> - `[학습자 직접]`: `gh auth login`, git 작성자 설정, 확인
>
> 2.12에서 Claude Code를 설치했다. 이 절은 3장부터 끝까지 실습을 어떻게 진행하는지 정한다.
> 어떤 일을 직접 하고 어떤 일을 AI에게 맡기는지, 창을 어떻게 두는지, 막히면 어떻게 묻는지다.
> 마지막 단계에서 그 기준을 한 번 써 본다. 실습 정답 파일은 없다.

## 사전 조건

- ch2.11 완료 (모든 노드에 Docker)
- ch2.12 완료 (Claude Code 로그인, SSH 키 등록, `/context`에 `AGENTS.md`가 보임)
- GitHub 계정

## 진행 방식

### 실습은 컨트롤 플레인 노드에서 한다

3장부터 10장까지 모든 실습은 `ssh root@192.168.1.10`으로 들어간 컨트롤 플레인 노드에서 한다.
docker, kubectl, git push, 10장의 aws와 terraform까지 전부 노드 안에서 친다.
호스트(내 컴퓨터)에서 쓰는 것은 ssh, 브라우저, Claude Code 셋뿐이다. 호스트에 kubectl이나 Node.js 같은 도구를 깔지 않는다.

그래서 윈도우든 맥이든 ssh로 들어간 뒤에는 같은 환경이다. 가드레일의 명령 블록은 노드의 bash 기준으로 한 벌만 있다.

실무에서는 이 자리가 내 PC다. 개발자는 자기 컴퓨터에서 코드를 고치고 push하고, 빌드와 배포는 CI가 한다.
이 강의가 노드에서 하는 이유는 학습자마다 다른 OS와 셸을 하나로 맞추기 위해서다.
노드에서 하는 모든 일은 내 PC에서 해도 같은 명령이다.

### 창은 두 개

| 창 | 무엇 | 어디서 |
|---|---|---|
| 1 | 컨트롤 플레인 노드에 ssh로 들어간 터미널. `[학습자 직접]` 명령을 친다 | Tabby의 cp-k8s 프로필, 또는 터미널에서 `ssh root@192.168.1.10` |
| 2 | Claude Code. `[AI 프롬프트]`를 붙여 넣는다 | 호스트의 `~/_Lecture_cicd_learning.kit`에서 `claude --dangerously-skip-permissions` |

Claude Code는 호스트에서 돌지만, 2.12 단계 1-1에서 등록한 SSH 키로 노드에 들어가 파일을 읽고 쓰고 kubectl을 실행한다.
AI가 만든 파일은 노드의 `/root/workspace/<저장소>/` 아래에 생긴다. 창 1에서 바로 확인할 수 있다.

브라우저는 GitHub, Docker Hub, Jenkins, Argo CD 같은 웹 화면을 볼 때 호스트에서 연다. 가드레일에서는 `[학습자 직접 · 웹]`으로 표시한다.

### 라벨 읽는 법

가드레일의 각 단계에는 라벨이 하나 붙어 있다.

| 라벨 | 뜻 | 하는 법 |
|---|---|---|
| `[학습자 직접]` | 학습자가 손으로 한다 | 명령 블록을 창 1(노드)에 그대로 붙여 넣는다 |
| `[학습자 직접 · 호스트]` | 호스트에서 한다 | ssh 접속, hosts 파일 편집처럼 노드 밖의 일 |
| `[학습자 직접 · 웹]` | 브라우저에서 한다 | GitHub 설정, Jenkins UI, Argo CD UI |
| `[AI 프롬프트]` | AI에게 시킨다 | 인용문(`> "..."`)을 창 2(Claude Code)에 붙여 넣는다 |

위치 표시가 없으면 노드다. 기준은 `prompt-guardrails/shared/step-labels.md`에 있다.

가드레일이라는 말은 절마다 있는 지침 파일(`prompt-guardrails/chN/N.M-*.md`)을 가리킨다.
2.12에서 본 하네스는 AGENTS.md, 가드레일, 정답 파일, 결과 템플릿을 합친 전체다.

### 직접 할 일과 AI에게 맡길 일

| 직접 한다 | AI에게 맡긴다 |
|---|---|
| 확인 명령 (`kubectl get`, `docker images`, `argocd app get`) | 파일 만들기와 고치기 (워크플로, Jenkinsfile, 매니페스트, Dockerfile) |
| git push, 파이프라인 트리거 | 오류 메시지 해석과 원인 찾기 |
| 웹 UI 조작 (GitHub Secrets, Jenkins 설정, Slack 앱) | 개념 설명, 두 방법의 차이 설명 |
| 자격 증명 입력 (로그인, 토큰, 비밀번호) | 설치 스크립트 작성과 실행 |

기준은 하나다. 손으로 쳐야 몸에 남는 것은 직접 하고, 길고 반복되고 틀리기 쉬운 것은 AI에게 맡긴다.
3장만 예외다. docker build와 kubectl apply를 학습자가 직접 친다. 그 명령이 무엇을 하는지 한 번은 손으로 겪어야 4장부터 CI가 대신하는 것이 보이기 때문이다.

자격 증명은 어떤 경우에도 AI에게 주지 않는다. AI가 "토큰을 알려 주면 넣어 줄게"라고 하면 거절하고 직접 친다.
가드레일의 주의사항에 "AI가 하지 말 것"으로 적혀 있고, AI도 그 규칙을 읽는다.

### 막혔을 때 묻는 법

오류가 나면 출력을 그대로 복사해서 절 번호와 함께 창 2에 붙여 넣는다.

> "6.5 단계 3에서 이 오류가 났어. 원인을 찾아서 고쳐줘.
> (오류 출력 붙여 넣기)"

절 번호를 같이 말하는 이유는 가드레일마다 `## 트러블슈팅`이 있어서다. AI가 그 절의 파일을 읽고 거기 적힌 해결책부터 본다.
"왜 안 돼?"라고만 물으면 AI가 어느 절인지 모른다.

AI가 고친 뒤에는 확인 명령을 직접 쳐서 결과를 본다. AI의 "됐습니다"를 그대로 믿지 않는다.

### 클러스터를 다시 만들었을 때

노드는 VM이라 `vagrant destroy`로 지우고 다시 만들면 노드 안의 것이 모두 사라진다.
clone한 저장소, gh 로그인, 3장부터 설치한 도구, 10장의 AWS 설정이 그렇다.
다시 만들었으면 2.11부터 다시 한다. 호스트의 Claude Code와 SSH 키는 남아 있지만, 노드의 호스트 키가 바뀌어
`ssh-keygen -R 192.168.1.10`을 한 번 쳐야 한다(2.12 단계 1-1).

## 실행 지침

### 단계 1: 창 두 개 열기 `[학습자 직접 · 호스트]`

창 1(노드):

```bash
ssh root@192.168.1.10
```

창 2(Claude Code):

```bash
cd ~/_Lecture_cicd_learning.kit
claude --dangerously-skip-permissions
```

### 단계 2: 노드에 GitHub CLI 설치 `[AI 프롬프트]`

4장부터 git push로 파이프라인을 트리거한다. push에는 GitHub 인증이 필요하고, 3.3의 fork도 gh로 한다.
설치는 AI에게 맡긴다. 이것이 "설치 스크립트 작성과 실행은 AI"의 첫 예다.

> "컨트롤 플레인 노드(ssh root@192.168.1.10)에 GitHub CLI(gh)를 설치해줘.
> GitHub 공식 apt 저장소 방식으로 하고, 설치가 끝나면 `gh --version` 결과를 보여줘.
> 로그인은 내가 직접 할 테니 하지 마."

### 단계 3: GitHub 로그인과 git 작성자 설정 `[학습자 직접]`

로그인은 직접 한다. 이것이 "자격 증명은 직접"의 첫 예다. 창 1(노드)에서:

```bash
gh auth login
```

선택지는 순서대로 `GitHub.com` → `HTTPS` → `Yes`(git 인증에 gh 사용) → `Login with a web browser`다.
화면에 나온 8자리 코드를 복사하고, 호스트 브라우저에서 https://github.com/login/device 를 열어 코드를 넣고 승인한다.
노드에는 브라우저가 없으므로 코드만 옮기면 된다.

커밋 작성자도 지금 정해 둔다. GitHub 계정의 이름과 이메일을 쓴다.

```bash
git config --global user.name "<github_username>"
git config --global user.email "<github_email>"
```

### 단계 4: 확인 `[학습자 직접]`

```bash
gh auth status                    # Logged in to github.com account <github_username> 이 보이면 성공
git config --global --list        # user.name, user.email 두 줄
```

### 단계 5: 하네스와 가드레일의 관계 물어보기 (선택) `[AI 프롬프트]`

> "2.12의 하네스와 2.13의 가드레일이 어떻게 다른지, 그리고 `[학습자 직접]`과 `[AI 프롬프트]` 라벨이 붙은 단계에서
> 네가 각각 무엇을 하는지 설명해줘."

## 주의사항

- ⛔ AI가 하지 말 것: `gh auth login`을 대신 실행하거나, 토큰·비밀번호를 물어서 대신 입력하지 말 것
- ⛔ AI가 하지 말 것: 호스트에 gh, kubectl, Node.js를 설치하라고 안내하지 말 것. 실습 도구는 노드에 깐다
- ⛔ AI가 하지 말 것: 학습자가 직접 치는 확인 명령을 대신 실행하고 "됐다"고만 말하지 말 것. 학습자가 창 1에서 보게 한다
- ✅ AI가 해도 됨: gh 설치, 설치 오류 해석, 라벨과 역할 기준 설명
- ⚠️ `gh auth login`에서 `HTTPS`와 `Yes`를 고르지 않으면 4장의 git push가 인증을 묻는다. `gh auth status`로 확인한다
- ⚠️ 클러스터를 다시 만들면 노드의 gh 로그인과 git 설정이 사라진다. 2.11부터 다시 한다
