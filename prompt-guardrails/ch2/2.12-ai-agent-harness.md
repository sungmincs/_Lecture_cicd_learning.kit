# 2.12 Claude Code와 실습 하네스 구조

> **학습자 진입 방식**:
> - `[학습자 직접]`: Claude Code 설치와 로그인, 강의 저장소 clone, 실행, `/context` 확인
> - `[AI 프롬프트]`: 하네스 구조 설명, 가드레일 mode 비교
>
> ch2에서 클러스터와 Docker까지 준비했다. ch3부터 함께 일할 AI 에이전트를 설치하고, 이 저장소가
> AI 에이전트에게 무엇을 어떻게 알려 주는지(하네스) 구조를 본다. 실습 정답 파일은 없다.

## 사전 조건

- ch2.3 또는 ch2.4 완료 (클러스터 동작)
- ch2.11 완료 (모든 노드에 Docker)
- Claude 계정 (유료 요금제)

## 하네스 구조

이 강의 저장소에서 AI 에이전트가 읽는 파일은 이렇게 나뉜다.

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 규칙의 정본. 가드레일 mode, 학습자 입력과 참조 파일 매칭표, 안전 규칙 |
| `CLAUDE.md` | `@AGENTS.md` 한 줄. Claude Code가 `AGENTS.md`를 읽게 하는 연결 |
| `prompt-guardrails/chN/` | 절마다의 실행 지침. 사전 조건, 단계, 주의사항 |
| `chN/N.M/` | 정답 파일. AI와 함께 만든 결과를 비교하는 기준 |
| `result-templates/chN/` | 결과 확인 체크리스트 (있는 절만) |

학습자의 요청 하나는 이렇게 흐른다.

```
학습자 입력 → AGENTS.md 매칭표 → prompt-guardrails의 실행 지침 → 작업 → 정답 파일과 비교 → 결과 확인
```

`AGENTS.md`는 AI 에이전트용 규칙 파일의 공개 형식이다(AAIF, Agentic AI Foundation 관리). 강의 시연은 Claude Code로
하지만 규칙은 특정 도구에 묶여 있지 않다. Codex 같은 다른 AI 에이전트는 `AGENTS.md`를 직접 읽는다.

`CLAUDE.md`를 따로 두는 이유: Claude Code도 `AGENTS.md`를 직접 읽을 수 있지만 설치 직후 첫 세션이나 일부 환경에서는
읽지 않는다. `@AGENTS.md` import 한 줄이 있으면 어느 환경에서든 첫 세션부터 같은 규칙이 적용되고 `/context`에서도 보인다.

## 실행 지침

### 단계 1: Claude Code 설치와 로그인 `[학습자 직접]`

호스트(내 컴퓨터) 터미널에서 공식 설치 안내(https://code.claude.com/docs)를 따른다.

```bash
claude --version
```

처음 실행하면 브라우저로 로그인한다.

### 단계 2: 강의 저장소 clone하고 실행 `[학습자 직접]`

```bash
cd ~
git clone https://github.com/sungmincs/_Lecture_cicd_learning.kit.git
cd _Lecture_cicd_learning.kit
claude --dangerously-skip-permissions
```

> ⚠️ `--dangerously-skip-permissions`는 명령마다 승인을 묻지 않는 모드다. 이 강의는 이 모드를 기준으로 한다.
> 그래서 반드시 이 저장소 안에서 실행한다. 홈 디렉터리 같은 곳에서 실행하지 않는다.

### 단계 3: 규칙이 로드됐는지 확인 `[학습자 직접]`

Claude Code 안에서:

```
/context
```

**Memory files**에 `CLAUDE.md`와 `AGENTS.md`가 보이면 규칙이 로드된 것이다.

### 단계 4: 하네스 구조 물어보기 `[AI 프롬프트]`

> "이 저장소에서 너는 어떤 규칙을 따라 움직여? AGENTS.md, prompt-guardrails, 정답 파일, result-templates가
> 각각 무슨 역할인지 설명해줘."

### 단계 5: 가드레일 mode 비교 (선택) `[AI 프롬프트]`

같은 질문을 가드레일을 끄고 한 번, 켜고 한 번 한다. **두 번 모두 "계획만 말해줘"를 붙인다.** 실제로 실행하면
ch3의 실습을 먼저 해 버린다.

> "가드레일 모드를 off로 바꿔줘."

> "Docker로 빌드하고 Docker Hub에 push해줘. 실행하지 말고 무엇을 할 계획인지만 말해줘."

> "가드레일 모드를 auto로 바꿔줘."

그리고 같은 질문을 다시 한다. auto에서는 AI가 `prompt-guardrails/ch3/3.5-docker-build.md`를 찾아 읽고,
`docker build`와 `docker push`는 학습자가 직접 치라고 안내한다. 같은 모델, 같은 문장인데 읽는 파일이 달라서 진행이 달라진다.

마지막에는 반드시 `mode: auto`로 돌려 둔다.

## 다른 AI 에이전트로 할 때

| | Claude Code | Codex CLI |
|---|---|---|
| 실행 | `claude --dangerously-skip-permissions` | `codex --full-auto --sandbox danger-full-access` |
| 규칙 파일 | `CLAUDE.md`의 `@AGENTS.md` | `AGENTS.md`를 직접 읽음 |

다른 도구도 대부분 `AGENTS.md`를 직접 읽는다. 도구가 바뀌어도 가드레일과 정답 파일은 그대로 쓴다.

## 주의사항

- ⛔ AI가 하지 말 것: 학습자 대신 로그인하거나 계정 정보를 묻지 말 것
- ⛔ AI가 하지 말 것: 단계 5에서 실제로 `docker build`나 `docker push`를 실행하지 말 것. 계획만 말한다
- ⛔ AI가 하지 말 것: `AGENTS.md`의 규칙을 `CLAUDE.md`로 옮겨 적으라고 안내하지 말 것
- ✅ AI가 해도 됨: 하네스 구조 설명, mode별 동작 차이 설명, 다른 AI 에이전트에서의 사용법 안내
- ⚠️ 단계 5를 마치면 `AGENTS.md`의 `mode`가 `auto`인지 확인한다. off로 남으면 이후 실습이 가드레일 없이 진행된다
- ⚠️ 설정으로만 읽힌 `AGENTS.md`는 `/context` 목록에 나오지 않는다. 이 저장소처럼 `CLAUDE.md`의 import로 읽히면 나온다
