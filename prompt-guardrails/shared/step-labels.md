# 실습 단계 라벨 기준

가드레일의 `## 실행 지침` 단계에 붙이는 라벨과 쓰는 방식이다. 새 절을 쓰거나 기존 절을 고칠 때 이 기준을 따른다(2026-10-09 정함).

## 라벨은 둘

| 라벨 | 뜻 | 단계 안에 두는 것 |
|---|---|---|
| `[학습자 직접]` | 학습자가 손으로 한다 | 명령 블록, 또는 웹 조작 절차 |
| `[AI 프롬프트]` | 학습자가 AI에게 시킨다 | 프롬프트 코드 블록(```` ```text ````)과 정답 파일 경로 |

- 단계마다 라벨은 하나다. 한 단계에 성격 2개가 섞이면 단계를 나눈다.
- `[AI 프롬프트]` 단계에는 학습자가 칠 명령 블록을 두지 않는다. 그 명령은 `[학습자 직접]` 단계로 뺀다.
- `[학습자 직접]` 단계에는 명령 블록이 있어야 한다. "push한다"처럼 문장으로만 적지 않는다.
- 명령 블록에 `[root@cp-k8s ~]#` 같은 프롬프트 접두를 붙이지 않는다. 그대로 붙여 넣어 실행되는 형태로 둔다.

## 위치는 노드가 기본

실습은 컨트롤 플레인 노드에서 한다. 그래서 위치는 적지 않고 예외만 적는다.

| 표기 | 언제 |
|---|---|
| `[학습자 직접 · 웹]` | 브라우저와 UI 조작(GitHub, Docker Hub, Jenkins, Argo CD, GitLab, AWS 콘솔, Slack) |
| `[학습자 직접 · 호스트]` | 호스트 PC에서 치는 것(ssh 접속, hosts 파일, Claude Code 실행) |

AI는 호스트의 Claude Code에서 ssh로 노드의 파일을 읽고 쓴다. 이 전제는 AGENTS.md에 있으므로 단계마다 적지 않는다. 다만 AI가 노드 파일을 고치는 단계는 프롬프트에 경로를 적는다(예: `/root/workspace/worklog-backend/`).

## 행동은 단계에만

- 사전 조건에는 상태만 적는다("ch6.5 완료", "Docker Hub에 이미지가 있음"). 명령이 필요하면 단계로 올린다.
- 체크리스트, 주의사항, 트러블슈팅에 들어 있는 실제 행동(`argocd app set`, 워크플로 끄기, `uv lock`)은 단계로 올린다. 주의사항은 "하지 말 것"과 "해도 됨"만 둔다.
- 주의사항의 "AI가 하지 말 것"이 본문 단계와 어긋나면 본문에 맞춘다.

## 용어

| 쓰는 말 | 쓰지 않는 말 |
|---|---|
| 학습자 | 독자, 사용자 |
| AI | 클로드, Claude(가드레일 본문에서. 시연 화면과 강의 제목은 Claude Code) |
| 컨트롤 플레인 노드 | cp, cp 노드, control plane 노드 |
| 호스트 | 로컬, 내 컴퓨터, 학습자 PC |

호스트 이름 `cp-k8s`와 `ssh root@192.168.1.10`은 실제 값이라 그대로 쓴다.

Jenkins 메뉴는 한국어 브라우저에서 보이는 이름 그대로 적는다(2026-10-19 저자 결정, Jenkins 2.541.3에서 확인). Jenkins 본체 메뉴 일부만 한국어이고 플러그인 메뉴는 영어다. 학습자 브라우저가 영어면 왼쪽 열의 영어 이름으로 보인다고 안내한다.

| 영어 화면 | 한국어 화면(강의 표기) |
|---|---|
| Manage Jenkins | Jenkins 관리 |
| New Item(왼쪽 메뉴) | 새로운 Item |
| Build Now | 지금 빌드 |
| Build History | 빌드 기록 |

Credentials, System, Global, Add Credentials, Plugins, Clouds, Configure, Scan Multibranch Pipeline Now, Console Output, Branch Sources, Add source, Save는 한국어 화면에서도 영어다. 프롬프트는 "~해줘"체로 맞춘다.

## 학습자 몫과 AI 몫, 프롬프트 빈칸 (2026-10-18 저자 결정)

**학습자 직접으로 두는 것**: 자격 증명, 웹 UI, 승인(promote, 수동 sync), 그 절에서 관찰할 실험(ch7의 set image, rollout undo),
그리고 AI가 한 일을 확인하는 짧은 명령이다.
**AI 프롬프트로 넘기는 것**: ch7부터 기계적 실행(apply, git add/commit/push, git pull, 정리, 활성화 전환)이다.
ch3~ch6은 이 명령을 손으로 처음 겪는 구간이라 학습자 직접으로 둔다.

프롬프트는 뒤로 갈수록 학습자가 쓰는 몫을 늘린다.

| 구간 | 프롬프트 | 학습자 몫 |
|---|---|---|
| ch2~ch4 | 전체를 준다 | 복사해 붙여 넣는다. 줄마다 왜 필요한지 슬라이드에서 설명한다 |
| ch5~ch7 | 전체를 주되 그 절의 학습 목표가 담긴 1~2줄을 `[채우기: 힌트]`로 비운다 | 복사해 붙여 넣고 `[채우기]` 자리를 작성한다. 가드레일에 예시와 이유를 접어 둔다 |
| ch8~ch10 | 짧은 요청 예와 "계획에서 확인할 것" 표를 준다. 세부 조건은 가드레일의 "AI가 따를 조건"에 둔다 | 목적만 짧게 요청하고 "계획부터 보여줘"로 끝낸다. AI의 계획을 표로 검토하고 빠진 항목만 1줄로 요청한다 |

- **입력 방법**: 가드레일의 코드 블록을 복사해(GitHub 화면의 복사 버튼) Claude Code에 붙여 넣고, `[채우기: ...]` 자리와 `<dockerhub_username>` 같은
  자기 값을 고친 뒤 보낸다. 프롬프트 전체를 읽고 보내게 하려는 것이다(빈칸 답만 따로 보내는 방식은 쓰지 않는다).
- `<...>`는 학습자 자신의 값(계정, 태그)이고 `[채우기: ...]`는 그 절에서 생각해서 쓰는 줄이다. 둘을 구분해 쓴다.
- `[채우기: ...]`가 남은 채로 들어오면 AI는 짐작해 작성하거나 가드레일의 예시를 넣지 않고 되묻는다. 각 가드레일의 주의사항에도 적는다.
- 표시 이름은 `[채우기]`로 둔다. 일반 문장에 쓰지 않는 말이라 프롬프트 안에서 눈에 띄고 해야 할 일이 드러난다. 빈칸을 설명하는 문장은 "작성"으로 쓴다(2026-10-18 저자 판정: `[작성]`으로 바꿔 보니 일반 문장처럼 묻혔다).
- 빈칸은 경로, 파일 이름, 버전처럼 외울 값이 아니라 그 절에서 판단해야 하는 내용에 둔다.
- **예시는 접어 둔다**: 가드레일의 예시 표는 `<details><summary>예시 보기</summary>` 안에 둔다. 프롬프트를 복사하려고 연 학습자가 쓰기 전에 답을 보지 않게 한다.
- 짧은 요청(1~2줄, 오류 해석이나 설명 요청)은 어느 구간이든 학습자가 직접 친다.
- **ch8~ch10 형식** (2026-10-18 밤 저자 결정, 10.9 시안으로 확인): 처음에는 요구 사항 표로 학습자가 5부분을 처음부터 쓰게 했다(8.3 시안). 그런데 후반에 학습자가 쓰는 양이 너무 많았고(ch10 31개 약 10,700자) 실무에서는 이렇게 모든 조건을 적지 않는다. 그래서 "짧은 요청 + 계획 검토"로 바꿨다.
  - 슬라이드는 AI 단계마다 장 1개(`prompt_review`)다. 위에 짧은 요청(끝에 "계획부터 보여줘"), 아래에 "계획에서 확인할 것 | 누락 시 결과" 표 2~3줄, 안내 상자 "맞으면 '계획대로 만들어줘', 빠진 항목이 있으면 그 항목만 1줄로 요청합니다". 요청 3줄, 표 3줄이 한계다. 노트 첫 줄은 화면 전환 안내다(영상에서 터미널로 넘어가 실제로 입력하고 계획을 검토한다).
  - push, 커밋 받기, 활성화 전환, 데모, 되돌리기처럼 기계적인 요청은 계획 없이 짧은 요청 장(`ai_prompts`)만 둔다.
  - 가드레일은 단계마다 짧은 요청 예, **AI가 따를 조건**(예전 예시 프롬프트의 조건), **계획에서 확인할 것** 표를 둔다. AI는 요청이 짧아도 이 조건을 읽어 따르고, 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다.
  - 확인 항목은 5장부터 7장까지 `[채우기]`로 직접 넣어 본 조건과 이어진다. 바뀐 방법은 ch8 p24("8장부터 AI에게 맡기는 방법이 바뀝니다"), p25("실행 전에 미리 보고 판단합니다": dry-run, argocd app diff, terraform plan과 같은 미리 보기)에서 설명한다.

## 프롬프트 작성 방식: 모범 사례(Best Practice) 기반 (2026-10-18 저자 결정)

프롬프트는 Anthropic의 모범 사례(Best Practice)를 기반으로 쓴다. 학습자가 따라 쓸 예시이기도 하다. ch8~ch10에서는 첫 문장(무엇을, 왜)과 "끝나면"(계획부터 보여줘)만 학습자가 쓰고 조건은 가드레일에 둔다.

```text
[무엇을, 왜] 한두 문장
파일: [경로]
조건:
- ...
- [채우기: 힌트]
참고: [따라 할 기존 파일이나 값의 출처]
끝나면: [확인 방법]을 실행하고 결과를 보여줘. [멈출 지점]에서 멈춰줘.
```

| 줄 | 근거 |
|---|---|
| 첫 문장에 목적(왜) | 지시의 이유를 주면 Claude가 의도에 맞게 판단한다 ("Add context to improve performance") |
| 파일, 조건을 구체적으로 | 맥락을 모르는 동료가 읽고 따라 할 수 있어야 한다 ("Be clear and direct") |
| 참고 | 따라 할 기존 패턴과 값의 출처를 짚는다 (Claude Code "Provide specific context") |
| 끝나면: 확인 | 스스로 확인할 방법을 주고 성공 주장 대신 증거를 보여 달라고 한다 (Claude Code "Give Claude a way to verify its work") |
| 끝나면: 멈출 지점 | 하지 말라는 말 대신 어디서 멈출지 쓴다. 되돌리기 어려운 일(push, 삭제) 앞에서 멈추게 한다 ("Tell Claude what to do", "Balancing autonomy and safety") |

출처: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-4-best-practices ,
https://code.claude.com/docs/en/best-practices

- 지시와 조건이 길면 머리말(파일, 조건, 참고, 끝나면)로 나눈다. XML 태그 대신 한국어 머리말을 쓴다. 학습자가 따라 쓰기 쉽게 하려는 것이다.
- 짧은 실행 요청(적용, push, 정리)은 첫 문장과 "끝나면"만 써도 된다.
- **처음 설명하는 곳**: 5부분은 2.13(가드레일 "프롬프트 읽는 법", 슬라이드 "Anthropic 모범 사례(Best Practice)로 프롬프트 작성하기"), 빈칸은 5.3("이 절부터 프롬프트의 빈칸은 직접 작성합니다"), AI 분담은 7.3("이 절부터 적용과 정리는 AI에게 맡깁니다"), 짧은 요청과 계획 검토는 8.3("8장부터 AI에게 맡기는 방법이 바뀝니다").

## 프롬프트의 마침표

- 지시나 질문처럼 서술어로 끝나는 문장은 마침표를 찍는다. 목록 줄이라도 "~해줘", "~하지 마"로 끝나면 문장이다.
- 조건이나 값만 적은 목록 줄은 찍지 않는다. 명사, 값, "~과 같게"처럼 서술어 없이 끝나는 줄이다.
- 마침표 하나는 토큰 1개 정도라 비용 차이는 없다. 지시가 끝나고 조건이 시작되는 경계를 보이려고 찍는다(2026-10-18 저자 결정).
- 정한 날 기준으로 어긋난 줄이 52줄 있었다(서술어인데 마침표 없음 42, 값인데 마침표 있음 10). 소급해서 고치지 않고 그 절을 다시 열 때 고친다.
  슬라이드의 AI 프롬프트 장은 가드레일 문장을 그대로 옮기므로 가드레일을 고치면 슬라이드도 따라 고친다.
