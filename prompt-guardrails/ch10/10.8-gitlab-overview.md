# 10.8 GitLab CI는 무엇이 다른가

> **학습자 진입 방식**: 개념 절이다. 실습 없음. GitHub Actions(10.6)와 Jenkins(10.7)로 EKS 배포까지
> 해 본 상태에서, 같은 일을 GitLab CI로 하면 무엇이 달라지는지 정리한 뒤 10.9·10.10으로 간다.

## 이 절의 목적

본편(ch4~ch9)은 GitHub Actions와 Jenkins 두 도구로 진행했다. GitLab CI는 10장에서 처음 다룬다.
같은 파이프라인을 처음부터 다시 만들지 않는다. 이미 아는 흐름 위에서 **달라지는 점만** 본다.

10장의 두 실습이 각각 하나씩 맡는다.

| 실습 | 무엇을 확인하나 |
|---|---|
| 10.9 | CI 본연의 기능. 테스트, 이미지 빌드, 매니페스트 갱신까지 하고 배포는 Argo CD에 맡긴다 |
| 10.10 | 인프라까지. 10.4의 Terraform state를 GitLab에 맡기고 파이프라인으로 EKS를 지운다 |

## 세 도구 비교

| | GitHub Actions | Jenkins | GitLab CI |
|---|---|---|---|
| 어디에 있나 | GitHub에 내장 | 직접 설치한 서버 | GitLab에 내장 |
| 파이프라인 파일 | `.github/workflows/*.yaml` (여러 개) | `Jenkinsfile` (Groovy) | `.gitlab-ci.yml` (저장소에 하나) |
| 실행 환경 | GitHub 호스팅 러너 | 에이전트(Pod) | 공유 러너 또는 직접 등록한 러너 |
| 단계 표현 | job과 `needs` | `stages { stage {} }` | `stages` 목록 + job별 `stage`, `needs` |
| 언제 돌릴지 | `on:` | 트리거 설정 | `workflow:rules`, job별 `rules` |
| 비밀값 | Secrets | Credentials | CI/CD Variables (masked, protected) |
| 사람이 누르는 단계 | environment 승인 | `input` | `when: manual` |
| Terraform state 보관 | 없음 (S3 등 따로 구성) | 없음 | **프로젝트마다 기본 제공** |

## 탐색 질문에 답할 때 짚을 것

- **설정이 한 파일에 모인다.** GitHub Actions는 워크플로 파일이 여러 개일 수 있고 Jenkins는 서버 설정과
  `Jenkinsfile`이 나뉜다. GitLab CI는 저장소 루트의 `.gitlab-ci.yml` 하나가 파이프라인 전체다.
- **stage가 먼저 정해진다.** `stages:`에 순서를 적고 job마다 어느 stage인지 붙인다. 같은 stage의 job은
  동시에 돈다. `needs:`를 쓰면 stage 순서와 상관없이 앞 job이 끝나자마자 시작한다.
- **변수의 보호 수준을 고른다.** masked는 로그에서 값을 가리고, protected는 보호된 브랜치(main 등)의
  파이프라인에만 값을 넘긴다. AWS 키처럼 인프라를 바꾸는 값은 둘 다 켠다.
- **사람이 버튼을 누르게 할 수 있다.** `when: manual`인 job은 파이프라인에 나타나기만 하고 누를 때 실행된다.
  10.10에서 apply와 destroy를 이렇게 둔다.
- **Terraform state를 맡길 곳이 있다.** 10.4의 state는 학습자 PC의 파일로만 있다. 잃어버리면
  `terraform destroy`를 할 수 없어 비용이 남는다. GitLab은 프로젝트마다 state 저장소(HTTP backend)를 준다.
  이것이 이 장의 제목 "GitLab CI로 인프라까지 관리하기"의 근거다.
- **Argo CD는 Git 저장소면 된다.** GitHub이든 GitLab이든 상관없다. 10.9에서 Argo CD가 보는 저장소만
  GitLab으로 바꾸고 클러스터 쪽은 그대로 둔다.

## 주의사항

- ⛔ AI가 하지 말 것: 이 절에서 GitLab 계정이나 저장소를 만들라고 진행하지 말 것. 준비는 10.9 단계 1~2에서 한다.

  GitLab 18.0에서 제거됐다(Terraform 라이선스 변경). state 보관 기능은 그대로이며 10.10은 템플릿 없이 job을 직접 쓴다.
- ✅ AI가 해도 됨: 위 비교 표를 학습자가 이미 만든 10.6·10.7 파일과 연결해 설명.
