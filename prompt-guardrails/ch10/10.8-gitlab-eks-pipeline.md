## 주의사항

- ⛔ AI가 하지 말 것: `$DOCKERHUB_USERNAME/$DOCKER_REPOSITORY` 형태로 username 중복 결합 (DOCKER_REPOSITORY에 이미 username 포함)
- ⛔ AI가 하지 말 것: test stage `allow_failure: true` 제거 (worklog-backend uv container 비동기 테스트 호환성 이슈로 의도적 유지)
- ⛔ AI가 하지 말 것: AWS Access Key를 `.gitlab-ci.yml`에 평문 작성 — 반드시 Variables 참조
- ⛔ AI가 하지 말 것: Part A에서 `kubectl apply` 후 deploy_manifest를 git push (ch9 패턴) — EKS 직접 접근이 본 절의 핵심
- ⛔ AI가 하지 말 것: `argocd login`을 `--insecure` 없이 작성 (self-signed 인증서)
- ✅ AI가 해도 됨: `.gitlab-ci.yml` 작성, `amazon/aws-cli`/`argoproj/argocd` 이미지 선택 이유 설명
- ✅ AI가 해도 됨: `docker:24-dind` + `DOCKER_TLS_CERTDIR=''` + `DOCKER_HOST=tcp://docker:2375` 조합 설명
- ✅ AI가 해도 됨: ch9 git push 위임 패턴 vs ch10 직접 호출 패턴 비교
- ⚠️ Variables의 `Protected` 옵션은 `main` 같은 보호된 브랜치/태그에서만 노출됨 — workflow.rules와 일치해야 변수가 주입됨
- ⚠️ `ARGOCD_SERVER`는 EKS 재생성 시 NLB hostname이 바뀜 → Variable 갱신 필요
- ⚠️ Part B의 `argocd app set ... --parameter image.tag=...`는 Application이 Helm/Kustomize 기반일 때 동작. 단순 K8s manifest Application이면 `app sync`만으로 충분 (또는 deploy_manifest sed + git push 패턴 병용)
- ⚠️ **EKS 검증 끝나면 즉시 `terraform destroy`** (ch10.4) — 비용 누적 방지
- ⛔ **script 항목에 콜론(`:`)+공백이 들어가면 반드시 작은따옴표로 감싼다.** `- echo "build successful: $SHA"`, `- sed ... "s|image: ...|"`, `- git commit -m "deploy: ..."` 같은 줄을 안 감싸면 GitLab YAML 파서가 매핑으로 오인해 파이프라인이 **0 job으로 실패**한다(`mapping values are not allowed`). push 전에 CI lint(Settings → CI/CD → Pipeline editor 또는 lint API)로 확인.
