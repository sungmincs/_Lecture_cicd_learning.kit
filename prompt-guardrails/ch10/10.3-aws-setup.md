# 10.3 AWS 환경 설정 (CLI, IAM)

> **학습자 진입 방식**:
> - `[학습자 직접]`: AWS 계정 생성, IAM User 생성 + Access Key 발급, AWS CLI 설치, 리전 정하기 + `aws configure`, 연결과 리전 확인, eksctl 설치
> - `[AI 프롬프트]`: IAM 정책 JSON 작성, 설치 트러블슈팅

## 사전 조건

- 본인 명의의 AWS 계정 (카드 등록 완료). 새로 만든다면 **무료 플랜(Free plan)**을 고른다
- 로컬에 ch3까지 진행한 Vagrant + VirtualBox 기반 K8s 동작 확인
- 유료 플랜이나 기존 계정이면 결제 알림(Budgets) 설정 권장. EKS 비용은 시간 단위로 나간다
- 학습자 OS(Linux/macOS) — 가이드 명령은 Linux 기준, macOS는 `brew install awscli` 가능

## AWS 가입 방식과 리전 (먼저 읽기)

AWS에는 지금 가입 방식이 두 가지 있다. 수강생이 어느 쪽으로 가입될지는 AWS가 정한다
(새 방식은 일부 사용자에게 순차 적용 중).

| | 기존 방식 | 새 방식 |
|---|---|---|
| 알아보는 법 | 콘솔 우측 상단에 **리전 선택**이 있다 | 콘솔이 "프로젝트" 화면이고 리전 선택이 없다 |
| 리전 | 고를 수 있다. 이 강의는 **ap-northeast-2(서울)** | 연락처 국가로 고정된다. 한국은 **ap-southeast-2(시드니)** |
| 무료 플랜 | 있다 | 있다 |

**이 강의에서 리전을 적는 곳은 단계 5의 `aws configure` 한 곳뿐이다.** 10.4의 Terraform은 그 값을 그대로 쓴다.
새 방식 계정에서 배정되지 않은 리전을 쓰면 읽기 명령까지 `explicit deny in a service control policy`로 거부된다.

무료 플랜에서 10장 전체 비용은 크레딧($100) 안에서 끝난다. 무료 플랜은 크레딧이 떨어져도 청구하지 않고 계정을 닫는다.

## 실행 지침

> 로컬 K8s와 EKS의 개념적 차이(네트워킹·스토리지·보안·스케일링)는 10.2에서 다뤘다. 본 절은 EKS를 다루기 위한 AWS 환경을 실제로 구성한다.

### 단계 1: 현재 로컬 클러스터 상태 확인 `[학습자 직접]`

```bash
kubectl get nodes
kubectl cluster-info
```

> ch10 진행 중에도 로컬 클러스터는 유지 — EKS와 분리해서 비교 학습한다.

### 단계 2: AWS IAM User 생성 + Access Key 발급 `[학습자 직접]`

AWS Console → IAM → Users → Create user

1. User name: `cicd-learning-user`
2. Attach policies directly → **`AdministratorAccess`** 하나를 붙인다
3. 생성 후 → Security credentials → Create access key (Use case: Command Line Interface)
4. **Access Key ID**, **Secret Access Key**를 csv로 받아 안전한 곳에 둔다 (Secret은 다시 볼 수 없다)

> ⚠️ 학습용 계정에 한한 설정이다. 10.4의 Terraform은 EKS, EC2, VPC, IAM 역할, KMS, CloudWatch Logs를
> 모두 만든다. 서비스별 관리형 정책을 골라 붙이면 빠지는 권한이 생긴다(예: `AmazonEKSClusterPolicy`는
> EKS 서비스가 쓰는 정책이라 사람에게 붙여도 클러스터를 만들 수 없다). 실무에서는 Terraform이 실제로
> 호출하는 API만 허용하는 정책을 따로 만든다.

> 새 방식 계정에서는 "IAM users should only be used for programmatic access"라는 안내가 뜬다. 이 사용자는
> CLI와 Terraform 전용이라 안내와 맞는 사용이다.

### 단계 3: AWS CLI 설치 `[학습자 직접]`

```bash
# Linux
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install

# macOS
brew install awscli

aws --version
```

### 단계 4: 내 계정의 리전 정하기 `[학습자 직접]`

위 "AWS 가입 방식과 리전" 표로 정한다.

- 콘솔 우측 상단에 리전 선택이 있다 → `ap-northeast-2`
- 없다(프로젝트 화면) → 배정된 리전. 한국 주소로 가입했다면 `ap-southeast-2`

### 단계 5: AWS 자격증명 구성 `[학습자 직접]`

```bash
aws configure
```

| 프롬프트 | 입력값 |
|---|---|
| AWS Access Key ID | 단계 2에서 발급한 키 |
| AWS Secret Access Key | 단계 2에서 발급한 시크릿 |
| Default region name | **단계 4에서 정한 리전** |
| Default output format | `json` |

> 이미 다른 AWS 계정을 기본 프로필로 쓰고 있다면 `aws configure --profile cicd`처럼 이름을 붙이고,
> 이후 터미널에서 `export AWS_PROFILE=cicd`로 고른다. 기본 프로필을 덮어쓰지 않는다.

### 단계 6: AWS 연결과 리전 확인 `[학습자 직접]`

```bash
aws sts get-caller-identity
aws ec2 describe-availability-zones --query 'AvailabilityZones[].ZoneName' --output text
```

- `Arn`이 `arn:aws:iam::<account_id>:user/cicd-learning-user`로 표시되면 자격증명 성공
- 가용 영역이 3개 이상 나오면 리전도 맞다
- `explicit deny in a service control policy`가 나오면 새 방식 계정인데 리전이 다르다. 단계 4로 돌아가
  `aws configure set region ap-southeast-2`로 고친다

### 단계 7: eksctl 설치 (선택) `[학습자 직접]`

```bash
# Linux
curl --silent --location "https://github.com/eksctl-io/eksctl/releases/latest/download/eksctl_$(uname -s)_amd64.tar.gz" | tar xz -C /tmp
sudo mv /tmp/eksctl /usr/local/bin

# macOS
brew install eksctl

eksctl version
```

> ch10에서는 Terraform으로 EKS를 만들지만, eksctl은 트러블슈팅/검증에 유용하다.

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<aws_region>` | 학습자 계정의 리전 (단계 4) | ❌ 가입 방식에 따라 다르다. 학습자에게 확인 |
| `<aws_access_key_id>` | IAM Access Key ID | ❌ 학습자 발급 |
| `<aws_secret_access_key>` | IAM Secret Access Key | ❌ 학습자 발급 |

## 주의사항

- ⛔ AI가 하지 말 것: Access Key/Secret을 코드/문서에 하드코딩하지 말 것 (`aws configure` 또는 환경변수로만 다룸)
- ⛔ AI가 하지 말 것: Root 계정 Access Key 발급 가이드 금지 — 반드시 IAM User 생성 후 발급
- ⛔ AI가 하지 말 것: 학습자 AWS 계정에서 임의로 명령을 실행하지 말 것 (모든 aws/eksctl 명령은 학습자 직접)
- ✅ AI가 해도 됨: IAM Policy JSON 초안 작성, 정책 비교 설명
- ✅ AI가 해도 됨: AWS CLI 설치 트러블슈팅(권한, PATH)
- ⚠️ **비용 주의**: 본 절은 IAM/CLI 설정만 — 과금 X. 단 ch10.4 이후 EKS apply 시 과금 시작
- ⚠️ Access Key는 재발급 불가 — 분실 시 비활성화 후 재발급
- ⚠️ `AdministratorAccess`는 학습용 한정. 실무에서는 Terraform이 요구하는 최소 정책만 부여
- ⛔ AI가 하지 말 것: 리전을 `ap-northeast-2`로 짐작해 넣지 말 것. 새 가입 방식 계정은 다른 리전으로 고정된다
- ⛔ AI가 하지 말 것: 학습자의 기본 AWS 프로필을 덮어쓰라고 안내하지 말 것 (회사 계정 등이 있을 수 있다)
- ✅ AI가 해도 됨: 콘솔 화면 설명을 듣고 가입 방식과 리전을 판단해 주기
