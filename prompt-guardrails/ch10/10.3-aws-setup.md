# 10.3 AWS 환경 설정 (CLI, IAM)

> **학습자 진입 방식**:
> - `[학습자 직접]`: AWS 계정 생성, IAM User 생성 + Access Key 발급, AWS CLI 설치 + `aws configure`, eksctl 설치, `aws sts get-caller-identity`로 연결 확인
> - `[AI 프롬프트]`: IAM 정책 JSON 작성, 설치 트러블슈팅

## 사전 조건

- 본인 명의의 AWS 계정 (신용카드 등록 완료)
- 로컬에 ch3까지 진행한 Vagrant + VirtualBox 기반 K8s 동작 확인
- 결제 알림(Billing Alert) 설정 권장 — EKS 비용은 시간 단위 과금
- 학습자 OS(Linux/macOS) — 가이드 명령은 Linux 기준, macOS는 `brew install awscli` 가능

## 실행 지침

> 로컬 K8s와 EKS의 개념적 차이(네트워킹·스토리지·보안·스케일링)는 10.2에서 다뤘다. 본 절은 EKS를 다루기 위한 AWS 환경을 실제로 구성한다.

### 단계 1: 현재 로컬 클러스터 상태 확인 `[학습자 직접]`

```bash
kubectl get nodes
kubectl cluster-info
```

> ch10 진행 중에도 로컬 클러스터는 유지 — EKS와 분리해서 비교 학습한다.

### 단계 2: AWS IAM User 생성 + Access Key 발급 `[학습자 직접]`

AWS Console → IAM → Users → Create user

1. User name: `cicd-learning-user` (예시)
2. Attach policies directly → 최소 권한 원칙으로 다음 정책 부여 (학습용)
   - `AmazonEKSClusterPolicy`
   - `AmazonEKSWorkerNodePolicy`
   - `AmazonEC2FullAccess`
   - `AmazonVPCFullAccess`
   - `IAMFullAccess` (Terraform module이 IAM Role 생성)
3. 생성 후 → Security credentials → Create access key (Use case: CLI)
4. **Access Key ID**, **Secret Access Key**를 안전한 곳에 저장 (재발급 불가)

> ⚠️ 실서비스에서는 IAMFullAccess 부여 금지. 학습용 한정.

### 단계 3: AWS CLI 설치 `[학습자 직접]`

```bash
# Linux
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install

# macOS
brew install awscli

aws --version
```

### 단계 4: AWS 자격증명 구성 `[학습자 직접]`

```bash
aws configure
```

| 프롬프트 | 입력값 |
|---|---|
| AWS Access Key ID | 단계 2에서 발급한 키 |
| AWS Secret Access Key | 단계 2에서 발급한 시크릿 |
| Default region name | `ap-northeast-2` (서울) |
| Default output format | `json` |

### 단계 5: AWS 연결 확인 `[학습자 직접]`

```bash
aws sts get-caller-identity
```

`Arn`이 `arn:aws:iam::<account_id>:user/cicd-learning-user`로 표시되면 성공.

### 단계 6: eksctl 설치 (선택) `[학습자 직접]`

```bash
# Linux
curl --silent --location "https://github.com/eksctl-io/eksctl/releases/latest/download/eksctl_$(uname -s)_amd64.tar.gz" | tar xz -C /tmp
sudo mv /tmp/eksctl /usr/local/bin

# macOS
brew install eksctl

eksctl version
```

> ch10에서는 Terraform으로 EKS를 만들지만, eksctl은 트러블슈팅/검증에 유용하다.

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<aws_region>` | AWS 리전 (예: ap-northeast-2) | ✅ 한국이면 ap-northeast-2 권장 |
| `<aws_access_key_id>` | IAM Access Key ID | ❌ 학습자 발급 |
| `<aws_secret_access_key>` | IAM Secret Access Key | ❌ 학습자 발급 |

## 주의사항

- ⛔ AI가 하지 말 것: Access Key/Secret을 코드/문서에 하드코딩하지 말 것 (`aws configure` 또는 환경변수로만 다룸)
- ⛔ AI가 하지 말 것: Root 계정 Access Key 발급 가이드 금지 — 반드시 IAM User 생성 후 발급
- ⛔ AI가 하지 말 것: 학습자 AWS 계정에서 임의로 명령을 실행하지 말 것 (모든 aws/eksctl 명령은 학습자 직접)
- ✅ AI가 해도 됨: IAM Policy JSON 초안 작성, 정책 비교 설명
- ✅ AI가 해도 됨: AWS CLI 설치 트러블슈팅(권한, PATH)
- ⚠️ **비용 주의**: 본 절은 IAM/CLI 설정만 — 과금 X. 단 ch10.4 이후 EKS apply 시 과금 시작
- ⚠️ Access Key는 재발급 불가 — 분실 시 비활성화 후 재발급
- ⚠️ `IAMFullAccess`는 학습용 한정. 실무에서는 Terraform이 요구하는 최소 정책만 부여
