## AWS 가입 방식과 리전 (먼저 읽기)

AWS에는 지금 가입 방식이 두 가지 있다. 수강생이 어느 쪽으로 가입될지는 AWS가 정한다
(새 방식은 일부 사용자에게 순차 적용 중).

| | 기존 방식 | 새 방식 |
|---|---|---|
| 알아보는 법 | 콘솔 우측 상단에 **리전 선택**이 있다 | 콘솔이 "프로젝트" 화면이고 리전 선택이 없다 |
| 리전 | 고를 수 있다. 이 강의는 **ap-northeast-2(서울)** | 연락처 국가로 고정된다. 한국은 **ap-southeast-2(시드니)** |
| 무료 플랜 | 있다 | 있다 |

**이 강의에서 리전을 적는 곳은 단계 5의 `aws configure` 한 곳뿐이다.** 10.4의 Terraform은 그 값을 그대로 쓴다.
새 방식 계정에서 배정되지 않은 리전을 쓰면 읽기 명령까지 `explicit deny in a service control policy`로 거부된다.

무료 플랜에서 10장 전체 비용은 크레딧($100) 안에서 끝난다. 무료 플랜은 크레딧이 떨어져도 청구하지 않고 계정을 닫는다.

## 실행 지침

### 단계 1: 로컬 클러스터 확인 `[학습자 직접]`

```bash
kubectl get nodes
kubectl config get-contexts
```

10장을 하는 동안에도 로컬 클러스터는 그대로 둔다. context 이름은 10.4 단계 7에서 `local`로 바꾼다.

### 단계 2: IAM User 생성과 Access Key 발급 `[학습자 직접 · 웹]`

AWS Console → IAM → Users → Create user

1. User name: `cicd-learning-user`
2. Attach policies directly → **`AdministratorAccess`** 하나를 붙인다
3. 생성 후 → Security credentials → Create access key (Use case: Command Line Interface)
4. **Access Key ID**, **Secret Access Key**를 csv로 받아 안전한 곳에 둔다 (Secret은 다시 볼 수 없다)

학습용 계정에 한한 설정이다. 10.4의 Terraform은 EKS, EC2, VPC, IAM 역할, KMS, CloudWatch Logs를 모두 만든다.
서비스별 관리형 정책을 골라 붙이면 빠지는 권한이 생긴다(예: `AmazonEKSClusterPolicy`는 EKS 서비스가 쓰는 정책이라
사람에게 붙여도 클러스터를 만들 수 없다). 실무에서는 Terraform이 실제로 호출하는 API만 허용하는 정책을 따로 만든다.

새 방식 계정에서는 "IAM users should only be used for programmatic access"라는 안내가 뜬다. 이 사용자는
CLI와 Terraform 전용이라 안내와 맞는 사용이다.

### 단계 3: 노드에 AWS CLI 설치 `[AI 프롬프트]`

> "컨트롤 플레인 노드(ssh root@192.168.1.10)에 AWS CLI v2 2.35.17을 설치해줘.
> - 노드 아키텍처(`uname -m`)에 맞는 zip을 받는다: `https://awscli.amazonaws.com/awscli-exe-linux-<x86_64|aarch64>-2.35.17.zip`
> - unzip이 없으면 apt로 설치
> - 끝나면 `aws --version` 결과를 보여줘
> - `aws configure`는 내가 직접 할 테니 하지 마. 키를 묻지도 마"

### 단계 4: 내 계정의 리전 정하기 `[학습자 직접 · 웹]`

AWS 콘솔을 보고 위 "AWS 가입 방식과 리전" 표로 정한다.

- 콘솔 우측 상단에 리전 선택이 있다 → `ap-northeast-2`
- 없다(프로젝트 화면) → 배정된 리전. 한국 주소로 가입했다면 `ap-southeast-2`

### 단계 5: AWS 자격 증명 구성 `[학습자 직접]`

```bash
aws configure
```

| 프롬프트 | 입력값 |
|---|---|
| AWS Access Key ID | 단계 2에서 발급한 키 |
| AWS Secret Access Key | 단계 2에서 발급한 시크릿 |
| Default region name | **단계 4에서 정한 리전** |
| Default output format | `json` |

키는 노드의 `/root/.aws/credentials`에 저장된다. 2.13에서 본 대로 클러스터를 다시 만들면 사라진다.

### 단계 6: AWS 연결과 리전 확인 `[학습자 직접]`

```bash
aws sts get-caller-identity
aws ec2 describe-availability-zones --query 'AvailabilityZones[].ZoneName' --output text
```

- `Arn`이 `arn:aws:iam::<account_id>:user/cicd-learning-user`로 표시되면 자격 증명이 맞다
- 가용 영역이 3개 이상 나오면 리전도 맞다
- `explicit deny in a service control policy`가 나오면 새 방식 계정인데 리전이 다르다. 단계 4로 돌아가
  `aws configure set region ap-southeast-2`로 고친다

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<aws_region>` | 학습자 계정의 리전 (단계 4) | ❌ 가입 방식에 따라 다르다. 학습자에게 확인 |
| `<account_id>` | AWS 계정 ID (단계 6의 출력에 보이는 12자리) | ❌ 학습자 계정 값 |

## 주의사항

- ⛔ AI가 하지 말 것: Access Key나 Secret을 묻거나, 파일과 문서에 적지 말 것. `aws configure`는 학습자가 직접 한다
- ⛔ AI가 하지 말 것: Root 계정의 Access Key를 발급하라고 안내하지 말 것. 반드시 IAM User를 만들어 발급한다
- ⛔ AI가 하지 말 것: 학습자 AWS 계정에서 리소스를 만들거나 지우는 명령을 임의로 실행하지 말 것
- ⛔ AI가 하지 말 것: 리전을 `ap-northeast-2`로 짐작해 넣지 말 것. 새 가입 방식 계정은 다른 리전으로 고정된다
- ⛔ AI가 하지 말 것: 호스트에 AWS CLI를 설치하라고 안내하지 말 것. 10장도 노드에서 한다
- ✅ AI가 해도 됨: AWS CLI 설치와 설치 오류 해석, 콘솔 화면 설명을 듣고 가입 방식과 리전을 판단해 주기
- ⚠️ 이 절은 IAM과 CLI 설정뿐이라 과금이 없다. 10.4에서 EKS를 만들면 과금이 시작된다
- ⚠️ Secret Access Key는 다시 볼 수 없다. 잃어버리면 그 키를 비활성화하고 새로 발급한다
- ⚠️ `AdministratorAccess`는 학습용 한정이다
- ⚠️ eksctl은 이 강의에서 쓰지 않는다(EKS는 Terraform으로 만든다). 예전 판에 있던 eksctl 설치 단계는 2026-10-10에 뺐다
