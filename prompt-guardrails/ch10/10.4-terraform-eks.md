# 10.4 Terraform으로 EKS 배포/삭제

> **학습자 진입 방식**:
> - `[학습자 직접]`: `terraform init/plan/apply`, kubectl context 정리, 클러스터 확인
> - `[AI 프롬프트]`: Terraform 설치, 연결 확인용 `terraform-test/`와 EKS용 `terraform-eks/` 작성(프롬프트는 학습자가 처음부터 작성), 비용 질문
>
> Terraform 파일은 강의 저장소가 아니라 노드의 `/root/ch10/`에 만든다. state 파일도 거기에 생긴다.
> 10.10에서 이 폴더를 통째로 GitLab 프로젝트로 옮긴다.

## 사전 조건

- ch10.3 완료 (노드에서 `aws sts get-caller-identity`가 `cicd-learning-user`를 보여 줌)
- 결제 알림을 걸어 두기를 강하게 권한다. destroy를 하지 않으면 비용이 쌓인다

## 실행 지침

### 단계 1: Terraform 설치 `[AI 프롬프트]`

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
노드에 Terraform을 설치하고 /root/ch10 폴더를 만들어줘. EKS를 코드로 만들려는 거야. 설치하기 전에 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- HashiCorp 공식 apt 저장소를 등록하고 terraform=1.15.7-1처럼 버전을 지정해 설치
- 작업 폴더 /root/ch10도 만들어줘.
- 끝나면: terraform version 결과를 보여줘.

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| HashiCorp 공식 apt 저장소 | 출처를 알 수 없는 파일을 설치 |
| 버전 1.15.7로 지정 | 10.10의 파이프라인과 버전이 달라 state를 읽지 못함 |

### 단계 2: 연결 확인 코드 `[AI 프롬프트]`

data source만 읽는 최소 코드다. 비용이 없다. provider에 리전을 적지 않아 `aws configure`의 리전을 쓴다.

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
자격 증명을 확인하는 최소 Terraform 코드를 /root/ch10/terraform-test에 만들어줘. EKS를 만들기 전에 AWS 접속을 확인하려는 거야. 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- 파일: /root/ch10/terraform-test/main.tf
- required_providers의 aws는 hashicorp/aws, ~> 5.0
- provider aws에는 리전을 적지 마. aws configure의 리전을 그대로 사용해.
- data aws_caller_identity current, output account_id와 caller_arn
- 비용이 드는 리소스는 만들지 마(data source만).
- 끝나면: 파일을 보여줘. terraform init 전에 멈춰줘.

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| provider에 리전을 적지 않음 | 리전이 두 곳에서 정해짐 |
| data로 읽기만 하고 리소스 없음 | 확인만 하려다 비용 발생 |

계획이 맞으면 학습자가 "계획대로 진행해줘"(파일이면 "계획대로 만들어줘")라고 한다. 빠진 항목이 있으면 학습자가 그 항목만 1줄로 요청한다.

### 단계 4: VPC와 변수 `[AI 프롬프트]`

EKS 코드는 확인할 것이 많아 단계 2개로 나눈다. 이 단계는 변수, VPC, 출력이고 단계 5에서 같은 `main.tf`에 EKS 모듈을 더한다.

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
EKS용 Terraform의 변수, VPC, 출력을 /root/ch10/terraform-eks에 만들어줘. 다음 단계에서 EKS 모듈을 추가할 거야. 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- 파일: /root/ch10/terraform-eks/의 variables.tf, main.tf, outputs.tf
- variables: region(default null), cluster_name(default cicd-learning-eks), tags
- vpc 모듈 terraform-aws-modules/vpc/aws ~> 5.0: cidr 10.0.0.0/16, AZ 3개, private 10.0.1~3.0/24, public 10.0.101~103.0/24, NAT gateway 1개

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| region 변수의 기본값 null | aws configure와 다른 리전에 생성 |
| 서브넷 태그 elb, internal-elb | 로드밸런서를 놓을 서브넷을 찾지 못함 |
| NAT Gateway 1개 | 가용 영역마다 생겨 비용 증가 |

계획이 맞으면 학습자가 "계획대로 진행해줘"(파일이면 "계획대로 만들어줘")라고 한다. 빠진 항목이 있으면 학습자가 그 항목만 1줄로 요청한다.

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

### 단계 8: context 정리와 확인 `[학습자 직접]`

클러스터가 둘이 됐다. 이름을 짧게 정해 둔다. 이제부터 `kubectl`은 EKS를 본다. 로컬 클러스터를 볼 때는 `--context local`을 붙인다. 앱의 외부 노출(ALB)은 10.5에서 한다.

```bash
kubectl config rename-context kubernetes-admin@kubernetes local
aws eks update-kubeconfig --name cicd-learning-eks --alias eks
kubectl get nodes
kubectl --context local get nodes     # 로컬 노드 4대
```

### 단계 9: state 파일 확인 `[학습자 직접]`

EKS는 지우지 않고 10.10까지 이어 간다. 삭제는 10.10의 마지막 단계에서 GitLab 파이프라인으로 한다.
이 `terraform.tfstate`를 지우거나 폴더를 정리하지 않는다. 이 파일이 없으면 `terraform destroy`를 할 수 없어 EKS 비용이 계속 나간다.
노드는 VM이다. 10.10을 마칠 때까지 `vagrant destroy`나 `vagrant up --provision`으로 클러스터를 다시 만들지 않는다. 다시 만들면 이 파일도 같이 사라진다.

```bash
ls -l /root/ch10/terraform-eks/terraform.tfstate
```

## 트러블슈팅

### 10장을 중간에 멈춰야 할 때

EKS를 켠 채로 두면 비용이 계속 나간다. 먼저 10.10 단계 11처럼 Argo CD Application, Ingress, LoadBalancer Service를 지워 로드밸런서를 회수한 뒤 지운다.

```bash
cd /root/ch10/terraform-eks
terraform destroy -auto-approve
```

10~15분 걸린다. 끝나면 AWS 콘솔의 EKS, EC2, VPC, NAT Gateway가 비었는지 본다. 10.5에서 만든 IAM 정책과 역할은 10.10 단계 13의 요청으로 지운다.

### state 파일이 없다 (노드를 다시 만들었거나 폴더를 지웠다)

Terraform으로는 지울 수 없다. AWS에 남은 것을 순서대로 직접 지운다. 노드를 다시 만들었다면 10.3부터 다시 해서 `aws`를 쓸 수 있게 한 뒤 진행한다.
순서가 중요하다. 로드밸런서와 NAT Gateway가 남아 있으면 VPC가 지워지지 않는다.

```bash
aws eks list-nodegroups --cluster-name cicd-learning-eks --query 'nodegroups' --output text    # 노드 그룹 이름 확인
aws eks delete-nodegroup --cluster-name cicd-learning-eks --nodegroup-name <nodegroup_name>
aws eks wait nodegroup-deleted --cluster-name cicd-learning-eks --nodegroup-name <nodegroup_name>
aws eks delete-cluster --name cicd-learning-eks
aws eks wait cluster-deleted --name cicd-learning-eks
```

그다음은 AWS 콘솔에서 지운다. EC2의 Load Balancers와 Target Groups, VPC의 NAT Gateways, Elastic IPs, 마지막으로 이름이 `cicd-learning-eks`로 시작하는 VPC다.
VPC를 지우면 서브넷과 라우팅 테이블, 보안 그룹이 같이 지워진다. 끝나면 Billing 화면에서 다음 날 비용이 0인지 확인한다.
과금이 큰 것은 EKS 클러스터, EC2 인스턴스, NAT Gateway, 로드밸런서 넷이다. 이 넷이 없으면 남은 것은 비용이 거의 없다.

### 10.5에서 앱 화면은 열리는데 할 일 목록이 뜨지 않거나 `504`가 섞여 나온다

노드 보안 그룹이 노드 사이의 80번 포트를 막고 있다. frontend Pod와 backend Pod가 같은 노드에 있을 때만 통한다.
`main.tf`의 module eks에 `node_security_group_additional_rules`의 `ingress_self_all`이 있는지 확인한다(단계 5의 프롬프트). 없으면 넣고 다시 apply한다. 규칙 하나만 더해지고 클러스터는 그대로다.

```bash
cd /root/ch10/terraform-eks
terraform apply -auto-approve          # Plan: 1 to add
```

### 노드 그룹이 `CREATING`에서 끝나지 않는다

무료 플랜은 무료 등급 대상이 아닌 인스턴스(t3.medium 등)를 거부한다. Terraform은 오류 없이 기다리기만 하고,
원인은 EC2 Auto Scaling 그룹의 활동 기록에만 남는다(`The specified instance type is not eligible for Free Tier`).
`c7i-flex.large`인지 확인한다.

### destroy가 VPC에서 `DependencyViolation`으로 실패한다

클러스터 안에서 만든 ALB나 NLB가 남아 있다. LoadBalancer Service와 Ingress를 `kubectl delete`로 지운 뒤 다시 한다(10.10 단계 11).

## 주의사항

- ⛔ AI가 하지 말 것: `terraform apply`나 `terraform destroy`를 대신 실행하지 말 것. 비용이 드는 일은 학습자가 직접 한다
- ⛔ AI가 하지 말 것: Terraform 파일을 강의 저장소나 fork 저장소 안에 만들지 말 것. `/root/ch10/`에 둔다
- ⛔ AI가 하지 말 것: `cluster_endpoint_public_access=false`로 설정 (외부 CI/CD가 EKS에 닿지 못한다)
- ⛔ AI가 하지 말 것: 노드 인스턴스를 바꾸지 말 것. 무료 플랜은 무료 등급 대상(`c7i-flex.large` 등)만 실행한다
- ⛔ AI가 하지 말 것: `enable_irsa`를 켜지 말 것. 새 가입 방식 계정은 OIDC provider 생성을 SCP로 거부한다
- ⛔ AI가 하지 말 것: main.tf나 variables.tf에 리전을 적지 말 것. 리전은 aws configure 한 곳에서만 정한다
- ⛔ AI가 하지 말 것: `node_security_group_additional_rules`를 빼지 말 것. 모듈 기본 규칙만으로는 노드 사이의 80번이 막힌다
- ⛔ AI가 하지 말 것: NAT Gateway를 AZ마다 두지 말 것 (비용을 줄이려고 하나만 둔다)
- ✅ AI가 해도 됨: Terraform 설치, 파일 작성, 비용 추정, plan 출력 해석
- ⚠️ state 파일은 10.10에서 GitLab으로 옮기기 전까지 노드에만 있다. 그때까지 클러스터(VM)를 다시 만들지 않는다. state가 없으면 트러블슈팅의 순서로 직접 지운다
- ⚠️ **비용**: EKS control plane이 시간당 $0.10이고, 노드 3대와 NAT Gateway, 로드밸런서를 합쳐 대략 시간당 $0.4~0.5다(리전마다 다르다. 시드니는 $0.5쯤). 하루 방치하면 $10~12다
- ⚠️ 무료 플랜은 크레딧($100)에서 빠지고, 크레딧이 떨어지면 청구 대신 계정이 닫힌다. 10장 전체는 크레딧 안에서 끝난다
