# 10.4 Terraform으로 EKS 배포/삭제

> **학습자 진입 방식**:
> - `[학습자 직접]`: Terraform 설치, `terraform init/plan/apply`, `aws eks update-kubeconfig`, **`terraform destroy` (실습 종료 즉시)**
> - `[AI 프롬프트]`: `terraform-test/main.tf` 작성 (연결 검증), `terraform-eks/` 모듈 구성 작성, 비용 추정, 트러블슈팅

## 사전 조건

- ch10.3 완료 (`aws sts get-caller-identity` 정상)
- Terraform 1.0 이상 설치 가능 환경
- IAM User에 EKS/VPC/IAM 관련 정책 부여 완료
- **결제 알림 설정 강력 권장** — 실수로 destroy 누락 시 비용 누적

## 실행 지침

### 단계 1: Terraform 설치 `[학습자 직접]`

```bash
# Ubuntu/Debian
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install terraform -y

# macOS
brew tap hashicorp/tap
brew install hashicorp/tap/terraform

terraform version
```

### 단계 2: 연결 검증용 `terraform-test/` 작성 `[AI 프롬프트]`

> "AWS 자격증명이 정상인지 확인하는 최소 Terraform 프로젝트를 만들어줘.
> - `terraform { required_providers { aws = { source=hashicorp/aws, version=~>5.0 } } }`
> - provider aws region = `<aws_region>`
> - data `aws_caller_identity` current
> - output account_id, caller_arn
> - 비용 발생 리소스 생성 금지 (data source만 사용)"

✅ 정답 파일 (완성 후 비교): `ch10/10.4/terraform-test/main.tf`

### 단계 4: EKS 클러스터용 `terraform-eks/` 작성 `[AI 프롬프트]`

> "AWS EKS 클러스터를 만드는 Terraform 프로젝트를 3개 파일로 나눠서 만들어줘.
>
> **variables.tf**:
> - `region` (default `<aws_region>`)
> - `cluster_name` (default `<eks_cluster_name>`)
> - `tags` map(string) (Environment=learning, Project=cicd-learning-kit)
>
> **main.tf**:
> - `terraform { required_version = >=1.0, aws ~> 5.0 }`
> - module vpc: `terraform-aws-modules/vpc/aws ~> 5.0`
>   - cidr=10.0.0.0/16
>   - 3 AZ (region a/b/c) private(10.0.1~3.0/24) + public(10.0.101~103.0/24)
>   - single NAT gateway, enable_dns_hostnames
>   - public_subnet_tags: `kubernetes.io/role/elb = 1`
>   - private_subnet_tags: `kubernetes.io/role/internal-elb = 1`
> - module eks: `terraform-aws-modules/eks/aws ~> 20.0`
>   - cluster_name, cluster_version=1.36
>   - vpc_id/subnet_ids = private subnets
>   - cluster_endpoint_public_access=true (학습자가 외부 CI/CD에서 접근 가능해야 함)
>   - **enable_cluster_creator_admin_permissions=true** (모듈 v20 기본 false — 없으면 클러스터 생성자도 kubectl 401)
>   - eks_managed_node_groups.default: t3.medium / min=2 / max=4 / desired=3
>
> **outputs.tf**:
> - cluster_endpoint, cluster_name, region"

✅ 정답 파일 (완성 후 비교):
- `ch10/10.4/terraform-eks/main.tf`
- `ch10/10.4/terraform-eks/variables.tf`
- `ch10/10.4/terraform-eks/outputs.tf`

### 단계 5: EKS apply 전 비용 추정 `[AI 프롬프트]`

> "방금 만든 terraform-eks 구성을 ap-northeast-2 리전에서 apply할 때 시간당/일일 예상 비용을 항목별로 추정해줘. EKS control plane, t3.medium × 3 노드, NAT Gateway, EBS 등."

> ⚠️ 학습자가 비용을 정확히 인지한 다음에만 다음 단계로 진행한다.

### 단계 6: EKS 클러스터 생성 `[학습자 직접]`

```bash
cd ~/_Lecture_cicd_learning.kit/ch10/10.4/terraform-eks
terraform init
terraform plan
terraform apply -auto-approve
```

**약 15~20분 소요**. 진행 중에는 종료/중단하지 말 것 (state 꼬임).

### 단계 7: kubectl 컨텍스트 설정 + 클러스터 확인 `[학습자 직접]`

```bash
aws eks update-kubeconfig --region <aws_region> --name <eks_cluster_name>
kubectl get nodes
kubectl cluster-info
```

3개 노드가 `Ready` 상태로 보이면 성공.

### 단계 8: 외부 노출 준비는 10.5에서 진행

앱 외부 노출은 **AWS Load Balancer Controller + ALB Ingress**로 통일한다 (ch10.5에서 설치). 별도의 ingress-nginx 설치는 하지 않는다 — 10.2 개요와 10.5 실습이 모두 ALB Controller 기준이다.

### 단계 9: **실습 종료 후 즉시 EKS 삭제** `[학습자 직접]` ⚠️ 필수

```bash
cd ~/_Lecture_cicd_learning.kit/ch10/10.4/terraform-eks
terraform destroy -auto-approve
```

**약 10~15분 소요**. 삭제 완료 후 AWS Console → EKS / EC2 / VPC / NAT Gateway에서 자원이 모두 사라졌는지 시각적으로도 확인한다.

> ⚠️ destroy 실패 시: ALB/Ingress가 만든 리소스 때문일 수 있다. Service `type=LoadBalancer`를 모두 삭제(`kubectl delete svc`)한 후 다시 destroy.

## 주의사항

- ⛔ AI가 하지 말 것: 학습자 AWS 계정에서 `terraform apply` 자동 실행 — 반드시 학습자 직접
- ⛔ AI가 하지 말 것: `cluster_endpoint_public_access=false`로 설정 (외부 CI/CD에서 EKS 접근 불가)
- ⛔ AI가 하지 말 것: 노드 그룹을 m5.large 이상의 대형 인스턴스로 변경 (학습용은 t3.medium 충분)
- ⛔ AI가 하지 말 것: NAT Gateway를 AZ별 multi로 설정 (학습 비용 절감을 위해 single로 유지)
- ✅ AI가 해도 됨: Terraform 파일 작성 (main.tf, variables.tf, outputs.tf)
- ✅ AI가 해도 됨: 비용 추정 및 항목 분해 설명
- ✅ AI가 해도 됨: VPC/Subnet 태그 (`kubernetes.io/role/elb`, `internal-elb`)가 ALB Ingress Controller에 왜 필요한지 설명
- ⚠️ **비용 주의 (매우 중요)**:
  - EKS Control Plane: 시간당 $0.10
  - t3.medium 노드 × 3: 시간당 약 $0.12
  - NAT Gateway: 시간당 약 $0.05 + 데이터 처리 비용
  - **합산 약 시간당 $0.27 → 하루 방치 시 약 $6.5 → 한 달 방치 시 약 $200**
- ⚠️ **실습 직후 `terraform destroy` 필수**. 강의 영상 중간에 destroy 가이드 빠뜨리지 말 것
- ⚠️ destroy 시 ALB/NLB가 만든 리소스 때문에 실패할 수 있음 → `kubectl delete svc --all-namespaces -l ...` 또는 LoadBalancer 타입 Service 수동 삭제 후 재시도
- ⚠️ **검증 영역**: **실배포 검증 완료(2026-07-03)** — EKS 1.36 생성, 노드 3대 Ready(v1.36.2-eks), apply/destroy 각 60 리소스. 학습자 계정에서의 apply는 본인 비용·계정 책임.
- ⛔ **`cluster_version`은 지원 버전으로 유지** — EKS는 구버전(예: 1.29) 생성 불가. 실배포 검증 기준 **1.36** 사용(`aws eks describe-cluster-versions`로 지원 버전 확인). 모듈 `~> 20.0`은 provider `< 6.0`을 유지해 v21/provider6 연쇄를 피함

## 검증 발견 (실배포, 2026-07-03)

- ⛔ `cluster_version=1.29`는 **EKS 생성 불가** (`aws eks describe-cluster-versions`로 확인) → **1.36** 사용.
- ⛔ **`enable_cluster_creator_admin_permissions = true` 필수.** 모듈 v20 기본값이 false라, 없으면 클러스터 생성자조차 `kubectl get nodes`에서 401(`You must be logged in to the server`).
- 모듈은 `~> 20.0` 유지 (v21은 provider `>= 6.0` 강제 + node group count 버그로 회피). 상세: 아래 주의사항 참조.
- destroy 후 KMS 키(클러스터 암호화용)가 `PendingDeletion`으로 7일+ 남는 것은 정상이며 과금 없음.
