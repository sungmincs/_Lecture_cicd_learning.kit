# 10.4 Terraform으로 EKS 배포/삭제

> **학습자 진입 방식**:
> - `[학습자 직접]`: `terraform init/plan/apply`, kubectl context 정리, 클러스터 확인
> - `[AI 프롬프트]`: Terraform 설치, 연결 검증용 `terraform-test/`와 EKS용 `terraform-eks/` 작성, 비용 추정
>
> Terraform 파일은 강의 저장소가 아니라 노드의 `/root/ch10/`에 만든다. state 파일도 거기에 생긴다.
> 10.10에서 이 폴더를 통째로 GitLab 프로젝트로 옮긴다.

## 사전 조건

- ch10.3 완료 (노드에서 `aws sts get-caller-identity`가 `cicd-learning-user`를 보여 줌)
- 결제 알림을 걸어 두기를 강하게 권한다. destroy를 빠뜨리면 비용이 쌓인다

## 실행 지침

### 단계 1: Terraform 설치 `[AI 프롬프트]`

> "컨트롤 플레인 노드에 Terraform 1.15.7을 설치해줘.
> - HashiCorp 공식 apt 저장소를 등록하고 `terraform=1.15.7-1`처럼 버전을 지정해 설치
> - 끝나면 `terraform version` 결과를 보여주고 `/root/ch10` 폴더를 만들어줘"

### 단계 2: 연결 검증용 `terraform-test/` 작성 `[AI 프롬프트]`

> "AWS 자격 증명이 정상인지 확인하는 최소 Terraform 프로젝트를 컨트롤 플레인 노드의 `/root/ch10/terraform-test/main.tf`에 만들어줘. 실행은 내가 할게.
> - `required_providers`의 aws는 `hashicorp/aws`, `~> 5.0`
> - provider aws에는 리전을 적지 마. `aws configure`의 리전을 그대로 쓴다
> - data `aws_caller_identity` current
> - output account_id, caller_arn
> - 비용이 드는 리소스는 만들지 마 (data source만)"

✅ 정답 파일 (완성 후 비교): `ch10/10.4/terraform-test/main.tf`

### 단계 3: `terraform-test/` 실행 `[학습자 직접]`

```bash
cd /root/ch10/terraform-test
terraform init
terraform apply -auto-approve
```

`account_id`와 `caller_arn`이 출력되면 Terraform이 AWS에 닿는 것이다. data source만 읽으므로 비용이 없다. 확인했으면 폴더를 지운다.

```bash
cd /root/ch10 && rm -rf /root/ch10/terraform-test
```

### 단계 4: EKS 클러스터용 `terraform-eks/` 작성 `[AI 프롬프트]`

> "AWS EKS 클러스터를 만드는 Terraform 프로젝트를 컨트롤 플레인 노드의 `/root/ch10/terraform-eks/`에 3개 파일로 나눠서 만들어줘. init과 apply는 내가 할게.
>
> **variables.tf**:
> - `region` (default `null`. 비워 두면 aws configure의 리전을 쓴다. 리전은 10.3 단계 5 한 곳에서만 정한다)
> - `cluster_name` (default `cicd-learning-eks`)
> - `tags` map(string) (Environment=learning, Project=cicd-learning-kit)
>
> **main.tf**:
> - `terraform { required_version = >=1.0, aws ~> 5.0 }`
> - module vpc: `terraform-aws-modules/vpc/aws ~> 5.0`
>   - cidr=10.0.0.0/16
>   - 3 AZ (`data.aws_availability_zones`에서 앞 3개) private(10.0.1~3.0/24) + public(10.0.101~103.0/24)
>   - single NAT gateway, enable_dns_hostnames
>   - public_subnet_tags: `kubernetes.io/role/elb = 1`
>   - private_subnet_tags: `kubernetes.io/role/internal-elb = 1`
> - module eks: `terraform-aws-modules/eks/aws ~> 20.0`
>   - cluster_name, cluster_version=1.36
>   - vpc_id/subnet_ids = private subnets
>   - cluster_endpoint_public_access=true (외부 CI/CD가 접근해야 한다)
>   - **enable_cluster_creator_admin_permissions=true** (모듈 v20 기본 false. 없으면 만든 사람도 kubectl이 401)
>   - **enable_irsa=false**, cluster_addons에 **eks-pod-identity-agent** (IRSA 대신 Pod Identity. 10.5에서 쓴다)
>   - **node_security_group_additional_rules**에 노드끼리 모든 포트를 여는 규칙 하나(`ingress_self_all`: protocol `-1`, from_port 0, to_port 0, type ingress, self true). 모듈 기본값은 노드 사이에 1025 이상 포트만 연다. backend가 80번이라 없으면 다른 노드의 frontend가 backend를 부르지 못한다
>   - eks_managed_node_groups.default: **c7i-flex.large** / min=2 / max=4 / desired=3
>
> **outputs.tf**:
> - cluster_endpoint, cluster_name, region(`data.aws_region.current.name`), vpc_id"

✅ 정답 파일 (완성 후 비교):
- `ch10/10.4/terraform-eks/main.tf`
- `ch10/10.4/terraform-eks/variables.tf`
- `ch10/10.4/terraform-eks/outputs.tf`

### 단계 5: apply 전 비용 추정 `[AI 프롬프트]`

> "`/root/ch10/terraform-eks` 구성을 내 리전(`aws configure get region`)에서 apply할 때 시간당, 하루 예상 비용을 항목별로 추정해줘. EKS control plane, c7i-flex.large 노드 3대, NAT Gateway, EBS 등. 무료 플랜이면 크레딧에서 얼마나 빠지는지도."

비용을 알고 나서 다음 단계로 간다.

### 단계 6: EKS 클러스터 생성 `[학습자 직접]`

```bash
cd /root/ch10/terraform-eks
terraform init
terraform plan | grep "Plan:"     # Plan: 61 to add, 0 to change, 0 to destroy. 만들 것만 있어야 한다
terraform apply -auto-approve
```

15~20분 걸린다. 도중에 끊지 않는다(state가 꼬인다). ssh가 끊길 것이 걱정되면 `tmux` 안에서 실행한다.

### 단계 7: kubectl context 정리와 클러스터 확인 `[학습자 직접]`

클러스터가 둘이 됐다. 이름을 짧게 정해 둔다.

```bash
kubectl config rename-context kubernetes-admin@kubernetes local      # 지금까지 쓴 로컬 클러스터
aws eks update-kubeconfig --name cicd-learning-eks --alias eks       # EKS를 추가하고 기본 context로 삼는다
kubectl config get-contexts                                          # * eks, local
kubectl get nodes                                                    # EKS 노드 3대 Ready
kubectl --context local get nodes                                    # 로컬 노드 4대
```

이제부터 `kubectl`은 EKS를 본다. 로컬 클러스터를 볼 때는 `--context local`을 붙인다. 앱의 외부 노출(ALB)은 10.5에서 한다.

### 단계 8: state 파일 확인 `[학습자 직접]`

```bash
ls -l /root/ch10/terraform-eks/terraform.tfstate
```

EKS는 지우지 않고 10.10까지 이어 간다. 삭제는 10.10의 마지막 단계에서 GitLab 파이프라인으로 한다.
이 `terraform.tfstate`를 지우거나 폴더를 정리하지 않는다. 이 파일을 잃으면 `terraform destroy`를 할 수 없어 EKS 비용이 계속 나간다.
노드는 VM이다. 10.10을 마칠 때까지 `vagrant destroy`나 `vagrant up --provision`으로 클러스터를 다시 만들지 않는다. 다시 만들면 이 파일도 같이 사라진다.

## 트러블슈팅

### 10장을 중간에 멈춰야 할 때

EKS를 켠 채로 두면 비용이 계속 나간다. 먼저 10.10 단계 8처럼 Argo CD Application, Ingress, LoadBalancer Service를 지워 로드밸런서를 회수한 뒤 지운다.

```bash
cd /root/ch10/terraform-eks
terraform destroy -auto-approve
```

10~15분 걸린다. 끝나면 AWS 콘솔의 EKS, EC2, VPC, NAT Gateway가 비었는지 본다. 10.5에서 만든 IAM 정책과 역할은 10.10 단계 10의 명령으로 지운다.

### state 파일을 잃었다 (노드를 다시 만들었거나 폴더를 지웠다)

Terraform으로는 지울 수 없다. AWS에 남은 것을 순서대로 직접 지운다. 노드를 다시 만들었다면 10.3부터 다시 해서 `aws`를 쓸 수 있게 한 뒤 진행한다.
순서가 중요하다. 로드밸런서와 NAT Gateway가 남아 있으면 VPC가 지워지지 않는다.

```bash
aws eks list-nodegroups --cluster-name cicd-learning-eks --query 'nodegroups' --output text    # 노드 그룹 이름 확인
aws eks delete-nodegroup --cluster-name cicd-learning-eks --nodegroup-name <nodegroup_name>
aws eks wait nodegroup-deleted --cluster-name cicd-learning-eks --nodegroup-name <nodegroup_name>
aws eks delete-cluster --name cicd-learning-eks
aws eks wait cluster-deleted --name cicd-learning-eks
```

그다음은 AWS 콘솔에서 지운다. EC2의 Load Balancers와 Target Groups, VPC의 NAT Gateways, Elastic IPs, 마지막으로 이름이 `cicd-learning-eks`로 시작하는 VPC다.
VPC를 지우면 서브넷과 라우팅 테이블, 보안 그룹이 같이 지워진다. 끝나면 Billing 화면에서 다음 날 비용이 0인지 확인한다.
과금이 큰 것은 EKS 클러스터, EC2 인스턴스, NAT Gateway, 로드밸런서 넷이다. 이 넷이 없으면 남은 것은 비용이 거의 없다.

### 10.5에서 앱 화면은 열리는데 할 일 목록이 뜨지 않거나 `504`가 섞여 나온다

노드 보안 그룹이 노드 사이의 80번 포트를 막고 있다. frontend Pod와 backend Pod가 같은 노드에 있을 때만 통한다.
`main.tf`의 module eks에 `node_security_group_additional_rules`의 `ingress_self_all`이 있는지 확인한다(단계 4의 프롬프트). 없으면 넣고 다시 apply한다. 규칙 하나만 더해지고 클러스터는 그대로다.

```bash
cd /root/ch10/terraform-eks
terraform apply -auto-approve          # Plan: 1 to add
```

### 노드 그룹이 `CREATING`에서 끝나지 않는다

무료 플랜은 무료 등급 대상이 아닌 인스턴스(t3.medium 등)를 거부한다. Terraform은 오류 없이 기다리기만 하고,
원인은 EC2 Auto Scaling 그룹의 활동 기록에만 남는다(`The specified instance type is not eligible for Free Tier`).
`c7i-flex.large`인지 확인한다.

### destroy가 VPC에서 `DependencyViolation`으로 실패한다

클러스터 안에서 만든 ALB나 NLB가 남아 있다. LoadBalancer Service와 Ingress를 `kubectl delete`로 지운 뒤 다시 한다(10.10 단계 8).

## 주의사항

- ⛔ AI가 하지 말 것: `terraform apply`나 `terraform destroy`를 대신 실행하지 말 것. 비용이 드는 일은 학습자가 직접 한다
- ⛔ AI가 하지 말 것: Terraform 파일을 강의 저장소나 fork 저장소 안에 만들지 말 것. `/root/ch10/`에 둔다
- ⛔ AI가 하지 말 것: `cluster_endpoint_public_access=false`로 설정 (외부 CI/CD가 EKS에 닿지 못한다)
- ⛔ AI가 하지 말 것: 노드 인스턴스를 바꾸지 말 것. 무료 플랜은 무료 등급 대상(`c7i-flex.large` 등)만 실행한다
- ⛔ AI가 하지 말 것: `enable_irsa`를 켜지 말 것. 새 가입 방식 계정은 OIDC provider 생성을 SCP로 거부한다
- ⛔ AI가 하지 말 것: main.tf나 variables.tf에 리전을 적지 말 것. 리전은 aws configure 한 곳에서만 정한다
- ⛔ AI가 하지 말 것: `node_security_group_additional_rules`를 빼지 말 것. 모듈 기본 규칙만으로는 노드 사이의 80번이 막힌다
- ⛔ AI가 하지 말 것: NAT Gateway를 AZ마다 두지 말 것 (비용을 줄이려고 하나만 둔다)
- ✅ AI가 해도 됨: Terraform 설치, 파일 작성, 비용 추정, plan 출력 해석
- ⚠️ state 파일은 10.10에서 GitLab으로 옮기기 전까지 노드에만 있다. 그때까지 클러스터(VM)를 다시 만들지 않는다. 잃었으면 트러블슈팅의 순서로 직접 지운다
- ⚠️ **비용**: EKS control plane이 시간당 $0.10이고, 노드 3대와 NAT Gateway, 로드밸런서를 합쳐 대략 시간당 $0.4~0.5다(리전마다 다르다. 시드니는 $0.5쯤). 하루 방치하면 $10~12다
- ⚠️ 무료 플랜은 크레딧($100)에서 빠지고, 크레딧이 떨어지면 청구 대신 계정이 닫힌다. 10장 전체는 크레딧 안에서 끝난다
- ⚠️ `cluster_version`은 EKS가 지원하는 버전이어야 한다(`aws eks describe-cluster-versions`). 검증 기준은 1.36이다. 모듈 `~> 20.0`은 provider를 6 미만으로 묶어 v21과의 연쇄를 피한다
- ⚠️ destroy 뒤 KMS 키가 `PendingDeletion`으로 7일쯤 남는 것은 정상이고 과금이 없다
