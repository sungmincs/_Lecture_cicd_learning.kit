## 실행 지침

### 단계 1: 기본 3단계 파이프라인 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/workspace/worklog-backend/Jenkinsfile`을 test → build → deploy 3단계 Jenkins 파이프라인으로 바꿔줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.6/Jenkinsfiles/1.hello-pipeline.groovy`

### 단계 2: git push `[학습자 직접]`

```bash

```

### 단계 2-1: 스캔과 빌드 확인 `[학습자 직접 · 웹]`

Jenkins의 `worklog-backend` job에서 'Scan Multibranch Pipeline Now'로 빌드를 시작하고, 빌드 번호의 Console Output에서 stage 순서와 결과를 확인한다.

### 단계 3: 빌드 실패 + Post-build 처리 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/workspace/worklog-backend/Jenkinsfile`에서 Build stage가 일부러 실패하게 하고, 빌드가 끝나면 성공과 실패에 따라 알림을 보내는 post 블록을 넣어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.6/Jenkinsfiles/2.hello-pipeline_build-failure.groovy`

### 단계 4: Stage 간 변수 전달 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/workspace/worklog-backend/Jenkinsfile`을 앞 Stage에서 만든 변수를 뒤 Stage에서 쓰는 파이프라인으로 바꿔줘. Build 실패는 되돌려줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.6/Jenkinsfiles/3.hello-pipeline_build-pass-variables.groovy`

### 단계 5: 재사용 함수 패턴 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/workspace/worklog-backend/Jenkinsfile`의 알림 부분을 함수로 만들어 재사용하는 패턴으로 바꿔줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.6/Jenkinsfiles/4.hello-pipeline_build-pass-variables-function.groovy`

### 단계 6: 시나리오마다 git push `[학습자 직접]`

단계 3, 4, 5를 하나 끝낼 때마다 push한다. 세 번 한다.

```bash
cd /root/workspace/worklog-backend
git add Jenkinsfile
git commit -m "test: jenkins pipeline scenario"

```

### 단계 6-1: 스캔과 시나리오 결과 확인 `[학습자 직접 · 웹]`

push할 때마다 'Scan Multibranch Pipeline Now'로 빌드를 시작하고, 빌드 번호의 Console Output에서 stage 순서와 결과를 확인한다.

| 단계 | 기대 결과 |
|---|---|
| 3 | Build stage 실패, 뒤 stage 건너뜀, post의 failure 블록 실행 |
| 4 | 모두 성공, 뒤 stage 로그에 앞 stage가 넘긴 값이 찍힘 |
