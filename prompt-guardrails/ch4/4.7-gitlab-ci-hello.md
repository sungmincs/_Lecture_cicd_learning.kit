# 4.7 GitLab CI/CD 첫 파이프라인 (Hello World)

> **학습자 진입 방식**:
> - `[학습자 직접]`: GitLab 가입, fork, SSH 키 등록, git push
> - `[AI 프롬프트]`: `.gitlab-ci.yml` 파일 작성

## 사전 조건

- GitLab.com 계정 (이 챕터 Step 1에서 생성 가능)
- worklog-backend 저장소를 GitLab으로 fork

## 실행 지침

### 단계 1: GitLab.com 가입 `[학습자 직접]`

> ⚠️ **강의자 필수 안내**: GitLab.com 새 계정은 shared runner(CI 실행 환경) 사용 전 **전화번호 인증 필수**. 가입 직후 파이프라인 실행 시 "계정을 인증해야 합니다" 메시지가 나타남. 파이프라인 실패 화면에서 인증 버튼 클릭 → 전화번호 입력. 실제 과금 없음.

- https://gitlab.com 접속 → 계정 생성

### 단계 2: 저장소 fork `[학습자 직접]`

- `sungmincs/worklog-backend` → GitLab으로 fork

### 단계 3: SSH 키 생성 및 등록 `[AI 프롬프트]`

> "GitLab SSH 키 생성하고 등록하는 방법 알려줘."

### 단계 4: git clone (SSH) `[학습자 직접]`

```bash
git clone git@gitlab.com:<gitlab_username>/worklog-backend.git
```

### 단계 5: Hello World .gitlab-ci.yml 작성 `[AI 프롬프트]`

> "Hello World GitLab CI 파이프라인 만들어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.7/1.hello-gitlab.yml`

### 단계 6: git push + CI 확인 `[학습자 직접]`

```bash
git add .gitlab-ci.yml
git commit -m "add: hello gitlab ci"
git push
```

GitLab 웹 → CI/CD → Pipelines에서 실행 확인.

### 단계 7: Variables 워크플로우 `[AI 프롬프트]`

> "GitLab CI 변수($CI_*, 사용자 정의 변수) 쓰는 파이프라인 만들어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.7/2.hello-gitlab-variables.yml`

## 주의사항

- ⛔ AI가 하지 말 것: git push 대신 실행하지 말 것
- ⛔ AI가 하지 말 것: GitLab UI 조작 대신하지 말 것
- ✅ AI가 해도 됨: `.gitlab-ci.yml` 작성
- ✅ AI가 해도 됨: SSH 키 생성 명령 안내 (`ssh-keygen`)
- ✅ AI가 해도 됨: GitLab CI/CD 파이프라인 결과 해석
- ⛔ AI가 하지 말아야 할 것: ssh-keygen의 파일 경로를 기본값이 아닌 값으로 변경하지 말 것 — SSH config 설정이 복잡해짐
