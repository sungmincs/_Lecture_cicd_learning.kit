### 단계 0: GitHub 워크플로 끄기 `[학습자 직접]`

4.3과 4.4에서 만든 워크플로 세 개를 끈다. 켜 두면 Jenkinsfile을 push할 때마다 GitHub Actions도 함께 돌고, 4.4의 파이프라인은 실패 예시로 끝나 있어 실패가 쌓인다.
규칙은 `prompt-guardrails/shared/one-pipeline.md`.

```bash

gh workflow disable hello-actions.yaml -R <github_username>/worklog-backend
gh workflow disable hello-actions-variables.yaml -R <github_username>/worklog-backend
gh workflow disable hello-pipeline.yaml -R <github_username>/worklog-backend
gh workflow list --all -R <github_username>/worklog-backend      # 셋 다 disabled_manually
```

웹에서 하려면 저장소 → Actions → 워크플로 이름 → 오른쪽 위 ⋯ → Disable workflow.

### 단계 4: Jenkins용 SSH 키 쌍 만들기 `[학습자 직접]`

Jenkins가 GitHub 저장소를 읽을 때 쓸 키다. 자격 증명이므로 직접 만든다.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/jenkins_github -N ""
cat ~/.ssh/jenkins_github.pub      # 공개 키. 단계 4-1에서 GitHub에 넣는다
cat ~/.ssh/jenkins_github          # 개인 키. 단계 4-2에서 Jenkins에 넣는다. AI 대화창에 붙여 넣지 않는다
```

### 단계 4-1: GitHub에 Deploy key 등록 `[학습자 직접 · 웹]`

GitHub fork 저장소(`<github_username>/worklog-backend`) → Settings → Deploy keys → Add deploy key.
Key에 `jenkins_github.pub` 내용을 넣는다. Allow write access는 끈다(읽기만 하면 된다).

### 단계 4-2: Jenkins에 Credential 등록 `[학습자 직접 · 웹]`

Jenkins 관리 → Credentials → System → Global credentials → Add Credentials.
Kind `SSH Username with private key`, ID `github-ssh`, Username `git`, Private Key는 Enter directly를 골라 `jenkins_github` 내용을 넣는다.

### 단계 5: Multibranch Pipeline 생성 `[학습자 직접 · 웹]`

새로운 Item → 이름(예: `worklog-backend`) → Multibranch Pipeline → Branch Sources → Add source → **Git**. Project Repository는 `git@github.com:<github_username>/worklog-backend.git`(SSH 형식. 4.3과 같은 fork), Credentials는 단계 4의 `github-ssh`. Build Configuration은 by Jenkinsfile.

설치된 플러그인에는 GitHub Branch Source가 없어서 Add source에서 "GitHub"는 나오지 않는다. "Git"을 고른다.

## 트러블슈팅

### Multibranch 스캔이 호스트 키 검증에서 실패한다

- 증상: 스캔 로그에 `No ED25519 host key is known for github.com and you have requested strict checking. Host key verification failed.`가 찍히고 브랜치를 찾지 못한다.
- 원인: Git 호스트 키 검증이 Known hosts file인데 컨트롤러의 known_hosts가 비어 있다.
- 지금 JCasC(`jenkins-config.yaml`)는 Accept first connection으로 설치한다(2026-10-08 수정, run-38 판단13). 이 오류가 나면 옛 JCasC로 설치된 것이다.
- 해결: Manage Jenkins → Security → Git Host Key Verification Configuration → Accept first connection으로 바꾸고 저장한 뒤 'Scan Multibranch Pipeline Now'를 다시 누른다.

## 검증 중 발견된 이슈 (강의자 참고)

- **Jenkinsfile `agent any` 사용**: `agent any`는 빈 실행기 아무 곳에서나 돈다. 이 설치에서는 컨트롤러 실행기 2개(`numExecutors: 2`)와 JCasC로 미리 구성된 쿠버네티스 Pod 에이전트가 모두 후보라, 빌드마다 위치가 다를 수 있다(run-38에서 실제로 섞였다). ch4는 echo만 하므로 결과는 같다. 쿠버네티스 Pod 에이전트를 명시하는 `agent { label 'jenkins-jenkins-agent' }`는 ch5.5부터 쓴다.
- **에이전트 이미지의 소스**: `jenkins-config.yaml`이 쓰는 `sungminl/inbound-agent-docker`는 같은 폴더의 `Dockerfile.agent`로 만든 이미지다(docker CLI를 넣은 inbound-agent). 학습자가 빌드하지 않는다.
- **`numExecutors: 0` 주의**: `jenkins-config.yaml` 기본값이 0이면 빌드 대기 상태 지속. 현재 `numExecutors: 2`로 설정됨.
- **JCasC deprecated 설정**: `agentProtocols`, `myViewsTabBar`, `viewsTabBar`가 Jenkins 2.541.3에서 제거됨. 있으면 Jenkins 시작 불가.
