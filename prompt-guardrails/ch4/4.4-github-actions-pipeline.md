# 4.4 GitHub Actions 빌드 파이프라인 구조 만들기

> **학습자 진입 방식**:
> - `[학습자 직접]`: git push, GitHub UI 확인
> - `[AI 프롬프트]`: 파이프라인 yaml 작성/수정

## 사전 조건

- ch4.3 완료 (`.github/workflows/` 존재, 첫 워크플로우 실행 경험)

## 실행 지침

### 단계 1: 기본 3단계 파이프라인 `[AI 프롬프트]`

> "test → build → deploy 3단계 GitHub Actions 파이프라인 만들어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.4/1.hello-pipeline.yaml`

### 단계 2: git push + 확인 `[학습자 직접]`

```bash
git add .github/workflows/
git commit -m "add: build pipeline"
git push
```

Actions 탭에서 Job 실행 순서(test → build → deploy) 확인.

### 단계 3: 빌드 실패 시나리오 `[AI 프롬프트]`

> "빌드가 실패했을 때 notify job이 실행되는 파이프라인으로 수정해줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.4/2.hello-pipeline_build-failure.yaml`

### 단계 4: Job 간 변수 전달 `[AI 프롬프트]`

> "앞 Job의 output을 다음 Job에서 사용하는 파이프라인 만들어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.4/3.hello-pipeline_build-pass-variables.yaml`

### 단계 5: 변수 전달 + 실패 시나리오 `[AI 프롬프트]`

✅ 정답 파일 (완성 후 비교): `ch4/4.4/4.hello-pipeline_build-pass-variables-failure.yaml`

### 단계 6: git push + 각 시나리오 확인 `[학습자 직접]`

## 주의사항

- ⛔ AI가 하지 말 것: git push 대신 실행하지 말 것
- ✅ AI가 해도 됨: 파이프라인 yaml 작성 및 수정
- ✅ AI가 해도 됨: Job 실행 결과 및 의존성 관계 설명
- ✅ AI가 해도 됨: `needs`, `outputs`, `if` 키워드 설명
- ⛔ AI가 하지 말아야 할 것: 4개의 yaml 파일을 한 번에 모두 제공하지 말 것 — 단계별로 하나씩 진행
- ⛔ AI가 하지 말아야 할 것: Step 2의 의도적 실패를 "수정"해주지 말 것 — 실패를 관찰하는 것이 학습 목표
