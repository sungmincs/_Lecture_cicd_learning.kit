# 4.3 GitHub Actions 첫 파이프라인 (Hello World)

> **학습자 진입 방식**:
> - `[학습자 직접]`: git push
> - `[학습자 직접 · 웹]`: GitHub Actions 탭에서 실행 확인
> - `[AI 프롬프트]`: 디렉터리 생성, 워크플로 yaml 작성
>
> 작업 위치는 컨트롤 플레인 노드의 `/root/workspace/worklog-backend`다. AI도 이 폴더에 파일을 만든다.

## 사전 조건

- GitHub 계정 보유
- worklog-backend 저장소가 본인 계정에 fork되어 있고 컨트롤 플레인 노드의 `/root/workspace/worklog-backend`에 clone되어 있음(3.3 단계 3). ch4~ch9의 GitHub Actions와 Jenkins는 이 저장소에서 이어진다
- ch2.13 완료(노드에서 `gh auth status`가 로그인 상태, git 작성자 설정)

## 실행 지침

### 단계 1: 워크플로우 디렉토리 생성 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/workspace/worklog-backend`에 GitHub Actions 워크플로우 디렉토리 만들어줘."

AI가 `.github/workflows/` 디렉토리를 생성합니다.

### 단계 2: Hello World 워크플로우 작성 `[AI 프롬프트]`

> "Hello World GitHub Actions 워크플로우를 컨트롤 플레인 노드의 `/root/workspace/worklog-backend/.github/workflows/hello-actions.yaml`로 만들어줘. 만든 뒤 각 줄이 무엇을 하는지 설명해줘."

AI가 파일을 만들고 `name`, `on`, `jobs`가 각각 무엇인지 설명합니다.

✅ 정답 파일 (완성 후 비교): `ch4/4.3/1.hello-actions_basic.yaml`

### 단계 3: git push `[학습자 직접]`

```bash
cd /root/workspace/worklog-backend
git add .github/
git commit -m "add: hello world workflow"
git push
```

`git push`가 인증을 물으면 2.13 단계 3(`gh auth login`)이 안 된 것이다.

### 단계 4: GitHub Actions UI에서 실행 확인 `[학습자 직접 · 웹]`

- GitHub 웹 → 저장소 → Actions 탭
- 워크플로우 실행 결과 확인

### 단계 5: Variables 워크플로우 `[AI 프롬프트]`

> "GitHub Context와 Variables를 쓰는 워크플로우도 컨트롤 플레인 노드의 `/root/workspace/worklog-backend/.github/workflows/hello-actions-variables.yaml`로 만들어줘."

✅ 정답 파일 (완성 후 비교): `ch4/4.3/2.hello-actions_variables.yaml`

### 단계 6: git push `[학습자 직접]`

```bash
cd /root/workspace/worklog-backend
git add .github/
git commit -m "add: hello variables workflow"
git push
```

### 단계 7: 두 워크플로 실행 확인 `[학습자 직접 · 웹]`

- GitHub 웹 → 저장소 → Actions 탭
- 이번 push로 워크플로 두 개가 함께 실행된다. 각 실행의 로그에서 context 값과 변수가 찍힌 것을 확인한다.

## 주의사항

- ⛔ AI가 하지 말 것: git push를 대신 실행하지 말 것 — 학습자가 직접 push해야 Actions가 트리거됨을 체감
- ⛔ AI가 하지 말 것: GitHub UI 조작을 대신하지 말 것
- ✅ AI가 해도 됨: `.github/workflows/` 디렉토리 생성 및 yaml 파일 작성
- ✅ AI가 해도 됨: 워크플로우 실행 결과 해석 및 에러 설명
- ⛔ AI가 하지 말 것: 파일만 만들고 끝내지 말 것 — 만든 뒤 `name`, `on`, `jobs`, `steps`가 무엇인지 줄 단위로 설명한다
- ⛔ AI가 하지 말 것: 단계 2를 건너뛰고 바로 상세 버전(단계 5)으로 가지 말 것 — 기본 Hello World를 먼저 경험해야 함
- ⛔ AI가 하지 말 것: 호스트의 강의 저장소 폴더에 `.github/`를 만들지 말 것 — 노드의 `/root/workspace/worklog-backend`에 만든다

## 검증 중 발견된 사항 (강의자 참고)

- **Node.js 20 deprecation 경고**: `actions/checkout@v4`는 Node.js 20용이라 Actions 로그 ANNOTATIONS에 다음 경고가 뜬다(2026-10-07 확인).
  ```
  Node.js 20 is deprecated. The following actions target Node.js 20 but are being forced to run on Node.js 24: actions/checkout@v4.
  ```
  이미 Node.js 24로 강제 실행 중이며 동작에는 영향이 없다. 같은 자리에 `The ubuntu-latest label will migrate to Ubuntu 26 beginning October 19, 2026.` 공지도 뜬다.
