# 3.2 컨테이너화와 쿠버네티스 배포 개요 (worklog 앱 소개)

> **학습자 진입 방식**: 개념 섹션 — 실습 없음. 이 장에서 다룰 worklog 앱과 "로컬 실행 → 컨테이너화 → K8s 배포" 흐름을 이해한 뒤 3.3으로 진행.

## 이 장의 목적

ch2에서 쿠버네티스 클러스터를 준비했다. ch3은 그 위에 **실제 애플리케이션(worklog)을 올리는 전 과정**을 손으로 직접 밟는다 — 로컬에서 실행해보고, Docker 이미지로 컨테이너화하고, 쿠버네티스에 배포한다. 이 장은 CI/CD 자동화 이전에 **"사람이 수동으로 하면 무엇을 어떻게 해야 하는지"** 를 체득하는 단계다. 그 불편함이 ch4 이후 CI/CD를 배우는 동기가 된다.

## 실습 앱: Worklog

worklog는 업무 기록을 남기는 간단한 웹 앱으로, **3개 구성요소**로 이뤄진 마이크로서비스다.

| 구성 | 역할 | 스택 |
|---|---|---|
| **frontend** | 화면(UI) | Node 24 + Vite (mock 버전 사용) |
| **backend** | API 서버 | Python 3.14 + uv |
| **MongoDB** | 데이터 저장 | mongo 8.0 |

> ch3에서는 주로 frontend(mock)와 backend를 다루며, 컨테이너화·배포의 기본기를 익힌다. 전체 스택(3개 동시 배포)은 ch7에서 다룬다.

## 이 장의 흐름: 로컬 → 컨테이너 → 클러스터

배포를 한 번에 하지 않고, **단계를 밟으며 각 단계가 왜 필요한지** 를 이해한다.

| 단계 | 무엇을 | 왜 |
|---|---|---|
| **로컬 실행** (3.3) | Docker 없이 직접 실행 | 앱이 어떻게 동작하는지 먼저 파악 |
| **Dockerfile 이해** (3.4) | 멀티스테이지 빌드·레이어 캐시 구조 파악 | 빌드 전에 "왜 이렇게 생겼는지" 이해 |
| **컨테이너화** (3.5) | 이미지 빌드 → Docker Hub push | "내 PC에서만 됨"을 없애고 어디서나 같은 환경 |
| **K8s 배포** (3.6) | 매니페스트로 클러스터에 배포 | 여러 노드에서 안정적으로 운영 |
| **재배포·진단** (3.8~3.9) | 이미지 업데이트, 트러블슈팅 | 운영 중 변경과 문제 해결 체험 |

> 핵심 메시지: 3장을 마치면 "코드를 고치면 → 빌드 → push → 배포"라는 흐름을 **수동으로** 할 수 있게 된다. 매번 이 과정을 손으로 하는 불편함이, ch4부터 배우는 CI/CD 자동화의 출발점이다.
