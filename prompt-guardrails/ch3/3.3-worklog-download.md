# 3.3 Worklog 앱 다운로드 및 로컬 실행 (Docker 없이)

## 사전 조건

- ch2 환경 구성 완료 (Vagrant + VirtualBox 기반 K8s 클러스터 가동 중)
  - control plane 노드 hostname: `cp-k8s`
  - control plane 노드 IP: `192.168.1.10`
  - control plane에 `/root/_Lecture_cicd_learning.kit`이 자동 clone되어 있음 (`controlplane_node.sh`에서 수행)
- GitHub 계정 보유

## 실행 지침

### 단계 1: control plane 노드에 root로 접속

호스트 머신 터미널에서:

```bash
ssh root@192.168.1.10
# 비밀번호: vagrant
```

> 💡 **호스트 vs control plane**: 본 챕터의 모든 명령은 control plane 노드(`cp-k8s`) **안에서 root 사용자로** 실행합니다. 호스트 머신이 아닙니다. AI가 명령 안내를 할 때도 "현재 어느 머신에서 실행 중인가"를 먼저 확인하세요.

### 단계 2: Node.js 24 + Yarn 설치

```bash
# Node.js 24 (NodeSource)
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt-get install -y nodejs

# Yarn (npm 통해 전역 설치)
npm install -g yarn

# 확인
node --version    # v24.x.x
yarn --version
```

### 단계 3: GitHub에서 worklog-frontend-mock fork

- https://github.com/sungmincs/worklog-frontend-mock 접속
- 우측 상단 **Fork** 클릭 → 학습자 계정에 복사

기대 결과: `<github_username>/worklog-frontend-mock`이 학습자 GitHub 계정에 생성됨.

### 단계 4: control plane 노드에서 clone

```bash
mkdir -p /root/workspace
cd /root/workspace
git clone https://github.com/<github_username>/worklog-frontend-mock.git
cd worklog-frontend-mock
```

### 단계 5: 의존성 설치

```bash
yarn install
```

> 💡 **첫 install은 1~2분 소요**됩니다. 본 프로젝트는 Yarn Berry(PnP) 형태라 `.yarn/` 디렉터리에 캐시가 생성됩니다.

### 단계 6: dev server 실행

```bash
yarn dev --host 0.0.0.0
```

기대 출력:

```
  VITE v5.x  ready in 1234 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.1.10:5173/
  ➜  press h + enter to show help
```

> ⚠️ **`--host 0.0.0.0` 누락 시 호스트에서 접속 불가**: 옵션 없이 `yarn dev`만 실행하면 dev server가 `127.0.0.1:5173`에만 바인드되어 호스트 머신 브라우저에서 접속할 수 없습니다.

> 💡 **여러 Network URL 중 192.168.1.10**: Vite가 여러 인터페이스(eth0, eth1, cni 등)를 보여줄 수 있습니다. 호스트와 통신하는 것은 `192.168.1.10` (private network). 다른 IP는 무시 가능.

### 단계 7: 호스트 머신 브라우저에서 접속

호스트 머신의 브라우저 주소창에:

```
http://192.168.1.10:5173
```

기대 결과: Worklog 앱 UI가 표시됨 (mock 데이터로 채워진 화면).

> 💡 **mock이 백엔드 없이 동작하는 원리**: 본 프로젝트는 **MSW**(Mock Service Worker)를 사용합니다. 브라우저의 service worker가 `/api/...` 같은 fetch 요청을 가로채 가짜 응답을 반환하므로, 별도의 백엔드 Pod 없이도 화면이 정상 동작합니다. ch3.6 K8s 배포 단계에서는 진짜 backend Pod로 교체됩니다.

## 트러블슈팅

### `EADDRINUSE: address already in use 0.0.0.0:5173`
이전 dev server가 종료되지 않은 상태입니다. 새 터미널에서:
```bash
pkill -f vite
```
후 단계 6 재실행.

### 호스트 브라우저에서 접속 불가 (timeout)
- `vagrant status`로 control plane 노드가 `running` 상태인지 확인
- control plane 노드에서 `ss -tnlp | grep 5173`로 dev server가 `0.0.0.0:5173`에 listen 중인지 확인
- `--host 0.0.0.0` 옵션 누락이 가장 흔한 원인 — 단계 6 명령 정확히 재확인

### `yarn: command not found`
단계 2의 `npm install -g yarn` 누락. 단계 2 재실행.

### `node: command not found` (단계 5에서)
단계 2의 NodeSource 설치 누락. 단계 2 재실행.

### `yarn install` 진행 중 peer dependency 경고
예: `warning "@tanstack/router-devtools > goober@2.1.14" has unmet peer dependency "csstype@^3.0.10".`
무해. 무시하고 다음 단계 진행해도 됨.

### Yarn Berry PnP 관련 경고/에러
본 프로젝트는 `.pnp.cjs`, `.yarn/` 파일이 존재하지만 `.yarnrc.yml`이 없어서 Yarn classic 모드로 동작합니다. 일반적으로 `yarn install`만으로 정상 동작. 에러가 지속되면 `.yarnrc.yml`이 추가되어 있는지 확인.

## 주의사항

- ⛔ AI가 하지 말 것: `<github_username>`을 임의로 채우지 말 것
- ⛔ AI가 하지 말 것: 명령을 **호스트 머신에서 실행**하라고 안내하지 말 것 — 본 챕터는 control plane 노드 안에서 root로 진행
- ⛔ AI가 하지 말 것: `docker compose` 흐름으로 우회하지 말 것 — 이번 챕터는 의도적으로 "**Docker 없이 npm으로 로컬 실행**"
- ⛔ AI가 하지 말 것: vagrant 사용자로 접속하라고 안내하지 말 것 — 본 강의 표준은 `ssh root@192.168.1.10`
- ✅ AI가 해도 됨: `yarn install` / `yarn dev` 출력 해석 안내
- ✅ AI가 해도 됨: Vite hot reload 등 dev 환경 부수 정보 안내
- ✅ AI가 해도 됨: 패키지 매니저 차이(npm vs yarn) 짧게 안내 (단, 본 가드레일은 yarn 기준)
