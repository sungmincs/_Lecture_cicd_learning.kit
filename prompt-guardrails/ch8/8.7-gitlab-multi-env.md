## 검증 중 발견된 이슈 (강의자 참고)

- **태그 빌드에서 deploy job `git push` 실패 — `CI_COMMIT_BRANCH` 빈 값 버그**: v* 태그 빌드 시 `$CI_COMMIT_BRANCH`가 비어있어 `git push origin HEAD:` (빈 refspec)이 실행되어 `fatal: invalid refspec 'HEAD:'` 오류 발생.
  - 증상: `fatal: invalid refspec 'HEAD:'`, `You are not currently on a branch.`
  - 원인: GitLab CI에서 태그 트리거 시 `CI_COMMIT_BRANCH`는 빈 문자열, 태그명은 `CI_COMMIT_TAG`에만 설정됨
  - 해결: deploy job의 push 전 BRANCH 결정 로직을 명시적으로 처리
  - 참조 파일 `ch8/8.7/1.multi-env-pipeline.yml`에 이미 반영됨
  - 수정된 코드:
    ```bash
    if [ -n "$CI_COMMIT_TAG" ]; then
      BRANCH="main"
    else
      BRANCH="$CI_COMMIT_BRANCH"
    fi
    git pull --rebase -X theirs origin $BRANCH || true
    git push origin HEAD:$BRANCH
    ```

- **deploy job rebase 충돌로 태그 이미지 유실 — `-X theirs` 누락 버그** (run-14 발견): 태그(prod) 빌드의
  deploy가 main에 push할 때, main의 `image:` 라인이 다른 파이프라인(예: main push의 dev 배포)으로 이미
  바뀌어 있으면 `git pull --rebase origin main`이 같은 라인에서 충돌한다. `|| true`가 충돌을 삼켜
  태그의 v* 이미지가 main에 반영되지 않고 직전 dev 이미지가 남는다.
  - 증상: deploy 로그에 `error: could not apply ... deploy: update image tag to v1.0.0 for prod`,
    그럼에도 job은 success(|| true) — main manifest는 v* 가 아니라 dev-sha.
  - 원인: GitHub 판(ch8.3/8.4)은 `git pull --rebase -X theirs`로 충돌 시 들어오는(태그) 변경을
    채택하는데, GitLab 판에는 `-X theirs`가 빠져 있었음.
  - 해결: `git pull --rebase -X theirs origin $BRANCH || true` (참조 파일 반영됨)
