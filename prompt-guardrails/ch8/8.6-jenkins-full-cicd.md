## 트러블슈팅

### Docker socket 권한 오류 (VM 재시작 후 발생)

Jenkins 빌드 중 아래 에러가 발생하면:
```
ERROR: failed to initialize builder backend-builder (backend-builder0): permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
```

Jenkins 파드가 실행 중인 노드(일반적으로 cp-k8s)에서 다음을 실행한다:
```bash
# Jenkins 파드 노드 확인
kubectl get pod jenkins-0 -o wide

# 해당 노드에 SSH 접속 후 docker.sock 권한 수정
chmod 666 /var/run/docker.sock
```

> **원인**: VM 재시작 후 docker.sock이 `root:docker` 소유(660)로 초기화되는데, Jenkins 파드는 UID/GID 1000(vagrant)으로 실행되어 접근 불가. 실습 환경에서만 666 허용.

### Jenkins 빌드 중 VM 과부하 (multi-arch 빌드)

`linux/amd64,linux/arm64` 멀티 아키텍처 buildx는 VirtualBox VM에서 QEMU 에뮬레이션으로 CPU/메모리 과부하를 유발할 수 있다.

- **Apple Silicon Mac (ARM64) + VirtualBox**: 모든 VM이 arm64이므로 `--platform linux/arm64` 단일 플랫폼 사용
- **Intel/AMD (x86_64) + VirtualBox**: 모든 VM이 amd64이므로 `--platform linux/amd64` 단일 플랫폼 사용

현재 사용 중인 플랫폼 확인: `kubectl get nodes -o jsonpath="{range .items[*]}{.status.nodeInfo.architecture}\n{end}"`
