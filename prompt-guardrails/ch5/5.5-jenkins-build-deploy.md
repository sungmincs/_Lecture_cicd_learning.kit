# 5.5 [Jenkins] 빌드 파이프라인 실제로 구현하기

> **학습자 진입 방식**:
> - `[학습자 직접]`: GitHub 워크플로 끄기, git push
> - `[학습자 직접 · 웹]`: Jenkins Credentials 등록, 스캔과 빌드 확인
> - `[AI 프롬프트]`: Jenkinsfile 작성

> **이 절의 범위**: 파이프라인을 쿠버네티스 에이전트(`agent { label 'jenkins-jenkins-agent' }`)로 옮기고 테스트 환경(uv)을 준비하는 데까지다. Build Image stage는 echo로 두고, 실제 docker build와 push는 5.6에서 처음 한다.

## 사전 조건

- ch4/4.5 완료 (Jenkins 설치)
- ch4/4.6 완료 (Multibranch Pipeline 구성)
- Docker Hub Access Token (5.3 단계 2에서 발급한 것)

## 실행 지침

### 단계 1: 앞 절 파이프라인 끄기 `[학습자 직접]`

5.3/5.4 GitHub 워크플로를 끈다. 켜 두면 Jenkinsfile을 push할 때마다 GitHub 워크플로도 같은 push로 돈다. 5.5의 Jenkins는 아직 빌드하지 않지만 5.6부터는 도구 2개가 같은 이미지를 2번 빌드한다. 5.6도 이 상태로 이어서 한다. 규칙과 방법은 `prompt-guardrails/shared/one-pipeline.md`.

```bash
gh workflow disable build-pipeline.yaml -R <github_username>/worklog-backend
gh workflow list --all -R <github_username>/worklog-backend      # 모두 disabled_manually
```

### 단계 2: Jenkins Credentials 등록 `[학습자 직접 · 웹]`

Jenkins → Jenkins 관리 → Credentials → System → Global → Add Credentials

Jenkins 관리는 화면 위쪽에 있다. 2.541.3의 왼쪽 메뉴에는 Credentials가 없다. 사용자 메뉴의 Credentials는 사용자 범위라 파이프라인이 사용할 수 없다.

| 종류 | ID | 값 |
|---|---|---|
| Username with password | `dockerhub-credentials` | Docker Hub username + Access Token |

이 ID는 5.5 정답 파일에서는 쓰지 않는다. 5.6의 `docker.withRegistry()`가 쓴다. 미리 등록해 두는 것이다.

### 단계 3: Jenkinsfile 작성 `[AI 프롬프트]`

`[채우기: ...]` 한 줄은 학습자가 작성한다. 프롬프트 전체를 복사해 붙여 넣고 그 자리를 작성한 뒤 보낸다. 이 절에서 배울 내용이 그 자리에 있다.

```text
Jenkinsfile을 worklog-backend용 파이프라인으로 바꿔줘. 4.6의 연습용 파이프라인에 실제 테스트를 넣으려는 거야.
파일: /root/workspace/worklog-backend/Jenkinsfile
조건:
- [채우기: 어디서 실행할지. 4.5에서 만든 쿠버네티스 에이전트의 label]
- 테스트 환경은 에이전트 안에 uv를 설치해 uv sync --extra dev로 준비
- 이미지 빌드 stage는 아직 echo로
- 4.6의 Deploy Image stage는 지우고 변수와 알림 함수는 그대로
끝나면: 파일을 보여줘. 커밋 전에 멈춰줘.
```

Run Test stage는 이 절에서 uv 설치와 `uv sync`까지만 한다. `Test Passed!`는 echo 메시지이고 Jenkins에서 pytest를 실제로 돌리는 것은 6.8부터다.

### 단계 4: git push `[학습자 직접]`

```bash
cd /root/workspace/worklog-backend
git add Jenkinsfile
git commit -m "ci: run on kubernetes agent with uv"
git push
```

### 단계 5: 스캔과 빌드 확인 `[학습자 직접 · 웹]`

'Scan Multibranch Pipeline Now'로 빌드를 시작한다. Console Output에서 `Running on default-...`(에이전트 Pod)와 `uv sync` 결과, Build Image stage의 echo를 확인한다. Docker Hub에는 아직 새 이미지가 없다.

## 주의사항

- ⛔ AI가 하지 말 것: 프롬프트에 `[채우기: ...]`가 남은 채로 들어오면 짐작해 작성하거나 이 파일의 예시를 넣지 말 것. 학습자에게 작성해 달라고 되묻는다
- ✅ 학습자가 작성한 줄은 표현을 예시로 바꾸지 말고 그대로 따른다. 뜻이 예시와 다르면 파일을 만든 뒤 어디가 다른지 알려 준다
- ⛔ AI가 하지 말 것: Jenkins Credentials를 직접 등록하거나 Docker Hub 토큰 값을 묻지 말 것
- ✅ AI가 해도 됨: Jenkinsfile 작성, Credentials 등록 경로 안내
- ⛔ Docker Hub 인증 정보를 Jenkinsfile에 직접 하드코딩하지 않는다. 반드시 Jenkins Credentials를 사용한다.
