# 5.2 CI에서 CD로: 빌드 산출물을 배포로 연결하기 (개념과 준비)

> **학습자 진입 방식**: 개념+준비 섹션 — 본격 실습 없음. CI→CD 흐름과 사전 준비를 마친 뒤 5.3으로 진행.

## 이 챕터에서 다루는 것

ch4에서는 파이프라인의 "구조"(트리거 → job/stage)만 익혔다. ch5에서는 한 걸음 더 나아가, **실제로 애플리케이션을 빌드해 컨테이너 이미지로 만들고, 레지스트리에 push한 뒤, 배포로 연결하는(`deploy_manifest/` 이미지 태그 갱신) 흐름**까지 만든다. 같은 흐름을 GitHub Actions / Jenkins / GitLab CI 세 도구로 각각 구현하고, 마켓플레이스·플러그인·extends로 간소화하는 방법까지 다룬다. 실제 클러스터 배포(CD)는 ch6 Argo CD에서 완성한다.

## CI → 아티팩트 → 매니페스트 갱신 (CD의 토대)

| 단계 | 하는 일 | 산출물 |
|---|---|---|
| **CI (빌드)** | 소스 체크아웃 → 테스트 → `docker build` | 컨테이너 이미지 |
| **레지스트리 push** | 이미지에 태그 부여 → Docker Hub로 push | 레지스트리의 이미지 |
| **매니페스트 갱신** | `deploy_manifest/`의 이미지 태그 갱신 | 갱신된 매니페스트(Git) |
| *(CD = 클러스터 반영, **ch6**)* | *Argo CD가 매니페스트 변경 감지 → 배포* | *실행 중인 Pod* |

> 핵심은 **"빌드 산출물(이미지)을 어떻게 배포로 연결하는가"** 다. **ch5의 범위는 빌드 → push → `deploy_manifest/` 이미지 태그 갱신까지**이고, 실제 클러스터 반영(Pod 실행, 곧 CD)은 **ch6에서 Argo CD(GitOps)** 가 담당한다. ch5는 그 CD의 토대(갱신된 매니페스트)를 만든다.

## 3개 도구의 동일한 골격

도구마다 문법은 다르지만 본질은 같다 — **빌드 → push → 매니페스트 갱신**.

| 도구 | 빌드/푸시 정의 | 간소화 수단 |
|---|---|---|
| GitHub Actions | `.github/workflows/*.yaml` | Marketplace Action(`docker/build-push-action`) |
| Jenkins | `Jenkinsfile` | Docker Plugin |
| GitLab CI | `.gitlab-ci.yml` | `extends` / 템플릿 |

## 실습 사전 준비 (체크리스트)

- [ ] **Docker Hub 계정 + Access Token** — 이미지 push 인증에 필수(ch5 전반에서 사용)
- [ ] 각 도구에 시크릿 등록: GitHub Secrets / Jenkins Credentials / GitLab Variables (`DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`)
- [ ] worklog 저장소(backend/frontend)가 본인 계정에 fork된 상태
- [ ] ch4 완료 — 각 도구의 파이프라인 기본 구조 이해

> 배포 대상 클러스터 접근(kubeconfig)·GitOps 연동은 ch6에서 본격적으로 다룬다. ch5는 "빌드→push→매니페스트 갱신"까지가 범위다.
