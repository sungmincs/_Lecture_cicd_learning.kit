# 5.3 [GitHub] CI 파이프라인 실제로 구현하기

> **학습자 진입 방식**:
> - `[학습자 직접]`: GitHub Secrets 등록, git push
> - `[AI 프롬프트]`: 파이프라인 yaml 작성

## 사전 조건

- ch5 시작 전: Docker Hub Access Token 발급
  - Docker Hub → Account Settings → Security → New Access Token
- worklog-backend 저장소가 GitHub에 있음 (ch4.3~4.4에서 사용한 fork)

## 실행 지침

### 단계 1: GitHub Secrets 등록 `[학습자 직접]`

저장소 → Settings → Secrets and variables → Actions → New repository secret

| Secret 이름 | 값 |
|---|---|
| `DOCKERHUB_TOKEN` | Docker Hub Access Token |

### 단계 2: 파이프라인 yaml 작성 `[AI 프롬프트]`

> "worklog-backend를 Docker Hub에 빌드하고 push하는 GitHub Actions 파이프라인 만들어줘. Docker Hub username은 `<dockerhub_username>`이야."

✅ 정답 파일 (완성 후 비교): `ch5/5.3/1.build-pipeline.yaml`

### 단계 3: git push `[학습자 직접]`

```bash
git add .github/workflows/
git commit -m "add: build and push pipeline"
git push
```

### 단계 4: Actions 실행 결과 확인 `[학습자 직접]`

GitHub → Actions 탭 → 각 job 성공 여부 확인
- Docker Hub에 이미지가 push됐는지 Docker Hub UI에서 확인

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<github_username>` | 학습자의 GitHub username | ❌ |

## 주의사항

- ⛔ AI가 하지 말 것: GitHub Secrets를 직접 등록하려 하지 말 것
- ✅ AI가 해도 됨: 파이프라인 yaml 작성
- ✅ AI가 해도 됨: Secrets 등록 경로 안내
- ✅ AI가 해도 됨: 빌드/push 실패 원인 분석
- ⛔ `env.DOCKERHUB_USERNAME` 값은 파이프라인 YAML에 하드코딩되어 있으므로 본인 계정으로 수정해야 한다.
