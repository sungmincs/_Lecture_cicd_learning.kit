## 검증 중 발견된 이슈 (강의자 참고)

- **GitLab CI `needs` 동작 — GitHub Actions `needs`와 다름** (4차 검증 발견):
  GitLab CI에서 `needs`로 연결된 job이 `failed`여도 후속 job이 **실행됨**.
  GitHub Actions는 `needs` job 실패 시 후속 job을 skip하지만,
  GitLab CI `needs`는 artifacts 공유 목적이므로 실패한 job을 의존해도 후속 job 실행.

  **학습자에게 안내**: test job이 실패해도 build job이 실행될 수 있음.
  test 실패 시 build를 차단하려면 `needs` 대신 stage 순서 의존 또는 `rules` 조건 사용:
  ```yaml
  build:
    stage: build
    # needs 제거 → 이전 stage(test) 실패 시 자동 skip
    script: ...
  ```

- **`DOCKER_TLS_CERTDIR: "/certs"` + `docker buildx create ... 2>/dev/null || true` 조합 버그**:
  GitLab 공유 러너 DinD 환경에서 `docker-container` 드라이버 생성이 silently fail하여
  기본 `docker` 드라이버로 fall back → `--platform linux/amd64,linux/arm64` 빌드 실패.
  
  **수정**: 참조 파일 `ch5/5.7/1.build-pipeline.yml`의 `build` job을 아래와 같이 변경해야 함:
  ```yaml
  variables:
    DOCKER_TLS_CERTDIR: ""        # TLS 비활성화
    DOCKER_HOST: tcp://docker:2375
    DOCKER_CONFIG: "/tmp/docker_config"
  script:
    ...
    - docker buildx rm mybuilder 2>/dev/null || true
    - docker buildx create --name mybuilder --driver docker-container --use
    - docker buildx build ...
  ```

## 검증 발견 (run-16, #91): fork 앱 소스의 httpx 버전 갭

- GitLab fork를 python3.14/uv로 정렬할 때, `uv.lock`이 가져오는 **최신 httpx(0.28+)** 에서는
  `AsyncClient(app=...)` 인자가 제거됨. fork의 `src/worklog/conftest.py`가 구버전 패턴이면
  `test` job이 `TypeError: AsyncClient.__init__() got an unexpected keyword argument 'app'`로 실패.
- 해결: conftest를 신버전으로 통일 — `AsyncClient(transport=ASGITransport(app=app), ...)`.
- 사전 준비 권장: **세 fork(GitHub/GitLab/frontend)의 앱 소스를 단일 기준으로 동기화**(코드와 uv.lock 불일치 방지).
