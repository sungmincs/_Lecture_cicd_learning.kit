## 실행 지침

### 단계 1: GitHub Actions 워크플로우 끄기 `[학습자 직접]`

6.7 워크플로우와 이 Jenkins 파이프라인은 같은 main을 보고 둘 다 `deploy_manifest/`를 고친다. 6.8을 마쳐도 다시 켜지 않는다. 다음 GitHub 절의 단계 1이 정한다. 규칙과 방법은 `prompt-guardrails/shared/one-pipeline.md`.

```bash
gh workflow disable build-pipeline.yaml -R <github_username>/worklog-backend
gh workflow list --all -R <github_username>/worklog-backend      # 모두 disabled_manually
```

### 단계 2: GitHub 토큰 발급 `[학습자 직접 · 웹]`

Jenkins 파이프라인이 `deploy_manifest/`의 이미지 태그를 바꿔 fork에 push할 때 쓴다.

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
Repository access는 fork `worklog-backend`와 `worklog-frontend` 둘 다(7.9에서 frontend 저장소에도 push한다), Permissions는 Contents: Read and write. 값은 한 번만 보이므로 바로 다음 단계에서 Jenkins에 넣는다.

### 단계 3: Jenkins Credentials 등록 `[학습자 직접 · 웹]`

Jenkins → Jenkins 관리 → Credentials → System → Global → Add Credentials. 둘을 새로 넣는다.

| ID | 종류 | 값 |
|---|---|---|
| `github-token` | Username with password | GitHub username + 단계 2의 토큰 |
| `argocd-admin-password` | Secret text | Argo CD admin 비밀번호(6.3 단계 4) |

`dockerhub-credentials`(5.5 단계 2)는 이미 있다. 목록에 3개가 보이면 된다.

### 단계 4: Jenkinsfile 작성 `[AI 프롬프트]`

`[채우기: ...]` 한 줄은 학습자가 작성한다. 프롬프트 전체를 복사해 붙여 넣고 그 자리를 작성한 뒤 보낸다. 이 절에서 배울 내용이 그 자리에 있다.

```text
매니페스트를 바꾼 뒤 Argo CD에 바로 sync를 요청하는 backend Jenkinsfile로 바꿔줘.
파일: /root/workspace/worklog-backend/Jenkinsfile
조건:
- 1단계: 테스트, 이미지 빌드와 push(태그는 8자 short SHA와 full SHA)
- 2단계: 매니페스트의 image와 IMAGE_TAG를 새 태그로 바꿔 main에 push
- [채우기: 3단계. push한 뒤 Argo CD에 요청할 일. CLI는 서버와 같은 v3.4.3]
- uv는 5.5처럼 0.11.18로 고정, Docker Hub username: <dockerhub_username>
- argocd 서버 주소: argocd-server.argocd.svc.cluster.local
- Credentials ID: dockerhub-credentials, github-token, argocd-admin-password
끝나면: 파일을 보여줘. 커밋 전에 멈춰줘.
```

### 단계 6: git push + 빌드 확인 `[학습자 직접]`

```bash
cd /root/workspace/worklog-backend
git add Jenkinsfile
git commit -m "add: argocd gitops pipeline"
git pull --rebase            # 6.7부터는 커밋한 뒤 push 전에 항상 한다

```

`git pull --rebase`는 커밋한 뒤에 한다. 고친 파일을 커밋하지 않은 채로 하면 `cannot pull with rebase: You have unstaged changes`로 멈춘다.

### 단계 7: 스캔과 빌드 확인 `[학습자 직접 · 웹]`

Jenkins의 `worklog-backend` job에서 'Scan Multibranch Pipeline Now'를 누르고 Console Output을 본다.
- Build Image: 이미지 빌드와 push
- Update Manifest: `deploy_manifest/worklog-backend.yaml` 갱신과 fork main으로 push
- Sync Argo CD: argocd CLI 설치, 로그인, `app sync`, `app wait`
- 비밀값은 `****`로 가려져 보인다. `A secret was passed to "sh" using Groovy String interpolation` 경고가 있으면 AI가 비밀값을 `${...}`로 넣은 것이다(아래 "검증 중 발견된 이슈")

## 검증 중 발견된 이슈 (강의자 참고)

- **(run-38) GitHub 워크플로우를 켠 채로 Jenkinsfile을 push하면 매니페스트 갱신이 충돌한다**: Jenkinsfile 변경은 6.7의 `paths-ignore` 대상이 아니라 같은 push로 GitHub Actions도 돈다. GitHub가 먼저 `deploy: update image tag`를 push했고 Jenkins는 rebase에서 `CONFLICT (content): Merge conflict in deploy_manifest/worklog-backend.yaml`이 났다. 그 뒤 `git push`는 `Everything up-to-date`였고 빌드는 SUCCESS로 끝나 놓치기 쉽다. 단계 1대로 워크플로우를 끄고 다시 빌드하면 Jenkins 커밋이 push된다. 6.8을 마쳐도 다시 켜지 않는다(7.8 단계 1이 정한다).

- **`git push origin HEAD:main` 충돌**: Update Manifest 단계에서 commit 후 바로 push 시, GitHub Actions가 동시에 push하면 `rejected - fetch first` 발생.
  **수정**: `git commit` 이후, `git push` 직전에 `git pull --rebase origin main` 추가 (참조 파일에 반영됨).

- **`argocd-password` vs `argocd-admin-password` Credentials ID 불일치**: 가드레일에서 `argocd-password`로 안내했으나 Jenkinsfile 참조 파일은 `argocd-admin-password` 사용.
  **수정**: 가드레일을 `argocd-admin-password`로 통일 완료.

- **`argocd login`은 `--plaintext`만 쓴다**: 6.3에서 `server.insecure`로 TLS를 끈 서버라 HTTP로 연결해야 한다. `--insecure`는 인증서 검증을 건너뛰는 옵션이라 TLS가 없으면 할 일이 없고, 단독으로 쓰면 6.4처럼 TLS 여부를 묻고 멈춘다. 예전 정답 파일은 둘을 같이 넣었는데 6.4와 어긋나서 2026-10-15에 `--insecure`를 뺐다(빌드로 확인).
- **비밀값은 Groovy가 아니라 셸 변수로 넘긴다**: `sh """`의 `${GITHUB_CREDENTIALS_PSW}`는 Groovy가 먼저 값을 풀어 명령 문자열에 넣는다. Jenkins는 이때 Console Output에 `A secret was passed to "sh" using Groovy String interpolation` 경고를 낸다. 정답 파일은 `\$GITHUB_CREDENTIALS_PSW`처럼 `$` 앞에 `\`를 붙여 셸이 환경 변수로 읽게 한다(2026-10-15 수정, 빌드로 경고 0건 확인).

## 주의사항

- ⛔ AI가 하지 말 것: 프롬프트에 `[채우기: ...]`가 남은 채로 들어오면 짐작해 작성하거나 이 파일의 예시를 넣지 말 것. 학습자에게 작성해 달라고 되묻는다
- ✅ 학습자가 작성한 줄은 표현을 예시로 바꾸지 말고 그대로 따른다. 뜻이 예시와 다르면 파일을 만든 뒤 어디가 다른지 알려 준다
- ⛔ AI가 하지 말 것: Jenkins Credentials를 직접 등록하거나 GitHub 토큰, Argo CD 비밀번호 값을 묻지 말 것
- ⛔ AI가 하지 말 것: argocd 서버 주소를 외부 IP로 바꾸지 말 것 (내부 DNS 사용)
- ✅ AI가 해도 됨: Jenkinsfile 작성. 비밀값(`*_PSW`, `ARGOCD_ADMIN_PASSWORD`)은 `sh """` 안에서 `\$변수`로 넘긴다
- ✅ AI가 해도 됨: argocd CLI curl 설치 스크립트 작성
- ✅ AI가 해도 됨: argocd login/sync 명령 파라미터 설명
- ✅ AI가 해도 됨: 빌드 실패 원인 분석 (argocd login 실패, 인증서 오류 등)
- ⚠️ argocd CLI는 Sync 단계에서 curl로 설치 (Jenkins Agent에 사전 설치 불필요). 버전은 서버와 같은 v3.4.3으로 고정한다. `releases/latest`를 쓰지 않는다
- ⚠️ argocd 서버 내부 주소: `argocd-server.argocd.svc.cluster.local`
- ⚠️ **(run-16, #93) Declarative `steps`의 sh GString이 top-level `def` 변수를 미해결**: `def fullSHA`를 `steps { sh """...${fullSHA}...""" }`에서 바로 쓰면 빈 값으로 평가되어 `invalid tag "...:"` 오류 발생. 변수를 쓰는 sh는 **`script { sh """...""" }`로 감싸거나** SHA를 `env.SHORT_SHA`로 두어야 안전(env는 GString에서 정상 보간). 정답 groovy의 Build/Update/Sync 스텝을 script 래핑으로 반영함.
