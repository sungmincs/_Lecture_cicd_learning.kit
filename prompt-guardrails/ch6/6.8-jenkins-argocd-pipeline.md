## 검증 중 발견된 이슈 (강의자 참고)

- **(run-38) GitHub 워크플로우를 켠 채로 Jenkinsfile을 push하면 매니페스트 갱신이 충돌한다**: Jenkinsfile 변경은 6.7의 `paths-ignore` 대상이 아니라 같은 push로 GitHub Actions도 돈다. GitHub가 먼저 `deploy: update image tag`를 push했고 Jenkins는 rebase에서 `CONFLICT (content): Merge conflict in deploy_manifest/worklog-backend.yaml`이 났다. 그 뒤 `git push`는 `Everything up-to-date`였고 빌드는 SUCCESS로 끝나 놓치기 쉽다. 단계 0대로 워크플로우를 끄고 다시 빌드하면 Jenkins 커밋이 push된다. 6.8을 마쳐도 다시 켜지 않는다(7.8 단계 0이 정한다).

- **`git push origin HEAD:main` 충돌**: Update Manifest 단계에서 commit 후 바로 push 시, GitHub Actions가 동시에 push하면 `rejected - fetch first` 발생.
  **수정**: `git commit` 이후, `git push` 직전에 `git pull --rebase origin main` 추가 (참조 파일에 반영됨).

- **`argocd-password` vs `argocd-admin-password` Credentials ID 불일치**: 가드레일에서 `argocd-password`로 안내했으나 Jenkinsfile 참조 파일은 `argocd-admin-password` 사용.
  **수정**: 가드레일을 `argocd-admin-password`로 통일 완료.

- **`argocd login --plaintext` 필수**: Jenkins 내부에서 `argocd-server.argocd.svc.cluster.local`로 연결 시 `--insecure`만으로는 부족. `--plaintext`도 함께 지정해야 gRPC over HTTP 연결 성공.

- ✅ AI가 해도 됨: Jenkinsfile 작성

- ✅ AI가 해도 됨: 빌드 실패 원인 분석 (argocd login 실패, 인증서 오류 등)
- ⚠️ argocd CLI는 Sync 단계에서 curl로 설치 (Jenkins Agent에 사전 설치 불필요)
- ⚠️ argocd 서버 내부 주소: `argocd-server.argocd.svc.cluster.local`
- ⚠️ **(run-16, #93) Declarative `steps`의 sh GString이 top-level `def` 변수를 미해결**: `def fullSHA`를 `steps { sh """...${fullSHA}...""" }`에서 바로 쓰면 빈 값으로 평가되어 `invalid tag "...:"` 오류 발생. 변수를 쓰는 sh는 **`script { sh """...""" }`로 감싸거나** SHA를 `env.SHORT_SHA`로 두어야 안전(env는 GString에서 정상 보간). 정답 groovy의 Build/Update/Sync 스텝을 script 래핑으로 반영함.
