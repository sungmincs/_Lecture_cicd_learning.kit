# 6.6 Argo CD Slack 알림 설정

> **학습자 진입 방식**:
> - `[학습자 직접]`: Slack 앱 Bot 토큰 발급과 채널 초대, Secret 등록, ConfigMap 병합 적용
> - `[AI 프롬프트]`: argocd-notifications ConfigMap/Secret/Trigger 작성

## 사전 조건

- ch6/6.5 완료 (Argo CD Application 동작 확인)
- Slack Workspace 접근 권한
- Argo CD Notifications Controller 설치 확인

```bash
kubectl get pods -n argocd | grep notification
```

## 실행 지침

### 단계 1: Slack 앱 Bot 토큰 발급 `[학습자 직접]`

Argo CD의 Slack 알림(`service.slack`)은 Slack 앱의 Bot 토큰으로 메시지를 보낸다. Incoming Webhook URL은 이 방식에 쓰지 않는다.
Slack 앱 만들기는 CI/CD 범위 밖의 준비 작업이라 순서만 따라 한다.

1. https://api.slack.com/apps → **Create New App** → From scratch → 앱 이름(예: `argocd-notifier`), 워크스페이스 선택
2. **OAuth & Permissions** → Bot Token Scopes에 `chat:write` 추가
3. 같은 화면 위쪽 **Install to Workspace** → 허용
4. **Bot User OAuth Token**(`xoxb-`로 시작)을 복사한다
5. Slack에서 `argocd-alerts` 채널을 만들고, 채널에서 `/invite @argocd-notifier`로 앱을 초대한다. 초대하지 않으면 `not_in_channel` 오류로 메시지가 가지 않는다

### 단계 2: argocd-notifications Secret 등록 `[학습자 직접]`

```bash
read -rs SLACK_TOKEN    # xoxb- 토큰을 붙여넣고 Enter. 화면과 셸 기록에 남지 않는다
kubectl patch secret argocd-notifications-secret -n argocd --type merge \
  -p "{\"stringData\": {\"slack-token\": \"$SLACK_TOKEN\"}}"
unset SLACK_TOKEN
```

Secret은 6.3 설치 때 이미 만들어졌다. `create`가 아니라 위 `patch`를 쓴다.

### 단계 3: argocd-notifications ConfigMap 작성 `[AI 프롬프트]`

> "Argo CD Notifications에서 Slack으로 알림을 보내는 ConfigMap을 작성해줘.
> - 트리거: on-sync-succeeded, on-sync-failed
> - 채널: argocd-alerts
> - Application 이름, sync 상태, timestamp를 메시지에 포함해줘."

✅ 정답 파일 (완성 후 비교): `ch6/6.6/1.argocd-notifications-cm.yaml`

### 단계 4: ConfigMap 병합 적용 `[학습자 직접]`

AI가 작성한 ConfigMap을 control plane 노드의 `/root/workspace/argocd-notifications-cm.yaml`로 저장하고 기존 ConfigMap에 **병합**한다.

```bash
kubectl get configmap argocd-notifications-cm -n argocd -o go-template='{{len .data}}{{"\n"}}'   # 적용 전 키 수(6.3 카탈로그)
kubectl patch configmap argocd-notifications-cm -n argocd --type merge \
  --patch-file /root/workspace/argocd-notifications-cm.yaml
kubectl get configmap argocd-notifications-cm -n argocd -o go-template='{{len .data}}{{"\n"}}'   # 늘었으면 병합된 것
```

`kubectl apply -f`를 쓰지 않는다. 6.3 `install.sh`가 넣은 알림 카탈로그(트리거와 템플릿 18개)가 이 파일의 6개로 바뀐다.
병합하면 카탈로그는 남고, 이 절에서 만든 템플릿과 트리거만 더해진다(같은 이름이 있으면 이 파일 값으로 바뀐다).

### 단계 5: Application에 알림 annotation 추가 `[AI 프롬프트]`

> "worklog-backend Application에 Slack 알림 annotation을 추가해줘. on-sync-succeeded와 on-sync-failed 트리거 모두 포함."

```bash
kubectl annotate application worklog-backend \
  -n argocd \
  notifications.argoproj.io/subscribe.on-sync-succeeded.slack="argocd-alerts" \
  notifications.argoproj.io/subscribe.on-sync-failed.slack="argocd-alerts"
```

### 단계 6: 알림 동작 확인 `[학습자 직접]`

```bash
# 수동 sync 트리거로 알림 테스트
argocd app sync worklog-backend
```

Slack 채널에 메시지가 도착하는지 확인한다. 오지 않으면 컨트롤러 로그를 본다.

```bash
kubectl logs -n argocd deploy/argocd-notifications-controller --tail=30 | grep -i slack
# invalid_auth → 토큰이 xoxb-가 아니다(Webhook URL을 넣었거나 오타)
# not_in_channel / channel_not_found → 단계 1의 5번(채널 만들기, 앱 초대)
```
