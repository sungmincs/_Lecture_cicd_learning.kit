# 6.6 Argo CD Slack 알림 설정

> **학습자 진입 방식**:
> - `[학습자 직접 · 웹]`: Slack 앱 Bot 토큰 발급과 채널 초대, Slack에서 메시지 확인
> - `[학습자 직접]`: Secret 등록, ConfigMap 병합 적용, annotation 추가, 동기화와 로그 확인
> - `[AI 프롬프트]`: argocd-notifications ConfigMap(템플릿과 트리거) 작성

## 사전 조건

- ch6/6.5 완료 (Argo CD Application 동작 확인)
- Slack Workspace 접근 권한(앱을 설치할 수 있어야 한다)

## 실행 지침

### 단계 1: Notifications Controller 확인 `[학습자 직접]`

```bash
kubectl get pods -n argocd | grep notification      # argocd-notifications-controller가 Running
```

### 단계 2: Slack 앱 Bot 토큰 발급 `[학습자 직접 · 웹]`

Argo CD의 Slack 알림(`service.slack`)은 Slack 앱의 Bot 토큰으로 메시지를 보낸다. Incoming Webhook URL은 이 방식에 쓰지 않는다.
Slack 앱 만들기는 CI/CD 범위 밖의 준비 작업이라 순서만 따라 한다.

1. https://api.slack.com/apps → **Create New App** → From scratch → 앱 이름(예: `argocd-notifier`), 워크스페이스 선택
2. **OAuth & Permissions** → Bot Token Scopes에 `chat:write` 추가
3. 같은 화면 위쪽 **Install to Workspace** → 허용
4. **Bot User OAuth Token**(`xoxb-`로 시작)을 복사한다
5. Slack에서 `argocd-alerts` 채널을 만들고, 채널에서 `/invite @argocd-notifier`로 앱을 초대한다. 초대하지 않으면 `not_in_channel` 오류로 메시지가 가지 않는다

### 단계 3: argocd-notifications Secret 등록 `[학습자 직접]`

```bash
read -rs SLACK_TOKEN    # xoxb- 토큰을 붙여넣고 Enter. 화면과 셸 기록에 남지 않는다
kubectl patch secret argocd-notifications-secret -n argocd --type merge \
  -p "{\"stringData\": {\"slack-token\": \"$SLACK_TOKEN\"}}"
unset SLACK_TOKEN
```

Secret은 6.3 설치 때 이미 만들어졌다. `create`가 아니라 위 `patch`를 쓴다.

### 단계 4: argocd-notifications ConfigMap 작성 `[AI 프롬프트]`

`[채우기: ...]` 한 줄은 학습자가 작성한다. 프롬프트 전체를 복사해 붙여 넣고 그 자리를 작성한 뒤 보낸다. 이 절에서 배울 내용이 그 자리에 있다.

```text
Argo CD Notifications가 Slack으로 알림을 보내는 ConfigMap을 만들어줘. 배포 결과를 Slack 채널에서 바로 보려는 거야.
파일: /root/workspace/argocd-notifications-cm.yaml (ConfigMap argocd-notifications-cm, 네임스페이스 argocd)
조건:
- service.slack은 Secret의 $slack-token을 사용한다
- [채우기: 알림을 보낼 때. 배포가 성공했을 때와 실패했을 때의 트리거 이름]
- 템플릿: app-sync-succeeded, app-sync-failed. Application 이름, revision, 시각을 메시지에 넣어줘
끝나면: 파일의 when: 줄을 다시 읽어 작은따옴표가 그대로 있는지 확인하고 파일을 보여줘. 적용 전에 멈춰줘.
```

|---|---|---|
| 트리거 | on-sync-succeeded, on-sync-failed | Argo CD가 sync를 끝낸 결과에 따라 알림 템플릿을 고른다 |

</details>

✅ 정답 파일 (완성 후 비교): `ch6/6.6/1.argocd-notifications-cm.yaml`

### 단계 5: ConfigMap 병합 적용 `[학습자 직접]`

단계 4에서 AI가 노드에 저장한 파일을 기존 ConfigMap에 **병합**한다. 먼저 조건식의 따옴표를 본다.

```bash
grep -n "when:" /root/workspace/argocd-notifications-cm.yaml
# when: app.status.operationState.phase in ['Succeeded']          ← 작은따옴표가 있어야 한다
# when: app.status.operationState.phase in ['Error', 'Failed']
```

따옴표가 빠져 `in [Succeeded]`로 되어 있으면 병합은 되지만 트리거가 조용히 실패한다. AI에게 다시 저장시키고 넘어간다.

```bash
kubectl patch configmap argocd-notifications-cm -n argocd --type merge \
  --patch-file /root/workspace/argocd-notifications-cm.yaml
kubectl get configmap argocd-notifications-cm -n argocd \
  -o jsonpath='{.data.template\.app-sync-succeeded}'        # 이 절에서 쓴 메시지 문구가 나오면 병합된 것
kubectl get configmap argocd-notifications-cm -n argocd -o go-template='{{len .data}}{{"\n"}}'   # 18. 카탈로그가 남아 있다
```

`kubectl apply -f`를 쓰지 않는다. 6.3 `install.sh`가 넣은 알림 카탈로그(키 18개: 템플릿 8, 트리거 8, 이 강의가 넣은 `context`와 `service.slack`)가 이 파일의 5개로 바뀐다.
병합하면 카탈로그는 남는다. 이 파일의 키 5개는 카탈로그에 같은 이름이 이미 있어서 키 수는 18 그대로이고 값만 이 파일 것으로 바뀐다.

### 단계 6: Application에 알림 annotation 추가 `[학습자 직접]`

worklog-backend Application이 트리거 2개를 `argocd-alerts` 채널로 구독하게 한다.

```bash
kubectl annotate application worklog-backend \
  -n argocd \
  notifications.argoproj.io/subscribe.on-sync-succeeded.slack="argocd-alerts" \
  notifications.argoproj.io/subscribe.on-sync-failed.slack="argocd-alerts"
```

### 단계 7: 알림 동작 확인 `[학습자 직접]`

```bash
# 수동 sync 트리거로 알림 테스트
argocd app sync worklog-backend
kubectl logs -n argocd deploy/argocd-notifications-controller --tail=30 | grep -i "slack\|trigger"
# invalid_auth → 토큰이 유효하지 않다(Webhook URL을 넣었거나, 오타, 다른 앱의 토큰)
# not_in_channel / channel_not_found → 단계 2의 5번(채널 만들기, 앱 초대)
# Trigger 'on-sync-succeeded' FAILED만 있고 slack 줄이 없다 → 단계 5의 when: 따옴표
```

정상일 때는 `Trigger 'on-sync-succeeded' TRIGGERED`와 `Sending notification ... to '{slack argocd-alerts}'`가 보인다.
같이 찍히는 `Trigger 'on-sync-failed' FAILED`는 오류가 아니다. "실패 조건에 해당하지 않는다"는 뜻이다.

### 단계 8: Slack에서 메시지 확인 `[학습자 직접 · 웹]`

Slack의 `argocd-alerts` 채널에 "Application *worklog-backend* sync succeeded" 메시지가 왔는지 본다.

## 주의사항

- ⛔ AI가 하지 말 것: 프롬프트에 `[채우기: ...]`가 남은 채로 들어오면 짐작해 작성하거나 이 파일의 예시를 넣지 말 것. 학습자에게 작성해 달라고 되묻는다
- ✅ 학습자가 작성한 줄은 표현을 예시로 바꾸지 말고 그대로 따른다. 뜻이 예시와 다르면 파일을 만든 뒤 어디가 다른지 알려 준다
- ⛔ AI가 하지 말 것: Slack 토큰을 임의로 생성하거나 추측하지 말 것. 토큰을 화면, 파일, 커밋에 남기지 말 것
- ⛔ AI가 하지 말 것: 단계 5에서 `kubectl apply -f`로 ConfigMap 전체를 바꾸지 말 것(6.3 카탈로그가 사라진다)
- ⛔ AI가 하지 말 것: 단계 6의 annotation이나 단계 5의 병합을 대신 실행하지 말 것. 파일 작성까지만 한다
- ✅ AI가 해도 됨: ConfigMap (trigger/template/service) 작성
- ✅ AI가 해도 됨: Slack 앱 Bot 토큰 발급 경로 안내
- ✅ AI가 해도 됨: 알림이 오지 않을 때 원인 분석 (Controller 로그, annotation 확인 등)
- ✅ AI가 해도 됨: on-health-degraded 등 추가 트리거 작성 (요청 시)
