- ch6/6.4 완료 (argocd CLI 로그인 확인)

## 실행 지침

### 단계 1: GitHub 저장소를 Argo CD에 연결 `[학습자 직접]`

```bash
argocd repo add https://github.com/<github_username>/worklog-backend
```

fork가 public이면 인증 없이 등록된다. private으로 바꿨다면 `--username <github_username> --password <github-token>`을 붙인다(토큰은 Contents 읽기 권한이면 충분하다).
같은 일을 Argo CD UI의 Settings → Repositories → Connect Repo로도 할 수 있다.

### 단계 2: Argo CD Application manifest 작성 `[AI 프롬프트]`

> "worklog-backend Argo CD Application manifest를 작성해서 컨트롤 플레인 노드의 `/root/workspace/argocd-application.yaml`로 저장해줘. 적용은 내가 할게.
> - 저장소: https://github.com/<github_username>/worklog-backend
> - 경로: deploy_manifest/
> - 대상 클러스터: in-cluster (https://kubernetes.default.svc)
> - namespace: default
> - automated sync 활성화 (selfHeal: true, prune: true)"

✅ 정답 파일 (완성 후 비교): `ch6/6.5/1.worklog-backend-app.yaml`

### 단계 3: Application 생성 `[학습자 직접]`

단계 2에서 AI가 노드에 저장한 파일을 확인하고 적용한다.

```bash
cat /root/workspace/argocd-application.yaml
kubectl apply -f /root/workspace/argocd-application.yaml
```

이 파일은 fork 저장소 안이 아니라 `/root/workspace/` 바로 아래에 둔다. Application은 Argo CD에게 "어느 저장소를 보라"고 알려 주는 설정이라 그 저장소 안에 두지 않는다.

### 단계 4: Application 상태 확인 `[학습자 직접]`

```bash
argocd app get worklog-backend
argocd app list
```

`Synced`, `Healthy`가 될 때까지 기다린다. 5.3에서 넣은 `buildtest1` 이미지로 backend가 뜬다. Argo CD UI에서도 같은 상태가 보인다.

```bash
kubectl get pods            # worklog-backend Pod가 Running
```

### 단계 5: imagePullSecret 만들기 `[학습자 직접]`

7장의 매니페스트는 `imagePullSecrets: dockerhub-creds`를 쓴다. 지금 만들어 둔다. 토큰은 자격 증명이라 직접 넣는다.

```bash
read -rs DOCKERHUB_TOKEN    # Docker Hub Access Token을 붙여넣고 Enter. 화면과 셸 기록에 남지 않는다
kubectl create secret docker-registry dockerhub-creds \
  --docker-username=<dockerhub_username> \
  --docker-password="$DOCKERHUB_TOKEN" \
  --docker-server=https://index.docker.io/v1/
unset DOCKERHUB_TOKEN
kubectl get secret dockerhub-creds
```

이 장의 `deploy_manifest/worklog-backend.yaml`은 이 Secret을 쓰지 않는다. 이미지가 public이라 없어도 받아진다.

### 단계 6: automated sync 동작 원리 설명 `[AI 프롬프트]`

> "Argo CD의 automated sync에서 selfHeal과 prune이 각각 무엇을 하는지 설명해줘."

> "deploy_manifest/ 폴더의 파일이 변경되면 Argo CD가 어떤 흐름으로 자동 배포하는지 설명해줘."

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<github_username>` | 학습자의 GitHub username | ❌ 반드시 확인 |
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<github-token>` | GitHub Personal Access Token (fork가 private일 때만) | ❌ 학습자가 직접 입력 |

## 주의사항

- ⛔ AI가 하지 말 것: GitHub token이나 Docker Hub token을 묻거나, 단계 5의 Secret을 대신 만들지 말 것
- ⛔ AI가 하지 말 것: Application 파일을 fork 저장소(`/root/workspace/worklog-backend/`) 안에 저장하지 말 것
- ⛔ AI가 하지 말 것: `deploy_manifest/` 경로를 다른 경로로 바꾸지 말 것 (6.7~6.8 파이프라인, 10.9와 연동)
- ✅ AI가 해도 됨: Application manifest 작성, selfHeal/prune 설명
- ✅ AI가 해도 됨: imagePullSecrets 구성 방법 안내
- ✅ AI가 해도 됨: Argo CD App of Apps 패턴 등 심화 개념 설명 (질문 시)
- ⚠️ `deploy_manifest/` 폴더는 학습자 fork 저장소에 있어야 함 (강의 키트 저장소 아님)
