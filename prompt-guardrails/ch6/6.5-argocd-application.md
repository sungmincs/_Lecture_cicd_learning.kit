## 실행 지침

### 단계 1: GitHub 저장소를 Argo CD에 연결 `[학습자 직접]`

```bash
argocd repo add https://github.com/<github_username>/worklog-backend
```

fork가 public이면 인증 없이 등록된다. private으로 바꿨다면 `--username <github_username> --password <github-token>`을 붙인다(토큰은 Contents 읽기 권한이면 충분하다).
같은 일을 Argo CD UI의 Settings → Repositories → Connect Repo로도 할 수 있다.

### 단계 2: Argo CD Application manifest 작성 `[AI 프롬프트]`

`[채우기: ...]` 한 줄은 학습자가 작성한다. 프롬프트 전체를 복사해 붙여 넣고 그 자리를 작성한 뒤 보낸다. 이 절에서 배울 내용이 그 자리에 있다.

```text
worklog-backend의 Argo CD Application manifest를 만들어줘. 저장소의 deploy_manifest를 Argo CD가 보고 클러스터에 배포하게 하려는 거야.
파일: /root/workspace/argocd-application.yaml
조건:
- 저장소: https://github.com/<github_username>/worklog-backend, 경로: deploy_manifest/
- 대상: in-cluster (https://kubernetes.default.svc), namespace default
- [채우기: Argo CD가 저장소와 클러스터를 자동으로 맞추게 하는 sync 설정. 클러스터를 직접 바꾼 경우와 저장소에서 파일을 지운 경우까지]
끝나면: dry-run으로 검사하고 파일을 보여줘. 적용 전에 멈춰줘.
```

### 단계 3: Application 생성 `[학습자 직접]`

단계 2에서 AI가 노드에 저장한 파일을 확인하고 적용한다.

```bash
cat /root/workspace/argocd-application.yaml
kubectl apply -f /root/workspace/argocd-application.yaml
```

이 파일은 fork 저장소 안이 아니라 `/root/workspace/` 바로 아래에 둔다. Application은 Argo CD에게 "어느 저장소를 보라"고 알려 주는 설정이라 그 저장소 안에 두지 않는다.

### 단계 4: Application 상태 확인 `[학습자 직접]`

```bash
argocd app get worklog-backend
argocd app list
```

`Synced`, `Healthy`가 될 때까지 기다린다. 5.3에서 넣은 `buildtest1` 이미지로 backend가 뜬다. Argo CD UI에서도 같은 상태가 보인다.

```bash
kubectl get pods            # worklog-backend Pod가 Running
```

### 단계 5: selfHeal 확인 `[학습자 직접]`

Git을 거치지 않고 클러스터를 직접 바꿔서 selfHeal이 Git 상태로 되돌리는 것을 본다. `deploy_manifest/worklog-backend.yaml`에는 `replicas: 1`이 지정돼 있다.

```bash
kubectl scale deployment worklog-backend --replicas=3
kubectl get pods -l app=worklog-backend      # 새 Pod 2개가 Pending으로 생긴다
kubectl get pods -l app=worklog-backend      # 몇 초 뒤 다시 보면 2개가 Terminating이고 1개만 남는다
kubectl get deployment worklog-backend       # READY 1/1
argocd app get worklog-backend               # MESSAGE에 deployment.apps/worklog-backend configured
```

Argo CD가 클러스터의 `replicas: 3`과 Git의 `replicas: 1`이 다른 것을 감지하고 Git 상태로 되돌렸다. 되돌리기까지 약 2초라 첫 `get pods`에서 이미 Terminating이 보일 수도 있다.
7.3부터 7.6까지는 kubectl로 직접 바꾸는 실습이라 이 기능을 먼저 끈다(7.3 단계 1).

## 주의사항

- ⛔ AI가 하지 말 것: 프롬프트에 `[채우기: ...]`가 남은 채로 들어오면 짐작해 작성하거나 이 파일의 예시를 넣지 말 것. 학습자에게 작성해 달라고 되묻는다
- ✅ 학습자가 작성한 줄은 표현을 예시로 바꾸지 말고 그대로 따른다. 뜻이 예시와 다르면 파일을 만든 뒤 어디가 다른지 알려 준다
- ⛔ AI가 하지 말 것: GitHub token을 묻거나 대신 입력하지 말 것
- ⛔ AI가 하지 말 것: Application 파일을 fork 저장소(`/root/workspace/worklog-backend/`) 안에 저장하지 말 것
- ⛔ AI가 하지 말 것: `deploy_manifest/` 경로를 다른 경로로 바꾸지 말 것 (6.7~6.8 파이프라인, 10.9와 연동)
- ✅ AI가 해도 됨: Application manifest 작성, selfHeal/prune 설명
- ✅ AI가 해도 됨: Argo CD App of Apps 패턴 등 심화 개념 설명 (질문 시)
- ⚠️ `deploy_manifest/` 폴더는 학습자 fork 저장소에 있어야 함 (강의 키트 저장소 아님)
