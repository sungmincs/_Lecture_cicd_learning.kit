# 6.3 Argo CD 설치

> **학습자 진입 방식**:
> - `[학습자 직접]`: install.sh 실행, kubectl 확인 명령
> - `[AI 프롬프트]`: HTTPRoute 구성 내용 설명, 트러블슈팅

## 사전 조건

- ch5 완료 (fork 저장소에 `deploy_manifest/` 존재, ch5.3 단계 3)
- NGINX Gateway Fabric과 Gateway `nginx-gateway`(default 네임스페이스) 동작 중 (ch2에서 설치, ch3.6에서 사용)
- 컨트롤 플레인 노드에 root로 접속해 있음 (`ssh root@192.168.1.10`). 이 절의 명령은 모두 노드에서 친다

## 실행 지침

### 단계 1: install.sh 실행 `[학습자 직접]`

강의 키트에 제공된 스크립트를 실행한다.

```bash
cd /root/_Lecture_cicd_learning.kit/ch6/6.3
bash install.sh
```

> ⚠️ **반드시 `ch6/6.3/` 디렉토리에서 실행**해야 합니다. install.sh가 `./argocd-manifest.yaml` 등 상대경로를 사용하므로, 루트에서 `bash ch6/6.3/install.sh`로 실행하면 파일을 찾지 못합니다.
>
> 스크립트 내용: argocd 네임스페이스 생성 → Argo CD v3.4.3 설치(server-side apply) → 알림 카탈로그 적용 → HTTPRoute와 ReferenceGrant 적용

### 단계 2: 설치 완료 확인 `[학습자 직접]`

```bash
kubectl get pods -n argocd
kubectl get httproute argocd -n default
kubectl get referencegrant argocd-from-default -n argocd
```

모든 Pod가 `Running` 상태인지 확인한다.
HTTPRoute는 Gateway가 있는 default 네임스페이스에, ReferenceGrant는 argocd 네임스페이스에 있다.

### 단계 3: HTTPRoute 구성 이해 `[AI 프롬프트]`

> "컨트롤 플레인 노드의 `/root/_Lecture_cicd_learning.kit/ch6/6.3/argocd-httproute.yaml`을 보여주고, 각 필드가 어떤 역할을 하는지 설명해줘."

> "Argo CD가 HTTPRoute로 노출되는 구조를 Gateway API 관점에서 설명해줘."

### 단계 4: 초기 admin 비밀번호 확인 `[학습자 직접]`

```bash
kubectl get secret argocd-initial-admin-secret -n argocd \
  -o jsonpath="{.data.password}" | base64 -d && echo
```

이 값은 6.4의 UI와 CLI 로그인, 6.8의 Jenkins Credentials에 쓴다. AI 대화창에 붙여 넣지 않는다.
