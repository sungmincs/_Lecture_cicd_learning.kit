> **학습자 진입 방식**:
> - `[학습자 직접]`: GitLab Variables 등록 (GITLAB_TOKEN 포함), git push
> - `[AI 프롬프트]`: .gitlab-ci.yml 작성 ([skip ci] commit + GITLAB_TOKEN push)

## 사전 조건

- ch5/5.7 완료 (기본 빌드 파이프라인 동작 확인)
- ch6/6.5 완료 (Argo CD Application 생성, `deploy_manifest/` 경로 등록)

## 실행 지침

### 단계 1: GitLab CI Variables 등록 `[학습자 직접]`

저장소 → Settings → CI/CD → Variables → Add variable

| 변수명 | 값 | 설명 |
|---|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub username | ch5에서 이미 등록 |
| `DOCKERHUB_TOKEN` | Docker Hub Access Token | ch5에서 이미 등록 |
| `GITLAB_TOKEN` | GitLab Personal Access Token | deploy_manifest/ push용 신규 등록 |

> **GITLAB_TOKEN 발급**: GitLab → User Settings → Access Tokens → New token
> - Scopes: `write_repository`

### 단계 3: [skip ci] commit 개념 이해 `[AI 프롬프트]`

> "deploy_manifest/를 같은 저장소에 push하면 파이프라인이 무한 루프에 빠질 수 있는데, GitLab에서 이를 방지하는 방법을 설명해줘."

### 단계 4: git push + 파이프라인 확인 `[학습자 직접]`

```bash

```

GitLab → CI/CD → Pipelines에서 각 stage 성공 여부 확인

### 단계 5: Argo CD 자동 sync 확인 `[학습자 직접]`

```bash

```

## 검증 중 발견된 이슈 (강의자 참고)

- **GitLab fork 레포 `pyproject.toml` 미동기화**: GitLab fork 레포의 `pyproject.toml`이 `fastapi>=0.111.0`인 경우 빌드된 이미지에서 `fastapi run` 커맨드 실패. `fastapi[standard]>=0.111.0`으로 변경 후 `uv lock` 재생성 필요.
  - 증상: `RuntimeError: To use the fastapi command, please install "fastapi[standard]"`
  - 해결: GitLab 레포의 `pyproject.toml`에서 `fastapi>=0.111.0` → `fastapi[standard]>=0.111.0` 변경

- **GitLab fork `deploy_manifest`에 `worklog-mongodb-creds` Secret 정의 누락 (run-15 발견)**: GitLab fork의 `deploy_manifest/worklog-backend.yaml`이 `worklog-mongodb-creds` Secret을 **참조만** 하고 `kind: Secret` 정의를 포함하지 않으면(GitHub 판 `ch5/5.3/deploy_manifest/`에는 포함), Argo CD가 이 매니페스트로 sync하며 `prune`할 때 Secret을 클러스터에서 제거한다. 이미 떠 있던 Pod는 시작 시 env를 캐시해 살아있지만, 이후 새 Pod 생성(롤아웃·재배포) 시 `CreateContainerConfigError: secret "worklog-mongodb-creds" not found`로 기동 실패한다.
  - 증상: 신규 Pod `CreateContainerConfigError`, describe에 `secret "worklog-mongodb-creds" not found`.
  - 원인: GitLab fork의 `deploy_manifest`가 GitHub 판(Secret 포함)과 어긋남.
  - 해결: GitLab fork의 `deploy_manifest/worklog-backend.yaml`에도 GitHub 판과 동일하게 `kind: Secret`(worklog-mongodb-creds) 블록을 포함시킨다(`ch5/5.3/deploy_manifest/worklog-backend.yaml`을 단일 출처로 복사 권장). 임시 복구는 `kubectl create secret generic worklog-mongodb-creds --from-literal=username=root --from-literal=password=mypassw0rd`.

- **build 단계 `docker buildx rm` 추가 권장**: `docker buildx create` 시 이름 충돌 방지를 위해 `docker buildx rm mybuilder 2>/dev/null || true` 선행 (참조 파일에 이미 반영됨).

- **`[skip ci]` workflow rule**: `workflow.rules`에 `$CI_COMMIT_MESSAGE !~ /\[skip ci\]/` 조건을 추가해야 deploy stage commit이 새 파이프라인을 트리거하지 않음.

- ⛔ AI가 하지 말 것: `[skip ci]` 없이 deploy_manifest/ commit하는 파이프라인 작성
- ⛔ AI가 하지 말 것: `deploy_manifest/` 경로를 다른 경로로 바꾸지 말 것
- ✅ AI가 해도 됨: .gitlab-ci.yml 작성
- ✅ AI가 해도 됨: GITLAB_TOKEN 발급 경로 및 scope 안내
- ✅ AI가 해도 됨: [skip ci] 무한 루프 방지 원리 설명
- ✅ AI가 해도 됨: git push 인증 오류 원인 분석
