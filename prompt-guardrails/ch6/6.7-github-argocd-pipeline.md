# 6.7 [GitHub] Argo CD 파이프라인 구현

> **학습자 진입 방식**:
> - `[학습자 직접]`: GitHub Secrets 등록, write 권한 활성화, git push
> - `[AI 프롬프트]`: 파이프라인 yaml 작성 (build + deploy_manifest 업데이트 + git push)

## 사전 조건

- ch5/5.3 또는 5.4 완료 (기본 빌드 파이프라인 동작 확인)
- ch6/6.5 완료 (Argo CD Application 생성, `deploy_manifest/` 경로 등록)
- 학습자 fork 저장소에 `deploy_manifest/` 폴더 존재

## 실행 지침

### 단계 1: GitHub Actions write 권한 활성화 `[학습자 직접]`

파이프라인에서 저장소에 git push하려면 write 권한이 필요하다.

저장소 → Settings → Actions → General → Workflow permissions
→ **Read and write permissions** 선택 → Save

> ⚠️ 이 설정 없이 git push 단계에서 `403 Permission denied` 오류 발생

### 단계 2: GitHub Secrets 확인/추가 `[학습자 직접]`

저장소 → Settings → Secrets and variables → Actions

| Secret 이름 | 값 |
|---|---|
| `DOCKERHUB_TOKEN` | Docker Hub Access Token (ch5에서 이미 등록) |

> `DOCKERHUB_USERNAME`은 파이프라인 yaml에 직접 입력하거나 Secret으로 추가

### 단계 3: 파이프라인 yaml 작성 `[AI 프롬프트]`

> "worklog-backend GitHub Actions 파이프라인을 Argo CD GitOps 방식으로 만들어줘.
> - 1단계: Docker 이미지 빌드 및 push (tag: `<dockerhub_username>/worklog-backend:<git-sha>`)
> - 2단계: deploy_manifest/deployment.yaml의 image 필드를 새 tag로 업데이트
> - 3단계: 변경된 deploy_manifest/를 같은 저장소에 git push
> - Docker Hub username: `<dockerhub_username>`
> - write 권한은 이미 활성화되어 있음"

✅ 정답 파일 (완성 후 비교): `ch6/6.7/1.build-and-argocd-sync.yaml`

### 단계 4: deploy_manifest/deployment.yaml image 필드 확인 `[학습자 직접]`

파이프라인이 업데이트할 대상 파일의 image 필드 형식을 확인한다.

```yaml
# deploy_manifest/deployment.yaml 예시
containers:
  - name: worklog-backend
    image: <dockerhub_username>/worklog-backend:latest  # 이 부분이 업데이트됨
```

### 단계 5: git push + 파이프라인 확인 `[학습자 직접]`

```bash
git add .github/workflows/
git commit -m "add: argocd gitops pipeline"
git push
```

GitHub → Actions 탭에서 각 job 성공 여부 확인

### 단계 6: Argo CD 자동 sync 확인 `[학습자 직접]`

```bash
argocd app get worklog-backend
```

파이프라인이 deploy_manifest/를 업데이트하면 Argo CD가 자동으로 클러스터에 반영하는지 확인한다.

### 단계 7: 파이프라인 흐름 설명 `[AI 프롬프트]`

> "방금 만든 파이프라인에서 image tag를 git SHA로 쓰는 이유와, Argo CD가 변경을 감지하는 흐름을 설명해줘."

## 검증 중 발견된 이슈 (강의자 참고)

- **deploy 단계 `git push` 충돌**: 저장소에 다른 워크플로우가 동시에 실행되는 경우 `git push` 전에 이미 다른 커밋이 쌓여 `rejected - fetch first` 에러 발생.
  **수정**: `git push origin main` 직전에 `git pull --rebase origin main` 추가 (참조 파일에 이미 반영됨).

- **GitHub Actions write 권한 미설정**: deploy 단계의 `git push`가 403 Permission denied로 실패.
  **수정**: 저장소 → Settings → Actions → General → Workflow permissions → Read and write permissions 선택.

## 주의사항

- ⛔ AI가 하지 말 것: GitHub Actions write 권한 설정을 대신 수행하려 하지 말 것
- ⛔ AI가 하지 말 것: `deploy_manifest/` 경로를 다른 경로로 바꾸지 말 것
- ✅ AI가 해도 됨: 파이프라인 yaml 작성 (build + image tag 업데이트 + git push 포함)
- ✅ AI가 해도 됨: write 권한 활성화 경로 안내
- ✅ AI가 해도 됨: git push 403 오류 원인 분석
- ✅ AI가 해도 됨: `${{ github.sha }}` 등 GitHub Actions 내장 변수 설명
- ⚠️ imagePullSecrets `dockerhub-creds` Secret이 클러스터에 있어야 배포 후 이미지 pull 가능
- ⚠️ **`paths-ignore: deploy_manifest/**` 설정 시 빈 커밋으로는 파이프라인 미트리거**: deploy job이 manifest를 변경·push하면 `paths-ignore`에 의해 다음 push가 차단됨 — 정상 동작. 파이프라인을 다시 트리거하려면 소스 코드 파일을 실제로 변경해야 함.
- ⚠️ **(run-16, #92) deploy_manifest의 IMAGE_TAG env에 `# IMAGE_TAG` inline 주석 필수**: deploy job의 sed가 `s|value: .* # IMAGE_TAG|value: ${SHA} # IMAGE_TAG|` 패턴으로 매칭하므로, `deploy_manifest/worklog-backend.yaml`의 `value:` 라인 끝에 `# IMAGE_TAG` 주석이 있어야 갱신됨(없으면 IMAGE_TAG env가 옛 값으로 남음). 정답 `ch5/5.3/deploy_manifest/worklog-backend.yaml`에 반영됨.
