# 7.5 Blue-Green 배포 실습

> **학습자 진입 방식**:
> - `[학습자 직접]`: kubectl apply, rollout 상태 확인, 이미지 업데이트, promote
> - `[AI 프롬프트]`: Rollout yaml 작성 (Blue-Green 전략), Active/Preview Service yaml 작성

## 사전 조건

- ch7/7.4 완료 (Argo Rollouts 컨트롤러 및 kubectl 플러그인 설치)
- Docker Hub에 worklog-backend 이미지가 push된 상태
- 기존 worklog-backend Deployment가 있다면 먼저 삭제 필요

> ⚠️ Deployment와 Rollout이 동일한 이름을 사용하면 충돌한다.
> `kubectl delete deployment worklog-backend` 후 진행한다.

## 실행 지침

### 단계 1: Blue-Green Rollout yaml 작성 `[AI 프롬프트]`

> "Argo Rollouts Blue-Green 전략으로 worklog-backend를 배포하는 Rollout yaml 만들어줘.
> - replicas: 3, imagePullSecrets: dockerhub-creds
> - Docker Hub username: `<dockerhub_username>`, image tag: `<image_tag>`
> - activeService: worklog-backend-active, previewService: worklog-backend-preview
> - autoPromotionEnabled: false (수동 승격)
> - MongoDB 연결 환경변수 포함 (worklog-mongodb-creds Secret 참조)"

✅ 정답 파일 (완성 후 비교): `ch7/7.5/1.worklog-backend-rollout-bluegreen.yaml`

### 단계 2: Active/Preview 서비스 yaml 작성 `[AI 프롬프트]`

> "worklog-backend-active, worklog-backend-preview 두 개의 Kubernetes Service yaml 만들어줘.
> selector: app=worklog-backend, port: 8000"

✅ 정답 파일 (완성 후 비교): `ch7/7.5/2.worklog-backend-services-bluegreen.yaml`

### 단계 3: Blue-Green 리소스 배포 `[학습자 직접]`

```bash
kubectl apply -f 1.worklog-backend-rollout-bluegreen.yaml
kubectl apply -f 2.worklog-backend-services-bluegreen.yaml
kubectl argo rollouts get rollout worklog-backend --watch
```

기대 결과: 3개의 Pod Running, Active 서비스에 연결

### 단계 4: 이미지 업데이트로 Blue-Green 배포 트리거 `[학습자 직접]`

```bash
kubectl argo rollouts set image worklog-backend worklog-backend=<dockerhub_username>/worklog-backend:<new_tag>
kubectl argo rollouts get rollout worklog-backend --watch
```

기대 결과: 새 ReplicaSet 생성, Preview 서비스에 연결, Active는 이전 버전 유지

### 단계 5: Preview 확인 후 수동 Promote `[학습자 직접]`

```bash
kubectl argo rollouts promote worklog-backend
kubectl argo rollouts get rollout worklog-backend --watch
kubectl get pods
kubectl get svc
```

기대 결과: Active 서비스가 새 버전으로 전환, 이전 버전 Pod 제거

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<image_tag>` | 초기 배포 이미지 태그 | ❌ 반드시 확인 |
| `<new_tag>` | Blue-Green 전환할 새 이미지 태그 | ❌ 반드시 확인 |

## 주의사항

- ⛔ `<dockerhub_username>`을 임의로 채우지 말 것
- ⛔ 기존 Deployment와 Rollout 이름이 동일하면 충돌 — 기존 Deployment를 먼저 삭제
- ✅ `autoPromotionEnabled: false`로 설정하여 수동 Promote 과정을 직접 체험
- ✅ Preview 서비스로 접속하여 새 버전을 사전 확인한 후 Active로 전환
- ✅ `kubectl argo rollouts abort worklog-backend`로 배포를 중단하고 이전 버전으로 롤백 가능
