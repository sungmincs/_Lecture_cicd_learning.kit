# 7.6 Canary 배포 실습

> **학습자 진입 방식**:
> - `[학습자 직접]`: Blue-Green 리소스 정리, kubectl apply, 이미지 업데이트, promote
> - `[AI 프롬프트]`: Canary 전략 Rollout yaml 작성, Service yaml 작성

## 사전 조건

- ch7/7.4 완료 (Argo Rollouts 설치)
- ch7/7.5 완료 (Blue-Green 실습) — 7.5의 Rollout/Service 리소스를 먼저 삭제해야 함
- Docker Hub에 worklog-backend 이미지가 2개 이상의 태그로 존재

## 실행 지침

### 단계 1: Blue-Green 리소스 정리 `[학습자 직접]`

```bash
kubectl delete rollout worklog-backend
kubectl delete svc worklog-backend-active worklog-backend-preview
```

### 단계 2: Canary Rollout yaml 작성 `[AI 프롬프트]`

> "Argo Rollouts Canary 전략으로 worklog-backend를 배포하는 Rollout yaml 만들어줘.
> - replicas: 5, imagePullSecrets: dockerhub-creds
> - Docker Hub username: `<dockerhub_username>`, image tag: `<image_tag>`
> - Canary 단계: 20%(수동 pause) → 40%(30s) → 60%(30s) → 80%(30s) → 100%
> - MongoDB 연결 환경변수 포함 (worklog-mongodb-creds Secret 참조)"

✅ 정답 파일 (완성 후 비교): `ch7/7.6/1.worklog-backend-rollout-canary.yaml`

### 단계 3: Canary용 Service yaml 작성 `[AI 프롬프트]`

> "worklog-backend Service yaml 만들어줘. selector: app=worklog-backend, port: 8000"

✅ 정답 파일 (완성 후 비교): `ch7/7.6/2.worklog-backend-service-canary.yaml`

### 단계 4: Canary 리소스 배포 `[학습자 직접]`

```bash
kubectl apply -f 1.worklog-backend-rollout-canary.yaml
kubectl apply -f 2.worklog-backend-service-canary.yaml
kubectl argo rollouts get rollout worklog-backend --watch
```

### 단계 5: 이미지 업데이트로 Canary 배포 트리거 `[학습자 직접]`

```bash
kubectl argo rollouts set image worklog-backend worklog-backend=<dockerhub_username>/worklog-backend:<new_tag>
kubectl argo rollouts get rollout worklog-backend --watch
```

기대 결과: Canary Pod 생성, 첫 번째 단계(20%)에서 수동 pause 대기

### 단계 6: Canary 단계 수동 진행 `[학습자 직접]`

```bash
kubectl argo rollouts promote worklog-backend
```

기대 결과: 40% → 30초 후 60% → 30초 후 80% → 30초 후 100% 순차 진행

### 단계 7: 최종 검증 `[학습자 직접]`

```bash
kubectl get pods
kubectl argo rollouts get rollout worklog-backend
```

기대 결과: 5개 Pod 모두 새 버전, Healthy 상태

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<image_tag>` | 초기 배포 이미지 태그 | ❌ 반드시 확인 |
| `<new_tag>` | Canary 배포할 새 이미지 태그 | ❌ 반드시 확인 |

## 주의사항

- ⛔ `<dockerhub_username>`을 임의로 채우지 말 것
- ⛔ 7.5의 Blue-Green 리소스를 먼저 삭제해야 함 — 같은 이름의 Rollout 충돌 방지
- ✅ 첫 번째 `pause: {}`는 무기한 대기 — 반드시 수동 `promote` 실행 필요
- ✅ 이후 `pause: {duration: 30s}`는 30초 후 자동 진행
- ✅ `kubectl argo rollouts abort worklog-backend`로 언제든 Canary를 중단하고 이전 버전으로 롤백 가능
- ✅ Rolling Update(7.3), Blue-Green(7.5)과 비교하여 트래픽 제어 방식의 차이를 이해
