# 7.10 [GitLab CI] 마이크로서비스 배포 파이프라인

> **학습자 진입 방식**:
> - `[학습자 직접]`: GitLab CI Variables 등록, .gitlab-ci.yml git push
> - `[AI 프롬프트]`: frontend/backend 각 .gitlab-ci.yml 작성

## 사전 조건

- ch5/5.7 또는 5.8 완료 (GitLab CI 파이프라인 이해)
- ch7/7.7 완료 (MongoDB, Backend, Frontend가 K8s에 배포된 상태)
- GitLab에 worklog-frontend-mock, worklog-backend 프로젝트 생성 완료
- GitLab Runner에 privileged 모드 설정 완료 (Docker-in-Docker 필요)

> ⚠️ worklog-frontend-mock은 GitLab에 별도 프로젝트로 생성해야 한다.
> GitHub의 fork를 GitLab에 mirror하거나 새로 push한다.

## 실행 지침

### 단계 1: GitLab CI Variables 등록 `[학습자 직접]`

두 프로젝트 모두에서: Settings → CI/CD → Variables → Add variable

| 변수명 | 값 | Protected |
|---|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub username | ✅ |
| `DOCKERHUB_TOKEN` | Docker Hub Access Token | ✅ |
| `GITLAB_TOKEN` | GitLab Personal Access Token (repo write 권한) | ✅ |

### 단계 2: Frontend .gitlab-ci.yml 작성 `[AI 프롬프트]`

> "worklog-frontend-mock GitLab CI 파이프라인 만들어줘.
> - main 브랜치 push 시 트리거, [skip ci] 커밋은 제외
> - stages: build, deploy
> - build stage: docker:24 + docker:24-dind, multi-arch 빌드 (linux/amd64, linux/arm64, docker buildx)
> - Docker Hub username: `<dockerhub_username>`, image: `<dockerhub_username>/worklog-frontend-mock`
> - 이미지 태그: CI_COMMIT_SHA 앞 8자리
> - deploy stage: alpine, deploy_manifest/worklog-frontend.yaml의 image 필드 업데이트 후 git push
> - GitLab 저장소 경로: `<gitlab_username>/worklog-frontend-mock`
> - git push 커밋 메시지에 [skip ci] 포함하여 무한 루프 방지"

✅ 정답 파일 (완성 후 비교): `ch7/7.10/1.frontend-build-deploy.yml`

### 단계 3: Backend .gitlab-ci.yml 작성 `[AI 프롬프트]`

> "worklog-backend GitLab CI 파이프라인 만들어줘.
> - main 브랜치 push 시 트리거, [skip ci] 커밋은 제외
> - stages: test, build, deploy
> - test stage: ghcr.io/astral-sh/uv:python3.14-bookworm-slim, uv sync, TESTING=true, pytest

> - Docker Hub username: `<dockerhub_username>`, image: `<dockerhub_username>/worklog-backend`
> - deploy stage: alpine, deploy_manifest/worklog-backend.yaml의 image 필드 및 IMAGE_TAG 환경변수 업데이트 후 git push
> - GitLab 저장소 경로: `<gitlab_username>/worklog-backend`
> - git push 커밋 메시지에 [skip ci] 포함하여 무한 루프 방지"

✅ 정답 파일 (완성 후 비교): `ch7/7.10/2.backend-build-deploy.yml`

### 단계 4: 파이프라인 적용 `[학습자 직접]`

```bash
# Frontend 프로젝트에서
cp ~/_Lecture_cicd_learning.kit/ch7/7.10/1.frontend-build-deploy.yml .gitlab-ci.yml
git add .gitlab-ci.yml
git commit -m "cicd: add frontend GitLab CI pipeline"
git push origin main

# Backend 프로젝트에서
cp ~/_Lecture_cicd_learning.kit/ch7/7.10/2.backend-build-deploy.yml .gitlab-ci.yml
git add .gitlab-ci.yml
git commit -m "cicd: add backend GitLab CI pipeline"
git push origin main
```

### 단계 5: 파이프라인 실행 결과 확인 `[학습자 직접]`

- GitLab → CI/CD → Pipelines에서 각 파이프라인 성공 확인
- Frontend: build → deploy 성공

접속 확인: `http://worklog-frontend.myk8s.local`

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<gitlab_username>` | 학습자의 GitLab username | ❌ 반드시 확인 |

## 주의사항

- ⛔ `<dockerhub_username>`, `<gitlab_username>`을 임의로 채우지 말 것
- ⛔ GitLab Runner에 privileged 모드가 설정되어 있어야 Docker-in-Docker(dind) 동작
- ⛔ deploy stage의 git push 커밋 메시지에 `[skip ci]` 가 없으면 파이프라인이 무한 루프에 빠짐
- ✅ `DOCKER_CONFIG`를 `/tmp/docker_config`로 지정하여 컨테이너 내 Docker 인증 충돌 방지
- ✅ `GITLAB_TOKEN`은 protected variable로 등록하여 main 브랜치에서만 사용
- ✅ 8.2에서 배포한 리소스가 존재해야 Argo CD sync가 동작
- ✅ Frontend와 Backend는 독립 프로젝트에서 독립 파이프라인으로 운영
