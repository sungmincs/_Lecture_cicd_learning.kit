# 7.3 Rolling Update 배포 실습

> **학습자 진입 방식**:
> - `[학습자 직접]`: kubectl apply, rollout status 확인, 이미지 업데이트, 롤백
> - `[AI 프롬프트]`: Rolling Update 전략 Deployment yaml 작성

## 사전 조건

- ch6 완료 (Argo CD 설치 및 파이프라인 구성)
- Docker Hub에 worklog-backend 이미지가 2개 이상의 태그로 존재
- Kubernetes 클러스터 접속 가능
- Argo CD Application이 있다면 sync 일시 중지 필요 (수동 kubectl apply 실습이므로)

> ⚠️ Argo CD가 자동 sync 중이라면 수동으로 배포한 변경이 즉시 되돌려질 수 있다.
> Argo CD UI 또는 CLI에서 해당 Application을 Suspend(disable auto-sync)한 후 실습한다.

## 실행 지침

### 단계 1: Rolling Update Deployment yaml 작성 `[AI 프롬프트]`

> "worklog-backend를 Rolling Update 전략으로 배포하는 Kubernetes Deployment yaml 만들어줘.
> - replicas: 3, maxSurge: 1, maxUnavailable: 0
> - imagePullSecrets: dockerhub-creds
> - Docker Hub username: `<dockerhub_username>`, image tag: `<image_tag>`
> - MongoDB 연결 환경변수 포함 (MONGO_HOST, worklog-mongodb-creds Secret 참조)
> - liveness/readiness probe: /health (port 80)"

✅ 정답 파일 (완성 후 비교): `ch7/7.3/1.worklog-backend-deployment-rolling.yaml`

### 단계 2: Deployment 배포 `[학습자 직접]`

```bash
kubectl apply -f 1.worklog-backend-deployment-rolling.yaml
kubectl get deployment worklog-backend
kubectl get pods -l app=worklog-backend
```

### 단계 3: Rolling Update 전략 설정 확인 `[학습자 직접]`

```bash
kubectl describe deployment worklog-backend | grep -A5 Strategy
```

기대 결과: RollingUpdate, maxSurge=1, maxUnavailable=0 확인

### 단계 4: 이미지 업데이트로 Rolling Update 트리거 `[학습자 직접]`

> ⚠️ **`<new_tag>` 선택 주의**: 반드시 Docker Hub에 실제로 존재하는 태그를 사용해야 합니다.
> ch3.5에서 `buildtest1`으로 빌드+push했으므로, `buildtest1` 재사용 또는 `buildtest2`를 ch3.5와 동일하게 직접 빌드+push 후 진행:
> ```bash
> # buildtest2 이미지가 없으면 먼저 빌드
> cd /root/workspace/worklog-backend
> docker build . -t <dockerhub_username>/worklog-backend:buildtest2
> docker push <dockerhub_username>/worklog-backend:buildtest2
> ```

```bash
kubectl set image deployment/worklog-backend worklog-backend=<dockerhub_username>/worklog-backend:<new_tag>
kubectl rollout status deployment/worklog-backend
```

### 단계 5: 롤백 실습 `[학습자 직접]`

```bash
kubectl rollout undo deployment/worklog-backend
kubectl rollout status deployment/worklog-backend
kubectl rollout history deployment/worklog-backend
```

### 단계 6: 리소스 정리 `[학습자 직접]`

```bash
kubectl delete deployment worklog-backend
```

> ⚠️ 7.4(Argo Rollouts 설치) 이후 실습을 위해 반드시 정리한다.

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<dockerhub_username>` | 학습자의 Docker Hub username | ❌ 반드시 확인 |
| `<image_tag>` | 초기 배포 이미지 태그 | ❌ 반드시 확인 |
| `<new_tag>` | 업데이트할 새 이미지 태그 | ❌ 반드시 확인 |

## 주의사항

- ⛔ `<dockerhub_username>`을 임의로 채우지 말 것
- ⛔ Argo CD 자동 sync가 켜져 있으면 수동 배포 결과가 즉시 되돌려질 수 있음 — 실습 전 suspend 필요
- ✅ Rolling Update는 K8s 기본 기능 — Argo Rollouts 없이 동작
- ✅ 이 실습은 7.5(Blue-Green), 7.6(Canary)와 비교하기 위한 베이스라인
- ✅ `kubectl rollout history`로 이전/현재 리비전 확인 가능
