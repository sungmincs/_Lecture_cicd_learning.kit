# 7.4 Argo Rollouts 설치

> **학습자 진입 방식**:
> - `[학습자 직접]`: 설치 스크립트 실행, 설치 검증
> - `[AI 프롬프트]`: 설치 스크립트 작성 (arm64 자동 감지 포함)

## 사전 조건

- ch6 완료 (Argo CD 설치)
- ch7/7.3 완료 (worklog-backend Deployment를 지운 상태, `/root/ch7/` 폴더가 있음)

## 실행 지침

### 단계 1: 설치 스크립트 작성 `[AI 프롬프트]`

> "Argo Rollouts v1.9.0을 설치하는 bash 스크립트를 만들어서 컨트롤 플레인 노드의 `/root/ch7/install_argo_rollouts.sh`로 저장해줘. 실행은 내가 할게.
> - argo-rollouts 네임스페이스 생성
> - 컨트롤러 설치 (공식 릴리스의 install.yaml)
> - kubectl 플러그인을 `/usr/local/bin/kubectl-argo-rollouts`로 설치 (arm64와 amd64를 자동 감지)
> - 마지막에 `kubectl argo rollouts version` 출력"

✅ 정답 파일 (완성 후 비교): `ch7/7.4/install_argo_rollouts.sh`

### 단계 2: 설치 스크립트 실행 `[학습자 직접]`

```bash
cd /root/ch7
bash install_argo_rollouts.sh
```

### 단계 3: 설치 검증 `[학습자 직접]`

```bash
kubectl -n argo-rollouts rollout status deployment/argo-rollouts      # 컨트롤러가 뜰 때까지 기다린다
kubectl argo rollouts version
kubectl get pods -n argo-rollouts
kubectl get crd rollouts.argoproj.io
```

기대 결과: 버전 `v1.9.0`, argo-rollouts Pod Running, Rollout CRD가 있음

## 주의사항

- ⛔ AI가 하지 말 것: 버전을 `latest`나 다른 값으로 바꾸지 말 것. v1.9.0으로 고정한다
- ⛔ AI가 하지 말 것: 스크립트를 대신 실행하지 말 것
- ✅ AI가 해도 됨: 스크립트 작성, 설치 오류 해석
- ✅ Argo Rollouts는 Argo CD 없이도 동작한다. 함께 쓰면 Git에 적은 Rollout을 Argo CD가 배포한다
- ⚠️ Deployment와 Rollout은 별개 리소스다. 같은 이름과 라벨로 둘 다 있으면 Pod가 양쪽에서 뜬다. 그래서 7.3 단계 7에서 Deployment를 지웠다
