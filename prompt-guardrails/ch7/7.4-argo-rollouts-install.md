# 7.4 Argo Rollouts 설치

> **학습자 진입 방식**:
> - `[학습자 직접]`: 설치 스크립트 실행, 설치 검증
> - `[AI 프롬프트]`: 설치 스크립트 작성 (arm64 자동 감지 포함)

## 사전 조건

- ch6 완료 (Argo CD 설치 및 파이프라인 구성)
- Kubernetes 클러스터 접속 가능 (kubectl 동작 확인)
- 클러스터에 admin 권한 보유
- 7.3에서 생성한 worklog-backend Deployment 정리 완료

## 실행 지침

### 단계 1: 설치 스크립트 작성 `[AI 프롬프트]`

> "Argo Rollouts v1.9.0을 설치하는 bash 스크립트 만들어줘.
> - argo-rollouts 네임스페이스 생성
> - 컨트롤러 설치 (공식 install.yaml)
> - kubectl 플러그인 설치 (arm64 환경 자동 감지 포함)
> - 설치 검증 (버전 출력)"

✅ 정답 파일 (완성 후 비교): `ch7/7.4/install_argo_rollouts.sh`

### 단계 2: 설치 스크립트 실행 `[학습자 직접]`

```bash
bash install_argo_rollouts.sh
```

### 단계 3: 설치 검증 `[학습자 직접]`

```bash
kubectl argo rollouts version
kubectl get pods -n argo-rollouts
kubectl get crd rollouts.argoproj.io
```

기대 결과: argo-rollouts Pod Running, Rollout CRD 존재, 버전 정보 출력

## 주의사항

- ⛔ 플러그인 바이너리 아키텍처가 실행 환경과 일치하는지 확인 — 스크립트가 arm64 자동 감지
- ⛔ 기존 Deployment와 Rollout 이름이 동일하면 충돌 — 7.3 리소스를 먼저 삭제
- ✅ `install_argo_rollouts.sh`로 전체 설치를 한 번에 수행 가능
- ✅ Argo Rollouts는 Argo CD와 독립적으로 동작하지만, 함께 사용하면 GitOps 기반 고급 배포 가능
- ✅ v1.9.0 고정 버전 사용으로 재현성 보장
- ⛔ 기존 Deployment 리소스와 Rollout 리소스는 별개 — Deployment를 Rollout으로 마이그레이션할 때 기존 Deployment를 먼저 삭제해야 충돌 방지
