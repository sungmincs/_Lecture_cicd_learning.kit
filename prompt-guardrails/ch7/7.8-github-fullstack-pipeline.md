## 실행 지침

### 단계 1: GitHub Actions write 권한 활성화 `[학습자 직접]`

파이프라인에서 저장소에 git push하려면 write 권한이 필요하다.

저장소 → Settings → Actions → General → Workflow permissions
→ **Read and write permissions** 선택 → Save

> ⚠️ 두 저장소(worklog-frontend-mock, worklog-backend) 모두 설정 필요

### 단계 2: GitHub Secrets 등록 `[학습자 직접]`

두 저장소 모두에서: Settings → Secrets and variables → Actions

| Secret 이름 | 값 |
|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub username |
| `DOCKERHUB_TOKEN` | Docker Hub Access Token |

## 검증 중 발견된 이슈 (강의자 참고)

- **동시 파이프라인 실행 시 rebase 충돌**: frontend와 backend 파이프라인이 동시에 실행되면 deploy 단계에서 `git pull --rebase`가 실패할 수 있음. 두 파이프라인이 같은 repo의 `deploy_manifest/`를 동시에 업데이트할 때 발생.
  - 증상: `CONFLICT (content): Merge conflict in deploy_manifest/worklog-backend.yaml` → `error: could not apply ...`
  - 해결: 학습자 실습 시 frontend와 backend를 순차적으로 push. 일반 실습 환경에서는 동시 push가 드물어 재현 가능성 낮음.

## 주의사항

- ⛔ `<dockerhub_username>`을 임의로 채우지 말 것
- ⛔ `deploy_manifest/**`를 paths-ignore에 포함시켜야 무한 루프 방지
- ⛔ write 권한 없이 git push 시 `403 Permission denied` 오류 발생
- ✅ backend 파이프라인: git push 전 `git pull --rebase origin main` 필수 — frontend와 동시에 push 시 충돌 방지
- ✅ Frontend와 Backend는 독립 저장소에서 독립 파이프라인으로 운영
- ✅ ch7.7에서 배포한 리소스가 존재해야 Argo CD sync가 동작
