# 9.2 AI 시대에 변화하는 CI/CD (개요)

> **학습자 진입 방식**: 이론 섹션 — 실습 없음. 개념 이해 후 9.3으로 진행.

## 이 챕터에서 다루는 것

AI가 코드를 생성하는 시대에 CI/CD 파이프라인의 역할이 바뀌었다. 개발자가 직접 코드를 한 줄씩 작성하던 시대에는 "개발자가 이미 검토한 코드"라는 암묵적 신뢰가 있었다. 하지만 AI가 생성한 코드는 빠르고 그럴듯하지만, 그 품질과 보안을 보장하기 위한 자동화된 게이트가 반드시 필요하다.

## CI 게이트: 코드 품질 보장

CI(지속적 통합) 단계에서는 코드가 합쳐지기 전에 자동으로 검증한다.

| 게이트 | 도구 | 목적 |
|---|---|---|
| Lint | ruff | 코드 스타일 오류, 불필요한 임포트, 잠재적 버그 패턴 탐지 |
| Security Scan | pip-audit, gitleaks | 의존성 취약점, 코드에 노출된 시크릿(키/토큰) 탐지 |
| Test Coverage | coverage + pytest | 테스트가 커버하지 못한 코드 영역 비율 임계값 강제 |

**왜 AI 시대에 더 중요한가?**

AI는 작동하는 코드를 빠르게 생성하지만, 취약한 라이브러리 버전을 그대로 사용하거나, 하드코딩된 토큰을 남기거나, 테스트 없이 로직을 추가하는 경향이 있다. Lint/Security/Coverage 게이트는 이를 파이프라인 수준에서 자동으로 차단한다.

## CD 게이트: 배포 안전성 보장

CD(지속적 배포) 단계에서는 이미지가 클러스터에 배포되기 전/후에 안전성을 확인한다.

| 게이트 | 도구 | 목적 |
|---|---|---|
| 이미지 취약점 스캔 | Trivy | 빌드된 Docker 이미지의 OS/라이브러리 수준 취약점 탐지 |
| 수동 승인 게이트 | Argo CD syncPolicy | prod 환경 배포 전 인간의 승인 필수화 |
| 자동 롤백 | Argo Rollouts AnalysisTemplate | canary 배포 중 health check 실패 시 자동으로 이전 버전으로 복귀 |

## 이 챕터의 학습 흐름

```
9.3 Lint (ruff)
    ↓
9.4 Security Scan (pip-audit + gitleaks)
    ↓
9.5 Test Coverage 임계값 (80%)
    ↓
9.6 Trivy 이미지 취약점 스캔
    ↓
9.7 prod 수동 승인 게이트
    ↓
9.8 자동 롤백 (AnalysisTemplate)
```

9.3~9.5는 CI 강화, 9.6~9.8은 CD 강화다. 각 섹션은 GitHub Actions / Jenkins / GitLab CI 세 가지 플랫폼 모두에 적용된다.

## 사전 조건

- ch8 완료 (dev/staging/prod 멀티환경 배포 구성)
- dev, staging, prod namespace 존재
- Argo CD Application 3개 (`worklog-backend-dev`, `worklog-backend-staging`, `worklog-backend-prod`) 존재
