## 실행 지침

### 단계 1: .gitleaks.toml 설정 파일 작성 `[AI 프롬프트]`

> "gitleaks v8 형식의 .gitleaks.toml 설정 파일을 만들어줘.
> - 기본 룰셋 활성화 (`useDefault = true`)
> - `.md` 파일, `tests/`, `deploy_manifest/` 경로는 스캔 제외
> - `[allowlist]` 형태 (map) 사용 — `[[allowlist.rules]]` slice 형태 아님"

✅ 정답 파일 (완성 후 비교): `ch9/9.4/.gitleaks.toml`

> ⚠️ gitleaks v8에서 `[allowlist]` (map)와 `[[rules.allowlist]]` (slice)가 혼용되면 오류 발생. 반드시 `[allowlist]` 형태로 작성.

### 단계 2: CI 파이프라인에 Security Scan 단계 추가 `[AI 프롬프트]`

사용하는 CI 플랫폼에 맞게 아래 프롬프트를 사용한다.

**GitHub Actions:**

> "기존 CI 파이프라인에 security-scan job을 추가해줘.
> - lint job 완료 후 실행 (`needs: [lint]`)
> - pip-audit: `uv sync --extra dev` 후 `uv run pip-audit` 실행
> - gitleaks: `gitleaks/gitleaks-action@v2` 사용, `fetch-depth: 0` 필요
> - GITHUB_TOKEN secret 사용"

✅ 정답 파일: `ch9/9.4/1.security-github.yaml`

**Jenkins:**

> "기존 Jenkinsfile에 Security Scan stage를 Lint 다음에 추가해줘.
> - pip-audit: `uv run pip-audit`
> - gitleaks: curl로 최신 버전 설치 후 `/tmp/gitleaks detect --source . --config .gitleaks.toml` 실행
> - gitleaks 설치: `curl -sSfL https://github.com/gitleaks/gitleaks/releases/latest/download/gitleaks_\$(uname -s)_x64.tar.gz | tar -xz -C /tmp/`"

✅ 정답 파일: `ch9/9.4/2.security-jenkins.groovy`

**GitLab CI:**

> "기존 .gitlab-ci.yml에 security stage와 security-scan job을 lint 다음에 추가해줘.
> - image: `ghcr.io/astral-sh/uv:python3.14-bookworm-slim`
> - before_script에서 apt-get으로 curl 설치 후 gitleaks 바이너리 /usr/local/bin/에 설치
> - pip-audit + gitleaks 실행"

✅ 정답 파일: `ch9/9.4/3.security-gitlab.yml`

## 플레이스홀더

이 섹션에는 플레이스홀더가 없다. (빌드/push 없음)

## 검증 중 발견된 이슈 (강의자 참고)

- **GitLab CI `workflow.rules` [skip ci] 순서 버그**: `[skip ci]` 규칙을 마지막에 배치하면 branch 규칙이 먼저 매칭되어 실질적으로 무효화됨. 반드시 첫 번째 규칙으로 배치.
- **GitLab CI docker:27-cli → docker:24**: `docker:24` + `docker:24-dind` 사용, DinD TLS 비활성화는 job 레벨 variables로 통일. (참조 파일 반영됨)
- **GITLAB_TOKEN**: GitLab CI에서 deploy_manifest push 시 `GITLAB_TOKEN`/`gitlab.com` 사용.

## 주의사항

- ⛔ AI가 하지 말 것: `.gitleaks.toml`에서 `[[rules.allowlist]]` slice 형태 사용 (gitleaks v8 비호환)
- ⛔ AI가 하지 말 것: `gitleaks/gitleaks-action@v2` 없이 GitHub Actions에서 gitleaks 직접 설치 시도
- ✅ AI가 해도 됨: .gitleaks.toml 작성, 파이프라인 작성
- ✅ AI가 해도 됨: pip-audit 취약점 발견 시 버전 업그레이드 제안
- ✅ AI가 해도 됨: gitleaks 탐지 오탐(false positive) 원인 분석 및 allowlist 조정
- ⚠️ GitHub Actions에서 gitleaks-action은 `fetch-depth: 0` 없으면 전체 이력 스캔 안 됨
- ⚠️ Jenkins에서 gitleaks 아키텍처 확인 필요: `$(uname -s)_x64` — ARM 환경에서는 별도 처리 필요
- ⚠️ **(run-16, #95) gitleaks 탐지 시연/테스트 조건 2가지**:
  - **엔트로피 필요**: `ghp_aaaa...`처럼 반복 문자는 엔트로피 부족으로 미탐지 → **랜덤 영숫자** 가짜 키여야 탐지됨(예: `ghp_` + 무작위 36자, `sk_live_` + 무작위 24자).
  - **작업트리 스캔은 `--no-git`**: 기본 `gitleaks detect`는 git 커밋 이력만 스캔. 미커밋/작업트리 파일을 잡으려면 `detect --no-git`.
  - AWS 예제키 `AKIAIOSFODNN7EXAMPLE`는 gitleaks 기본 allowlist(문서 예제)라 영원히 미탐지 → 테스트 패턴으로 쓰지 말 것.
