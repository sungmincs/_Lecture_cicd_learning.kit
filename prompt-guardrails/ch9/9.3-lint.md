# 9.3 CI 강화 - Lint (ruff)

> **학습자 진입 방식**:
> - `[학습자 직접]`: 워크플로 상태 확인
> - `[학습자 직접 · 웹]`: GitHub Actions와 Jenkins의 실행 결과 확인
> - `[AI 프롬프트]`: ruff 설정 파일, GitHub 워크플로와 Jenkinsfile에 lint 단계 추가, push, 실패용 코드 push와 되돌리기(프롬프트는 학습자가 처음부터 작성)
>
> 9장은 한 절 안에서 GitHub Actions와 Jenkins를 함께 고친다. 파일은 모두 노드의 `/root/workspace/worklog-backend`(main 브랜치)에 있다.
> GitHub는 `.github/workflows/ci.yaml` 한 파일에 게이트를 쌓고, Jenkins는 8.6의 `Jenkinsfile`에 stage를 더한다.

요청과 계획 검토 방식은 8.3의 "8장부터 짧게 요청하고 계획을 검토한다"와 같다.

## 사전 조건

- ch8 완료 (8.6의 Jenkinsfile이 main, develop, release/1.0.0에 있고 GitHub 워크플로는 모두 꺼져 있음)
- 노드의 backend clone이 main 브랜치이고 `git pull --rebase`까지 마친 상태
- `pyproject.toml`의 dev 의존성에 `ruff`가 있음 (기준 저장소에 이미 있다)

## 실행 지침

### 단계 1: 워크플로 상태 확인 `[학습자 직접]`

ch8 워크플로가 꺼져 있는지 본다(8.5 단계 1에서 껐다). 9.3~9.5의 GitHub `ci.yaml`은 게이트만 있고 배포가 없어 Jenkins와 겹쳐도 충돌하지 않는다. 그래서 이 구간에서는 `ci.yaml`을 켜 둔 채로 Jenkins도 스캔한다. 9.6부터는 `ci.yaml`에 deploy가 붙으므로 그때 다시 정한다. 규칙과 방법은 `prompt-guardrails/shared/one-pipeline.md`.

```bash
gh workflow list --all -R <github_username>/worklog-backend      # 모두 disabled_manually
cd /root/workspace/worklog-backend && git checkout main && git pull --rebase
grep -n "ruff" pyproject.toml                                     # dev 의존성에 ruff가 보인다
```

### 단계 2: ruff 설정 파일 작성 `[AI 프롬프트]`

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
backend에 ruff lint 설정 파일 ruff.toml을 만들어줘. 파이프라인에서 스타일과 잠재 버그를 검사하려는 거야. 파일을 만들기 전에 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- 파일: /root/workspace/worklog-backend/ruff.toml
- E, F, W, I 룰 활성화
- E501(줄 길이)은 무시
- 끝나면: 파일을 보여줘. 커밋 전에 멈춰줘.

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| 룰 E, F, W, I 활성화 | 검사 범위가 기본값으로 감소 |
| E501(줄 길이)은 무시 | 기존 코드의 긴 줄이 모두 실패 |

계획이 맞으면 학습자가 "계획대로 진행해줘"(파일이면 "계획대로 만들어줘")라고 한다. 빠진 항목이 있으면 학습자가 그 항목만 1줄로 요청한다.

✅ 정답 파일 (완성 후 비교): `ch9/9.3/ruff.toml`

### 단계 3: GitHub 워크플로에 lint job `[AI 프롬프트]`

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
ci.yaml을 새로 만들어 ruff lint job을 넣어줘. 9장의 게이트를 이 파일에 하나씩 쌓으려는 거야. 파일을 만들기 전에 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- 파일: /root/workspace/worklog-backend/.github/workflows/ci.yaml
- 트리거: main 대상 PR, main, develop, release/* push, deploy_manifest/** 변경은 제외
- setup-uv 액션(uv 0.11.18, Python 3.14)
- uv sync --extra dev 뒤 uv run ruff check src/
- 기존 워크플로 파일은 그대로 둬.
- 참고: uv 설치 방식은 같은 폴더의 multi-env.yaml(8.4)의 init-and-test job과 같게 해줘.
- 끝나면: yaml 문법을 검사하고 파일을 보여줘. 커밋 전에 멈춰줘.

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| deploy_manifest/** 변경은 제외 | 배포 커밋이 lint를 다시 실행 |
| uv 0.11.18과 Python 3.14 | 로컬과 다른 버전으로 검사 |
| uv sync 뒤 uv run ruff check src/ | ruff가 설치되지 않아 실패 |

계획이 맞으면 학습자가 "계획대로 진행해줘"(파일이면 "계획대로 만들어줘")라고 한다. 빠진 항목이 있으면 학습자가 그 항목만 1줄로 요청한다.

✅ 정답 파일 (완성 후 비교): `ch9/9.3/1.lint-github.yaml`

### 단계 4: Jenkinsfile에 Lint stage `[AI 프롬프트]`

짧게 요청하고 AI가 보여 주는 계획을 검토한다. 학습자 요청 예:

```text
Jenkinsfile에 Lint stage를 추가해줘. GitHub와 같은 검사를 Jenkins에서도 하려는 거야. 수정하기 전에 계획부터 보여줘.
```

**AI가 따를 조건** (학습자 요청에 적혀 있지 않아도 이 가드레일에서 읽어 따른다. 파일을 만들거나 실행하기 전에 계획을 먼저 보여 준다)

- 파일: /root/workspace/worklog-backend/Jenkinsfile
- Init stage 바로 다음, Test stage 앞에 둠. 나머지 stage는 그대로
- uv sync --extra dev 뒤 uv run ruff check src/
- 참고: uv 설치와 PATH 설정은 같은 파일의 Test stage와 같게 해줘.
- 끝나면: 바뀐 부분을 보여줘. 커밋 전에 멈춰줘.

**계획에서 확인할 것**

| 확인 항목 | 누락 시 결과 |
|---|---|
| Init 다음, Test 앞 | 스타일 오류가 있어도 테스트와 빌드까지 진행 |
| 나머지 stage 변경 없음 | 8장에서 만든 단계가 바뀜 |

계획이 맞으면 학습자가 "계획대로 진행해줘"(파일이면 "계획대로 만들어줘")라고 한다. 빠진 항목이 있으면 학습자가 그 항목만 1줄로 요청한다.

✅ 정답 파일 (완성 후 비교): `ch9/9.3/2.lint-jenkins.groovy`

### 단계 5: push `[AI 프롬프트]`

짧은 요청이라 계획 없이 바로 맡긴다. 학습자 요청 예:

```text
ruff.toml, ci.yaml, Jenkinsfile을 커밋하고 push해줘. 커밋 메시지는 ci: add ruff lint gate, push 전에 git pull --rebase 해줘.
```

**AI가 따를 조건**

- 커밋 메시지는 ci: add ruff lint gate
- push 전에 git pull --rebase
- 끝나면: push 결과를 보여줘.

### 단계 6: 파이프라인 2개 확인 `[학습자 직접 · 웹]`

- GitHub: fork의 Actions 탭에 Lint 실행이 생기고 lint job이 성공한다.
- Jenkins: `worklog-backend` job에서 'Scan Multibranch Pipeline Now'를 누른다. main 빌드의 Console Output에서 Lint stage가 Test 앞에 돌고 통과하는지 본다. Jenkins는 lint 뒤에 이미지 빌드와 매니페스트 갱신까지 한다(8.6과 같다).

### 단계 7: lint가 막는 코드를 push `[AI 프롬프트]`

통과만 봐서는 게이트가 동작하는지 알 수 없다. ruff가 잡는 코드를 의도적으로 올린다.

짧은 요청이라 계획 없이 바로 맡긴다. 학습자 요청 예:

```text
ruff가 잡는 코드를 src/worklog/lint_demo.py에 의도적으로 만들어 push해줘. lint 게이트가 막는지 보려는 거야. 커밋 메시지는 test: lint failure demo.
```

**AI가 따를 조건**

- 파일: /root/workspace/worklog-backend/src/worklog/lint_demo.py
- 사용하지 않는 import처럼 단순한 것
- 커밋 메시지는 test: lint failure demo, push 전에 git pull --rebase
- 끝나면: 파일과 push 결과를 보여줘.

### 단계 8: lint 실패 확인 `[학습자 직접 · 웹]`

fork의 Actions 탭에서 방금 실행의 lint job이 실패하는지 본다. 로그에 ruff가 잡은 룰 코드(`F401` 같은 것)와 파일 위치가 나온다. 이 단계에서는 Jenkins를 스캔하지 않는다. 같은 실패를 한 번 더 보는 것뿐이다.

### 단계 9: 되돌리기 `[AI 프롬프트]`

짧은 요청이라 계획 없이 바로 맡긴다. 학습자 요청 예:

```text
방금 올린 커밋을 git revert로 되돌려 push해줘. lint가 다시 통과하는지 보려는 거야.
```

**AI가 따를 조건**

- git revert --no-edit HEAD
- push 전에 git pull --rebase
- 끝나면: push 결과를 보여줘.

Actions 탭에서 lint job이 다시 성공하는지 본다.

### 단계 10: ruff가 잡아내는 오류 종류 이해 `[AI 프롬프트]`

짧은 질문이라 직접 친다.

```text
ruff.toml에서 설정한 E, F, W, I 룰이 각각 어떤 종류의 오류를 잡아내는지 설명해줘.
```

## 트러블슈팅

### Jenkins 빌드가 `downloading uv ...`에서 멈춰 끝나지 않는다

에이전트가 uv를 내려받는 연결이 끊긴 채로 기다리는 것이다. 설치 스크립트의 내려받기에는 시간 제한이 없다(run-40에서 21분 동안 멈췄다). 빌드 화면에서 중단(Abort)하고 'Scan Multibranch Pipeline Now'를 다시 누른다. 다시 돌리면 몇 초에 끝난다.

## 플레이스홀더

| 플레이스홀더 | 설명 | AI가 임의로 채워도 되는가? |
|---|---|---|
| `<github_username>` | 학습자의 GitHub username (단계 1의 `gh workflow` 명령) | ❌ 반드시 확인 |
| `<dockerhub_username>` | 학습자의 Docker Hub username (Jenkins 정답만. GitHub 정답은 빌드 단계가 없다) | ❌ 반드시 확인 |

Jenkins 정답은 8.6 Jenkinsfile에 앞 절까지의 게이트 stage를 쌓은 전체 파이프라인이라 이미지 빌드, push, 매니페스트 갱신까지 한다(9.3 Lint → 9.4 Security Scan → 9.5 커버리지 기준 → 9.6 Scan). 이미지 태그 규칙도 8.6과 같다(dev-, staging-, 태그 이름).

## 주의사항

- ✅ 학습자의 요청이 짧아도 이 가드레일의 "AI가 따를 조건"을 따른다. 요청과 조건이 다르면 요청을 따르되 다른 점을 계획에 적는다
- ⛔ AI가 하지 말 것: 계획 검토 단계에서 계획을 보여 주기 전에 파일을 만들거나 명령을 실행하지 말 것. 학습자가 "계획대로"라고 한 뒤에 진행한다. 정답 파일을 읽어 그대로 쓰지 않는다
- ⛔ AI가 하지 말 것: Jenkins 스캔을 대신 하지 말 것. 단계 5, 7, 9의 요청이 없을 때 커밋과 push를 하지 말 것
- ⛔ AI가 하지 말 것: ruff.toml 없이 파이프라인만 작성하지 말 것 (설정 파일 필요)
- ⛔ AI가 하지 말 것: `ruff check .` 대신 `ruff check src/` 사용 (worklog-backend 구조)
- ✅ AI가 해도 됨: ruff.toml 작성, 파이프라인 yaml/groovy 작성
- ✅ AI가 해도 됨: lint 오류 원인 분석 및 수정 방법 안내
- ✅ AI가 해도 됨: pyproject.toml dev 의존성 추가
- ⚠️ Jenkins에서 uv 설치 시 `export PATH="$HOME/.local/bin:$PATH"` 누락하면 `uv: command not found` 발생
- ⚠️ Jenkinsfile의 비밀값(`*_PSW`, `ARGOCD_ADMIN_PASSWORD`)은 `sh """` 안에서 `\$변수`로 넘긴다. `${...}`로 쓰면 Groovy가 값을 먼저 풀어 Console Output에 `Groovy String interpolation` 경고가 남는다(6.8 "검증 중 발견된 이슈")
