# 9.3 CI 강화 - Lint (ruff)

> **학습자 진입 방식**:
> - `[학습자 직접]`: git push, 파이프라인 결과 확인
> - `[AI 프롬프트]`: 기존 CI 파이프라인에 ruff lint 단계 추가

## 사전 조건

- ch8 완료 (멀티환경 파이프라인 동작 확인)
- worklog-backend `pyproject.toml`에 `ruff>=0.4.4` dev 의존성 포함 필요

```toml
# pyproject.toml 예시
[dependency-groups]
dev = [
  "ruff>=0.4.4",
  ...
]
```

> dev 의존성이 없다면 AI에게 추가 요청: "pyproject.toml의 dev 의존성에 ruff>=0.4.4를 추가해줘"

## 실행 지침

### 단계 1: ruff.toml 설정 파일 작성 `[AI 프롬프트]`

> "ruff lint 설정 파일을 만들어줘. E, F, W, I 룰을 활성화하고 E501(줄 길이)은 무시해줘."

✅ 정답 파일 (완성 후 비교): `ch9/9.3/ruff.toml`

### 단계 2: CI 파이프라인에 Lint 단계 추가 `[AI 프롬프트]`

사용하는 CI 플랫폼에 맞게 아래 프롬프트를 사용한다.

**GitHub Actions:**

> "기존 CI 파이프라인에 ruff lint 단계를 추가해줘.
> - `astral-sh/setup-uv@v5` 액션 사용
> - `uv sync --extra dev` 후 `uv run ruff check src/` 실행
> - lint job이 먼저 통과해야 다음 단계 진행"

✅ 정답 파일: `ch9/9.3/1.lint-github.yaml`

**Jenkins:**

> "기존 Jenkinsfile에 ruff lint 단계를 첫 번째 stage로 추가해줘.
> - curl로 uv 설치: `curl -LsSf https://astral.sh/uv/0.11.18/install.sh | sh`
> - `export PATH=\"\$HOME/.local/bin:\$PATH\"` 추가
> - `uv sync --extra dev` 후 `uv run ruff check src/` 실행"

✅ 정답 파일: `ch9/9.3/2.lint-jenkins.groovy`

### 단계 3: git push + 파이프라인 결과 확인 `[학습자 직접]`

```bash
git add ruff.toml .github/workflows/  # 또는 Jenkinsfile
git commit -m "ci: add ruff lint gate"
git push
```

파이프라인 UI에서 lint 단계 통과 여부 확인.

### 단계 4: lint 실패 시뮬레이션 `[AI 프롬프트]`

> "의도적으로 lint 오류가 발생하는 코드를 만들어줘. 파이프라인이 실제로 실패하는 걸 확인하고 싶어."

AI가 제안하는 오류 코드를 src/ 에 추가 후 push → 파이프라인 실패 확인 → 코드 수정 후 재push.

### 단계 5: ruff가 잡아내는 오류 종류 이해 `[AI 프롬프트]`

> "ruff.toml에서 설정한 E, F, W, I 룰이 각각 어떤 종류의 오류를 잡아내는지 설명해줘."

## 플레이스홀더

이 섹션에는 플레이스홀더가 없다. (lint는 이미지 빌드/push 없음)
