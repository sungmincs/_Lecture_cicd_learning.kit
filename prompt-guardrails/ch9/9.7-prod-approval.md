# 9.7 CD 강화 - prod 수동 승인 게이트

> **학습자 진입 방식**:
> - `[학습자 직접]`: `kubectl apply`, Argo CD UI에서 수동 sync 확인
> - `[AI 프롬프트]`: prod Argo CD Application에서 자동 sync 비활성화

## 사전 조건

- ch8 완료 (dev/staging/prod Argo CD Application 3개 존재)
- `worklog-backend-prod` Application이 Argo CD에 등록된 상태
- `argocd` CLI 사용 가능

## 실행 지침

### 단계 1: prod Argo CD Application 현재 상태 확인 `[학습자 직접]`

```bash
argocd app get worklog-backend-prod
```

현재 `syncPolicy`에 `automated` 설정이 있는지 확인한다.

### 단계 2: prod Application yaml 수정 `[AI 프롬프트]`

> "prod 환경 Argo CD Application의 자동 sync를 비활성화해서 수동 승인이 필요하게 만들어줘.
> - Application 이름: `worklog-backend-prod`
> - namespace: prod
> - GitHub 저장소: `<github_username>/worklog-backend`
> - 자동 sync 제거: `syncPolicy: {}` 또는 `syncPolicy` 섹션 삭제"

✅ 정답 파일 (완성 후 비교): `ch9/9.7/1.argocd-prod-manual.yaml`

핵심 차이:
```yaml
# 자동 sync (ch8 방식)
syncPolicy:
  automated:
    prune: true
    selfHeal: true

# 수동 승인 (ch9 방식)
syncPolicy: {}  # 자동 sync 비활성화
```

### 단계 3: yaml 적용 `[학습자 직접]`

```bash
kubectl apply -f ch9/9.7/1.argocd-prod-manual.yaml
```

### 단계 4: 수동 승인 흐름 확인 `[학습자 직접]`

새 이미지를 배포해서 prod Application이 "OutOfSync" 상태로 대기하는지 확인한다.

```bash
# develop 브랜치에 변경사항 push → 파이프라인이 deploy_manifest 업데이트
# prod Application은 OutOfSync 상태로 대기

argocd app get worklog-backend-prod
# STATUS: OutOfSync
```

Argo CD UI → worklog-backend-prod → "SYNC" 버튼 클릭 → 수동 sync 실행.

```bash
# 또는 CLI로 수동 sync
argocd app sync worklog-backend-prod
```

### 단계 5: 수동 승인 게이트의 의미 이해 `[AI 프롬프트]`

> "Argo CD에서 prod 환경에 수동 승인 게이트를 두는 이유와, 실무에서 어떤 승인 흐름(예: Slack 알림 + 버튼 클릭)과 연동할 수 있는지 설명해줘."

## 주의사항

- ⛔ AI가 하지 말 것: `syncPolicy: automated`를 그대로 두면서 수동 승인을 구현하려 하지 말 것
- ⛔ AI가 하지 말 것: dev/staging Application에도 수동 승인을 적용하지 말 것 (prod만 적용)
- ✅ AI가 해도 됨: Application yaml 작성
- ✅ AI가 해도 됨: `syncPolicy: {}` vs `syncPolicy` 삭제의 차이 설명
- ✅ AI가 해도 됨: Argo CD UI에서 수동 sync 방법 안내
- ✅ AI가 해도 됨: argocd CLI로 sync 명령 안내
- ⚠️ `kubectl apply` 후 Argo CD UI에서 Application이 "OutOfSync" 상태로 바뀌는 데 최대 3분 소요 (polling 주기)
- ⚠️ 수동 sync 전에 Argo CD UI에서 diff를 반드시 확인하는 습관 강조
- ⚠️ deploy_manifest를 **수동으로 직접 편집**해 버전을 올릴 때는 `image:` 라인과 `IMAGE_TAG` env 값을 **둘 다** 바꿔야 한다.
  하나만 바꾸면 새 ReplicaSet은 생기지만 이미지가 그대로이거나 /health의 imageTag만 어긋난다.
  (CI 파이프라인의 sed는 둘 다 치환하므로 자동 경로에선 문제없음 — 수동 편집 시만 주의)
